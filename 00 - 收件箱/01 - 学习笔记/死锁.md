# 基础概念
死锁是并发编程中最棘手的问题之一它是指两个或两个以上的进程（或线程）在执行过程中，因**争夺资源**而造成的一种**互相等待**的现象
若无外力干涉，这些进程都将无法向前推进，系统处于“卡死”状态
## 经典比喻：哲学家就餐问题
为了形象地解释死锁，计算机科学家 Dijkstra 提出了“哲学家就餐问题”：
- **场景**：五位哲学家围坐在一张圆桌旁，桌上有五根筷子，每两人之间放一根
- **规则**：哲学家只做两件事——思考和吃饭吃饭时必须**同时**拿起左右两边的筷子
- **死锁形成**：如果所有哲学家**同时**拿起了自己**左边**的筷子，那么每个人都持有左筷子（保持资源），并等待右边的筷子（请求资源）结果就是谁也吃不上饭，所有人都在无限期等待，从而陷入死锁
# 产生的必要条件
死锁的发生并非偶然，它必须**同时满足**以下四个条件只要破坏其中任何一个，死锁就不会发生
1. **互斥条件**
    - **定义**：一个资源每次只能被一个进程使用
    - **示例**：打印机、互斥锁 (Mutex)如果资源是共享的（如只读文件），则不会发生死锁
2. **请求与保持条件
    - **定义**：一个进程因请求资源而阻塞时，对已获得的资源**保持不放**
    - **示例**：线程 A 持有锁 1，想申请锁 2；但此时锁 2 被占用，线程 A 阻塞等待，却不释放锁 1
3. **不剥夺条件
    - **定义**：进程已获得的资源，在未使用完之前，**不能被强行剥夺**，只能由进程自己释放
    - **示例**：你不能强行把线程 A 手里的锁抢过来给线程 B 用
4. **循环等待条件
    - **定义**：若干进程之间形成一种**头尾相接**的循环等待资源关系
    - **示例**：
        - 线程 A 持有锁 1，等待锁 2
        - 线程 B 持有锁 2，等待锁 1
        - 形成环路：A -> 2 -> B -> 1 -> A
# 解决和预防死锁的策略
解决死锁的思路就是破坏上述四个必要条件中的至少一个主要策略分为三类：预防、避免、检测与恢复
## 预防死锁
**核心思想**：在设计阶段制定规则，杜绝死锁的可能性
1. **破坏“请求与保持”条件**
    - **方法**：**一次性申请所有资源**进程在开始运行前，必须一次性申请其所需的所有资源如果不满足，则什么都不分配，进程等待
    - **缺点**：实现简单但**效率低下**，**资源浪费严重**（有些资源可能最后才用，却一开始就被占着），且容易导致饥饿
2. **破坏“不剥夺”条件**
    - **方法**：**允许抢占**如果一个进程已经持有了一些资源，但申请新资源失败，它必须**释放所有已持有的资源**，待以后需要时重新申请
    - **实现技巧**：可以使用 `pthread_mutex_trylock` (非阻塞加锁)如果获取失败，则释放已有的锁，休息一会重试
    - **缺点**：实现复杂，反复申请和释放资源会增加上下文切换的开销（CPU 抖动）
3. **破坏“循环等待”条件 —— 【最常用、最实用】**
    - **方法**：**资源有序分配法**
    - **原理**：给系统中所有的资源编号，规定所有进程必须按照**递增的顺序**申请资源
    - **为何有效**：如果规定只能按 A -> B -> C 的顺序申请，那么就不可能出现有人持有 C 却在等 A 的情况，从而打破了环路
    - **示例**：
        - 假设有锁 L1, L2, L3
        - 规定必须按 L1 -> L2 -> L3 的顺序加锁
        - 线程 A：申请 L1，再申请 L2 (合法)
        - 线程 C：想先申请 L3，再申请 L1 (非法，会被禁止)
## 避免死锁
**核心思想**：在运行时，系统在进行资源分配前，先计算这次分配是否安全
- **银行家算法 (Banker's Algorithm)**
    - 这是一个经典的死锁避免算法
    - **逻辑**：系统在分配资源前，模拟分配，然后检查系统是否进入**不安全状态**（即是否存在死锁风险）如果会进入不安全状态，则拒绝本次分配，让进程等待
    - **优点**：相比预防策略，资源的利用率更高
    - **缺点**：
        - 需要事先知道进程的**最大资源需求**（在实际编程中很难预知）
        - 算法本身有计算开销
        - 因此，主要用于操作系统教学或特定的嵌入式系统设计，通用编程中较少使用
## 检测与恢复
**核心思想**：放任死锁发生，但系统会定期检查，一旦发现死锁，就采取措施恢复
1. **死锁检测**
    - 系统维护一个**资源分配图 (Resource Allocation Graph)**
    - 定期运行算法（如深度优先搜索 DFS）检查图中是否存在**环路 (Cycle)**如果存在环路，说明发生了死锁
2. 死锁恢复
    一旦检测到死锁，需要采取“止损”措施：
    - **进程终止**：
        - _简单粗暴_：终止所有死锁进程代价高，前功尽弃
        - _逐个终止_：每次杀掉一个进程，释放其资源，直到死锁解除选择“受害者”时通常考虑优先级低、代价小的进程
    - **资源抢占**：
        - 从一个或多个死锁进程中强行剥夺资源，分配给其他进程
        - **需要解决的问题**：
            1. **选择牺牲品**：谁的资源被抢？
            2. **回滚 (Rollback)**：被抢占的进程无法继续运行，需要回滚到某个安全状态
            3. **饥饿 (Starvation)**：如何防止同一个进程总是被选中当“倒霉蛋”？（通常通过增加权重，避免频繁选中同一进程）
# 在线程并发中的实例
在多线程编程中，当一个线程持有资源（如锁、内存）时被外部取消（Cancel），容易导致资源无法释放，从而引发死锁。为了解决这个问题，Pthreads 提供了两套机制。
## 使用取消处理函数
这是防止资源泄漏的标准做法。利用“清理栈”机制，确保线程在异常退出时能自动释放资源。
### 注册清理函数 `pthread_cleanup_push()`
- **函数原型**
    ```c
    #include <pthread.h>
    
    void pthread_cleanup_push(void (*routine)(void *), void *arg);
    ```
- 作用
    将一个清理函数压入当前线程的清理栈 (Cleanup Stack) 中。如果线程在之后被取消或调用 pthread_exit，系统会从栈顶弹出并执行该函数。
- **参数详解**
    - `routine`：函数指针，指向你需要执行的清理函数（例如用于解锁、释放内存的函数）。
    - `arg`：传递给清理函数的参数。
- 返回值
    无（void）。
- 注意事项
    该函数通常以宏定义实现，必须与 pthread_cleanup_pop 在同一个代码块 { ... } 中成对出现。
### 移除清理函数 `pthread_cleanup_pop()`
- **函数原型**
    ```c
    #include <pthread.h>
    
    void pthread_cleanup_pop(int execute);
    ```
- 作用
    从清理栈的栈顶移除一个清理函数。
- **参数详解**
    - `execute`：决定移除时是否执行该函数。
        - `0`：仅移除，**不执行**（通常用于线程正常执行完某段代码，资源已正常释放，不再需要清理函数兜底的情况）。
        - `非0`：移除并**立即执行**该函数。
- 返回值
    无（void）。
### 示例代码
```c
#include <pthread.h>
#include <stdio.h>
#include <unistd.h>

// 定义3个清理函数模仿资源释放
void func1(void* arg) { printf("[1]清理函数1执行\n"); }
void func2(void* arg) { printf("[2]清理函数2执行\n"); }
void func3(void* arg) { printf("[3]清理函数3执行\n"); }
  

void* task_func(void* arg) {
	// 注册3个清理函数
	pthread_cleanup_push(func3, NULL);
	pthread_cleanup_push(func2, NULL);
	pthread_cleanup_push(func1, NULL);
	// 子线程工作
	printf("子进程开始工作\n");
	while (1) {
		sleep(1);
	}
	// 注销3个清理函数
	// 每个清理函数表示清理一个类型的资源
	pthread_cleanup_pop(0);
	pthread_cleanup_pop(0);
	pthread_cleanup_pop(0);
	return NULL;
}
int main() {
	pthread_t tid;
	// 创建子线程
	pthread_create(&tid, NULL, task_func, NULL);
	sleep(1);
	printf("取消子进程\n");
	pthread_cancel(tid);
	// 等待子线程结束
	pthread_join(tid, NULL);
	printf("主进程结束\n");
	return 0;
}
```
## 修改取消状态与类型
另一种策略是控制“是否允许被取消”以及“何时被取消”
### 设置取消状态 `pthread_setcancelstate()`
- **函数原型**
    ```c
    #include <pthread.h>
    
    int pthread_setcancelstate(int state, int *oldstate);
    ```
- 作用
    设置当前线程是否接受取消请求。
- **参数详解**
    - `state`：新的状态。
        - `PTHREAD_CANCEL_ENABLE`：**使能**（默认），允许被取消。
        - `PTHREAD_CANCEL_DISABLE`：**禁能**，暂时忽略取消请求（请求会挂起，直到状态重新变回 Enable）。
    - `oldstate`：输出参数，用于保存修改前的状态（以便后续恢复），可填 `NULL`。
- 返回值
    成功返回 0，失败返回错误码。
### 设置取消类型 `pthread_setcanceltype()`
- **函数原型**
    ```c
    #include <pthread.h>
    
    int pthread_setcanceltype(int type, int *oldtype);
    ```
- 作用
    在允许取消的前提下，设置取消的时机。
- **参数详解**
    - `type`：新的类型。
        - `PTHREAD_CANCEL_DEFERRED`：**延迟响应**（默认）。收到取消后继续运行，直到遇到**取消点 (Cancellation Point)** 才退出。
            - _常见取消点_：`sleep`, `read`, `write`, `printf`, `accept` 等系统调用。
        - `PTHREAD_CANCEL_ASYNCHRONOUS`：**异步响应**。收到取消请求后立即退出，不管执行到哪里（非常危险，仅用于纯计算密集型任务）。
    - `oldtype`：输出参数，保存旧类型。
- 返回值
    成功返回 0，失败返回错误码。
### 示例代码
通常纯 CPU 计算循环（无系统调用）无法被默认机制取消，此时需要设置为异步类型。
```c
#include <stdio.h>
#include <pthread.h>
#include <unistd.h>

void * TaskFunc(void * arg)
{
    // 设置为异步取消：不需要等待取消点，收到 cancel 立即死
    // 适用于这种没有 sleep/printf 等取消点的死循环
    pthread_setcanceltype(PTHREAD_CANCEL_ASYNCHRONOUS, NULL);

    int Num = 5;
    while(Num > 0)
    {
        // 这是一个纯计算逻辑，没有任何系统调用取消点
        // 如果不设置 ASYNCHRONOUS，pthread_cancel 无法终止它
    }
    return NULL;
}

int main() {
    pthread_t tid;
    pthread_create(&tid, NULL, TaskFunc, NULL);
    sleep(1);
    pthread_cancel(tid); // 立即杀死子线程
    pthread_join(tid, NULL);
    return 0;
}
```
