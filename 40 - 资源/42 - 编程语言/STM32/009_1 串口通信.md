#stm32
## 串口概述
串口通信是单片机与外部世界交互的最重要通道之一
### 串口的定义与电平标准划分
在电子通信中，“串口”是一个广泛的概念根据应用场景和电平标准的不同，我们主要将其划分为**板级通信**和**外部通信**两大类为了适配不同的传输距离和抗干扰要求，衍生出了多种电平标准
#### 电平标准

| **电平标准**     | **逻辑逻辑** | **信号定义 (电压范围)**                                        | **通信线制** | **典型波特率** | **传输距离**    | **连接拓扑** |
| ------------ | -------- | ------------------------------------------------------ | -------- | --------- | ----------- | -------- |
| **TTL** (5V) | **正逻辑**  | **输出**：高(2.4~5V)，低(0~0.4V)<br>**输入**：高(2~5V)，低(0~0.8V) | TX/RX    | 板级速率      | 极短 (板级)     | 芯片间直连    |
| **RS232**    | **负逻辑**  | **高电平(-1)**：-15V ~ -3V<br>**低电平(0)**：+3V ~ +15V        | 3线全双工    | 115200    | 近 (最远15m)   | 一对一      |
| **RS485**    | **差分电平** | **高(1)**：A-B > +2~6V<br>**低(0)**：A-B < -2~-6V          | 2线半双工    | 10M       | 远 (最远1.2km) | 一对多      |
| **RS422**    | **差分电平** | (同RS485，使用两对差分线)                                       | 4线全双工    | 10M       | 远 (最远1.2km) | 一对多      |

- TTL电平（板级通信的核心）：
    TTL (Transistor-Transistor Logic) 是单片机内部及周边芯片（如蓝牙、WiFi模块、IIC、SPI设备）通信的基础电平
    - **正逻辑**：在TTL中，逻辑“1”代表高电平，逻辑“0”代表低电平
    - **输入输出电压差异**：**输入的阈值范围比输出更宽**例如，输出高电平最低是2.4V，而输入只要高于2V就被认为是高电平这种设计是为了保证在信号传输过程中，即使线路存在微小的电压损耗或干扰，接收端依然能正确识别信号，从而提高了系统的**容错性**
- RS232（负逻辑与抗干扰）：
    早期计算机常用的接口它使用负逻辑，即负电压代表“1”，正电压代表“0”这种大幅度的电压摆动（最高可达15V）使其具有较好的抗干扰能力，但由于信号线是非平衡的，传输距离依然受限（约15米）
- RS485/RS422（差分信号与长距离）：
    为了突破距离限制，这两种标准采用了差分信号传输它们不检测对地电压，而是检测两根线（A和B）之间的电压差如果外部有干扰信号，通常会同时作用于两根线，两者相减后干扰就被抵消了这使得它们能实现高达1.2km的远距离传输，广泛应用于工业现场
### 同步与异步通信
单片机中的串口外设通常命名为 **USART** (Universal Synchronous Asynchronous Receiver Transmitter)，即通用同步异步收发器其核心区别在于**是否有配合的时钟线**来规范数据传输的节奏
- **同步通信 (Synchronous)**：双方有一根公共的时钟线（如SCL、SCK）发送方必须配合时钟信号（如在上升沿）发送数据，接收方也在同一时钟节拍（如在下降沿）读取数据这种方式效率高，但对时钟信号质量要求严格
- **异步通信 (Asynchronous - UART)**：**没有时钟线**这是我们最常用的模式（UART）由于没有统一的时钟，双方必须约定好一个共同的传输速度（**波特率**），并依靠数据帧中的**起始位**来对齐时间，从而实现数据读写虽然效率略低于同步模式，但接线简单，适合长距离
![](images/009_1%20串口通信/file-20260113094618518.jpg)
### 串行与并行通信
- **串行通信**：数据排成一队，通过**单根数据线**一位一位地传输就像单车道，虽然车流速度受限，但只需要铺设一条路，成本低，且线缆间干扰小，适合长距离传输
    ![](images/009_1%20串口通信/file-20260113094618521.jpg)
- **并行通信**：数据通过**多根数据线**（如8根）同时传输就像8车道的高速公路，一次可以通过很多车，速度极快，但线缆复杂且容易产生线间干扰，通常只用于内部总线或短距离高速交换
 ![](images/009_1%20串口通信/file-20260113094618522.jpg)
    

### 数据传输方向
1. **单工**：数据只能单向流动（A只能发，B只能收），如同广播
![](images/009_1%20串口通信/file-20260113094618531.jpg)
2. **半双工**：数据可以双向流动，但**不能同时进行**同一时刻只能有一方在发，如同对讲机RS485就是典型的半双工
![](images/009_1%20串口通信/file-20260113094618549.jpg)
3. **全双工**：数据可以**同时**进行双向传输A 发给 B 的同时，B 也可以发给A，如同打电话UART和RS422都支持全双工
    ![](images/009_1%20串口通信/file-20260113094618528.jpg)
### UART与USART的硬件连接
在实际硬件连接中，最重要的是理解“交叉连接”的原则

- **UART连接**：对象A的发送端（TX）必须连接对象B的接收端（RX），反之亦然，同时双方必须共地（GND相连）以建立统一的参考电位这种连接方式支持全双工异步通信
![](images/009_1%20串口通信/file-20260113094618529.jpg)
- **USART连接**：在UART的基础上增加了一条时钟线（SCL/SCK），用于同步模式下的时钟信号传输常见的SPI协议就是全双工同步通信的典型代表，而IIC则是半双工同步通信
![](images/009_1%20串口通信/file-20260113094618526.jpg)

> [!tip]
> - **TX (Transmit)**：发送端
> - **RX (Receive)**：接收端
> - **GND**：地线


### 数据帧格式
在异步通信中，因为没有时钟线，数据包的格式（帧格式）就是通信的“法律”一个标准的字符帧包含以下部分 ：
1. **空闲位**：线路空闲时保持高电平
2. **起始位**：发送方将电平拉低（1位时间），告诉接收方“数据要来了”，开始同步
3. **数据位**：通常为8位（1字节），先发低位（LSB），后发高位（MSB）
4. **校验位 (可选)**：用于简单的错误检测
    - **奇校验 (Odd Parity)**：确保数据位+校验位中“1”的总数为**奇数**如果数据中有偶数个1，校验位补1；否则补0
    - **偶校验 (Even Parity)**：确保数据位+校验位中“1”的总数为**偶数**如果数据中有偶数个1，校验位补0
5. **停止位**：电平拉高，表示一个字符传输结束，线路回到空闲状态
![](images/009_1%20串口通信/file-20260113094618550.jpg)

> [!tip]
>  通信双方必须将**波特率 (bps)** 设置得完全一致，否则接收方无法按照正确的时间间隔采样，会导致数据乱码

**校验位**：为了确保数据传输的正确性，可以使用奇偶校验
- **奇校验**：保证数据位加上校验位中“1”的总个数为奇数如果数据中有偶数个1，校验位就补1
![](images/009_1%20串口通信/file-20260113094618559.jpg)
- **偶校验**：保证整体“1”的个数为偶数如果数据中有奇数个1，校验位就补0
    ![](images/009_1%20串口通信/file-20260113094618579.jpg)
- **CRC 校验** ：又称循环冗余校验，是一种根据网络数据包或计算机文件等数据产生简短固定位数校验码的一种**检错编码**有以下特点
	- 检错能力强：可以检测出所有奇数位错误、双位错误以及突发性错误
	- 不可逆： 单向的，不能从 CRC 码还原数据
	- 非加密：不具备安全性，容易被伪造，仅用于防范物理干扰导致的错误
	- 固定长度：无论数据多长，生成的 CRC 码长度是固定的
### 流控机制
在串口通信的实际应用中，尤其是当上位机（如高性能PC，处理能力几个G）与下位机（如单片机，主频仅几十M）进行交互时，常常会出现**速度不匹配**的现象一旦接收端的数据缓冲区（Buffer）已满，而发送端因处理能力过强仍源源不断地发送数据，接收端来不及处理，就会导致**数据丢失**为了解决这个问题，我们需要一种机制来协调双方的收发节奏，这就是**流控**

流控的基本原理非常直观：当接收端“吃不消”时，发出信号让发送端“暂停”；当接收端处理完毕有空闲时，再通知发送端“继续”常见的流控方式分为**硬件流控**和**软件流控**

#### 硬件流控
硬件流控是最可靠的方法，它在TX和RX之外，增加了两根专用的控制线来实现“刹车”功能这两根线分别是 **RTS** (Request To Send) 和 **CTS** (Clear To Send)
在硬件连接上，同样遵循“交叉连接”原则：设备A的 **RTS** 连接设备B的 **CTS**，设备A的 **CTS** 连接设备B的 **RTS**这样，数据的传输方向是从TX到RX，而控制流的方向则是从RTS到CTS
![](images/009_1%20串口通信/file-20260113094618562.jpg)

> [!tip]
> - **RTS (Request To Send，发送请求/请求发送)**： 这是一个**输出**信号它用于指示**本设备**是否准备好接收数据通常低电平有效，当RTS输出**低电平**时，代表“我的缓冲区有空，你可以给我发数据”；拉高则代表“我忙不过来了，请暂停发送”
> - **CTS (Clear To Send，清除发送/允许发送)**： 这是一个**输入**信号它用于判断**对方**是否允许我发送数据通常低电平有效，当检测到CTS为**低电平**时，说明对方准备好了，本设备可以开始发送；若检测到高电平，则停止发送数据

#### 软件流控
由于硬件流控需要额外的线缆，受限于成本或布线（如只有3根线），我们在普通控制通讯中常用软件流控 软件流控不占用额外引脚，而是通过在数据流中插入特殊的**字符**来沟通一般采用 **XON/XOFF** 协议：
- 当接收端缓冲区快满（超过设定的高水位）时，向发送端发送 **XOFF字符**（通常是十进制19，0x13），发送端收到后立即停止
- 当接收端处理了数据，缓冲区空闲（低于低水位）时，发送 **XON字符**（通常是十进制17，0x11），发送端收到后恢复发送
**注意**：软件流控有一个明显的缺陷——如果传输的是**二进制数据**，数据本身可能恰好包含了0x11或0x13这两个值，这会导致误判为流控信号而引起操作错误因此，二进制传输推荐使用硬件流控
**Linux环境下的流控配置示例**： 在Linux编程中，我们可以通过配置 `termios` 结构体来实现流控，代码如下 ：

```c
options.c_cc[VSTOP] = 0x22;  // 定义停止发送的字符（要求对端停止）
options.c_cc[VSTART]= 0x33;  // 定义开始发送的字符（告诉对端可以发送）
options.c_iflag |= IXON|IXOFF; // 在输入标志中使能软件流控制
```

### Printf重定向
#### 为什么需要重定向？
对于初学者而言，在PC上学习C语言时，`printf("Hello World!")` 是最常用的调试手段，它默认输出到电脑屏幕但在嵌入式开发（如STM32）中，单片机并没有显示器 为了能像在PC上一样方便地打印调试信息，我们需要将 `printf` 的输出方向“劫持”并修改，使其数据通过串口（UART）发送出来，最终在电脑的串口助手上显示这个过程被称为**重定向**或**Retargeting**
#### 实现原理与代码
在Keil MDK-ARM或ARM DS-5等开发环境中，C标准库的 `printf` 底层依赖一个名为 `fputc` 的函数来发送单个字符我们只需要在代码中**重写**这个 `fputc` 函数，将其逻辑改为“将字符写入串口发送寄存器”，即可实现重定向
- **代码示例** ：
```c
/* retarget.c 的精简版 - 在 Keil MDK-ARM 中支持简单 printf 的最少代码 */
/**************************************************************/
/* 适用于 ARM DS-5 Professional / Keil MDK 的最小重定向函数 */
/**************************************************************/

// 关键指令：告诉编译器不使用半主机模式，避免运行错误
#pragma import(__use_no_semihosting_swi)

#include "stm32f4xx.h"
#include <stdio.h>

// 标准IO库需要的结构体定义
struct __FILE { int handle; /* 在此处添加你需要的任何句柄信息 */ };

// 定义标准输出和标准输入流
FILE __stdout;
FILE __stdin;

// 重写 fputc 函数，printf 最终会调用它
int fputc(int ch, FILE *f) {
    // 这里调用硬件发送函数，通常是串口发送，例如 USART_SendData
    // 原例中使用 ITM_SendChar 是针对调试器的，实际串口通常需修改此处
    return (ITM_SendChar(ch)); 
}

// 定义系统退出函数，防止程序结束时出错
void _sys_exit(int return_code) {
label: goto label; /* 进入死循环，防止程序跑飞 */
}
```

#### 半主机模式与BKPT
在上述代码中，有一句非常关键的预处理指令：`#pragma import(__use_no_semihosting_swi)`理解这行代码需要引入**半主机模式 (Semihosting)** 的概念
**什么是半主机模式？** 半主机是ARM的一种机制，它允许在ARM目标上运行的代码借用**主机电脑**的输入输出设备（如屏幕、键盘）当你调用 `printf` 时，默认情况下C库会认为你要使用主机的屏幕，因此它会编译出特殊的指令来请求主机服务
**为什么不加这句代码会死机？** 默认的半主机机制是通过 **BKPT** 指令实现的（ARMv7之前使用SVC指令，Cortex-M系列使用BKPT）
- **BKPT指令**：这是一种软件断点指令（如 `BKPT 0xAB`）当CPU执行到这条指令时，会产生软件中断并停止运行，等待调试器（Debugger）来处理
- **后果**：如果你已经把程序下载到单片机里独立运行（没有连接调试器），而代码中又包含了 `printf`，CPU执行到底层的 `BKPT` 指令时，因为没有调试器来响应，CPU就会卡在这个中断处（通常表现为进入死循环或HardFault），导致程序“死机”
**解决方案** 通过 `#pragma import(__use_no_semihosting_swi)` 声明，明确告诉编译器：“不要使用半主机模式”这样，编译器就不会生成 `BKPT` 指令，而是会寻找我们自己实现的 `fputc` 函数，从而将数据正确地导向我们配置好的串口硬件，确保程序在脱离调试器的情况下也能正常运行

## 有线串口(A-A口线)
### 硬件连接与驱动
我们在实验中使用的USB转串口线（A-A口线），其内部集成了**CH340芯片**，作用是将电脑USB信号转换为单片机能识别的TTL串口信号因此，初次使用必须在电脑上安装CH340驱动
硬件连接步骤如下：
1. **物理连接**：将USB线一端接电脑，另一端接开发板的USB-UART接口
2. **跳线设置**：确保开发板上的UART1跳线帽（通常是1-3和2-4）已短接，这将STM32芯片的USART1引脚（PA9/TX和PA10/RX）物理导通到了CH340芯片上
![](images/009_1%20串口通信/file-20260113094618582.jpg)
### 软件程序编写与使用
#### 上位机设置
在进行串口通信开发时，上位机不仅是数据显示的窗口，更是排查问题的基准。使用“串口助手”等调试软件（如XCOM、SSCOM）前，**首要步骤是建立物理连接与驱动确认**：需进入设备管理器查看端口列表，确认USB转TTL芯片（如CH340、CP2102）驱动已正确安装并识别出对应的端口号（如COM5），若未识别需检查是否安装驱动或USB 是否连接
使用“串口助手”软件进行调试
在软件中打开该端口，**参数配置必须严格遵循通信协议的一致性原则**，即经典的 **“9600, N, 8, 1”** 规则：
- **波特率（Baud Rate）**：通常设为9600（wifi）或115200（usb），这代表每秒传输的二进制位数。此数值必须与单片机完全一致，否则因采样时间点错位将导致乱码
- **校验位（Parity）**：None（无校验）是主要选择，除非环境干扰极大，一般不开启奇偶校验
- **数据位（Data Bits）**：**8位**，代表一次传输一个字节（Standard Byte）
- **停止位（Stop Bits）**：**1位**，用于标识一帧数据的结束，预留电平恢复时间
![](images/009_1%20串口通信/file-20260113094618578.jpg)

> [!NOTE] **波特率 vs 比特率**
> - **波特率 ($R_B$)**：**码元速率**即信号在每秒钟内发生变化的次数（每秒传输的符号数）。
> - **比特率 ($R_b$)**：**信息速率**即每秒传输的二进制位数 (bit/s)
> - 两者关系公式（M 为信号的电平级数）
> 	- $$R_b = R_B \times \log_2 M$$
> 普通串口信号只有“高”和“低”两种电平 ($M=2$)，根据公式 $\log_2 2 = 1$，此时 **1 波特 = 1 比特**。因此，我们说 9600 波特率时，实际传输速度就是 9600 bps
#### 下位机编程
在 STM32F4 等高性能芯片上开发串口驱动，本质上是配置芯片内部的寄存器以控制硬件时序。与简单的 51 单片机不同，STM32 的外设资源管理更为严格，编程流程遵循“时钟使能 -> 硬件配置 -> 数据交互”的三步法则
##### 编程思路
A. 硬件时钟使能（开启“心脏”）
单片机为降低功耗，所有外设时钟默认处于门控关闭状态。操作任何外设前，必须查阅数据手册确认其挂载的总线，并开启对应时钟，否则写入寄存器无效。
- **外设时钟**：调用 `RCC_APB2PeriphClockCmd` 开启 **USART1** 时钟。
- **IO 时钟**：串口通信依赖物理引脚传输电平，必须调用 `RCC_AHB1PeriphClockCmd` 开启 **GPIOA** 时钟（因为 USART1 复用在 PA9/PA10）
> [!Tip]
>   USART1 通常挂载在高速 APB2 总线，而 USART2/3 挂载在 APB1）

**B. 硬件配置**
- **引脚复用（GPIO AF 映射）**：STM32F4 的引脚资源高度灵活。必须修改 GPIO 寄存器，将 PA9 (TX) 和 PA10 (RX) 的工作模式从普通 I/O 切换为**复用功能 (Alternate Function)**，并明确指定映射到 **AF7 (USART1)**。此时，引脚内部电路直通串口控制器，不再受普通 ODR 寄存器控制。
- **参数配置（协议匹配）**：初始化 `USART_InitTypeDef` 结构体，设置通信协议。核心是波特率（如 115200），库函数会根据设置的波特率和系统总线频率自动计算分频值写入 **BRR 寄存器**。其余参数需遵循经典的 **“N, 8, 1”** 规则（无校验、8位数据、1位停止位），确保与上位机配置一致。
- **中断配置（NVIC）**：为了避免 CPU 死等数据（轮询模式低效），通常开启**接收非空 (RXNE)** 中断。配置 NVIC 优先级后，每当移位寄存器收到一个字节并填入数据寄存器（DR），硬件会自动触发中断请求
C. 数据收发控制（寄存器交互）
初始化完成后，软件只需读写 DR (Data Register)，硬件会自动完成并串转换
- **发送**：写入 DR 后，必须查询 **TXE (发送寄存器空)** 标志位，确认上一个字节已移入发送移位寄存器，才能写入下一个字节，防止数据覆盖
- **接收**：在中断服务函数中读取 DR。读取操作不仅能获取数据，还会**自动清除 RXNE 中断标志位**

> [!tip] 乱码排查指南
>
> 如果串口助手收到乱码，除了检查波特率是否匹配外，必须核对系统时钟设置。
>
> 波特率生成器是通过分频系统时钟工作的。如果外部晶振 (HSE) 频率（如 8MHz vs 25MHz）与代码中 stm32f4xx.h 定义的 HSE_VALUE 不一致，或者 PLL 倍频系数错误，会导致库函数计算出的波特率产生偏差，进而导致采样错误。

以下代码实现了串口初始化、阻塞式字符串发送以及中断接收（含缓冲区溢出保护）

```c
#ifndef __UART_H
#define __UART_H
#include "stm32f4xx.h"

#define UART1_RX_MAX_LEN  128  // 定义缓冲区最大长度

// 全局变量声明 (extern)
extern uint8_t UART1_RxBuffer[UART1_RX_MAX_LEN];
extern uint8_t u1_count;
extern uint8_t u1_flag;
```

**`uart.c`**
```c
#include "uart.h"

// 全局变量定义 (分配内存)
uint8_t UART1_RxBuffer[UART1_RX_MAX_LEN]; // 接收缓冲区
uint8_t u1_count = 0;                     // 当前接收计数
uint8_t u1_flag = 0;                      // 接收完成标志

/**
 * @brief  初始化串口1 (USART1)
 * @note   包含时钟使能、GPIO复用、参数配置及NVIC中断设置
 */
void UART1_Init(uint32_t baudrate) {
    // 1. 时钟使能：开启 GPIOA (AHB1) 和 USART1 (APB2)
    RCC_AHB1PeriphClockCmd(RCC_AHB1Periph_GPIOA, ENABLE); 
    RCC_APB2PeriphClockCmd(RCC_APB2Periph_USART1, ENABLE); 

    // 2. GPIO 复用配置：将 PA9/PA10 映射到 USART1 (AF7)
    GPIO_PinAFConfig(GPIOA, GPIO_PinSource9, GPIO_AF_USART1);
    GPIO_PinAFConfig(GPIOA, GPIO_PinSource10, GPIO_AF_USART1);

    // 3. GPIO 初始化：复用模式、推挽输出、上拉
    GPIO_InitTypeDef GPIO_InitStructure;
    GPIO_InitStructure.GPIO_Pin = GPIO_Pin_9 | GPIO_Pin_10;
    GPIO_InitStructure.GPIO_Mode = GPIO_Mode_AF;      // 关键：复用模式
    GPIO_InitStructure.GPIO_Speed = GPIO_Speed_50MHz;
    GPIO_InitStructure.GPIO_OType = GPIO_OType_PP;
    GPIO_InitStructure.GPIO_PuPd = GPIO_PuPd_UP;      // 上拉防止空闲误码
    GPIO_Init(GPIOA, &GPIO_InitStructure);

    // 4. USART 参数配置：N-8-1 模式
    USART_InitTypeDef USART_InitStructure;
    USART_InitStructure.USART_BaudRate = baudrate;
    USART_InitStructure.USART_WordLength = USART_WordLength_8b;
    USART_InitStructure.USART_StopBits = USART_StopBits_1;
    USART_InitStructure.USART_Parity = USART_Parity_No;
    USART_InitStructure.USART_HardwareFlowControl = USART_HardwareFlowControl_None;
    USART_InitStructure.USART_Mode = USART_Mode_Rx | USART_Mode_Tx;
    USART_Init(USART1, &USART_InitStructure);

    // 5. 中断配置：开启接收非空 (RXNE) 中断
    USART_ITConfig(USART1, USART_IT_RXNE, ENABLE); 

    NVIC_InitTypeDef NVIC_InitStructure;
    NVIC_InitStructure.NVIC_IRQChannel = USART1_IRQn;
    NVIC_InitStructure.NVIC_IRQChannelPreemptionPriority = 1;
    NVIC_InitStructure.NVIC_IRQChannelSubPriority = 1;
    NVIC_InitStructure.NVIC_IRQChannelCmd = ENABLE;
    NVIC_Init(&NVIC_InitStructure);

    // 6. 使能串口
    USART_Cmd(USART1, ENABLE);
}

/**
 * @brief  发送字符串
 * @note   使用轮询 TXE 标志位的方式阻塞发送
 */
void UART1_SendStr(const char *str) {
    while (*str != '\0') {
        USART_SendData(USART1, *str);
        // 等待 TXE 置位 (发送数据寄存器空)，确保数据已移入移位寄存器
        while (USART_GetFlagStatus(USART1, USART_FLAG_TXE) == RESET);
        str++; // 指针后移
    }
}

/**
 * @brief  中断服务函数
 * @note   处理数据接收、缓冲区管理及回显
 */
void USART1_IRQHandler(void) {
    if (USART_GetITStatus(USART1, USART_IT_RXNE) == SET) {
        uint8_t r_data = USART_ReceiveData(USART1); // 读操作自动清除标志位
        
        // 存入缓冲区
        UART1_RxBuffer[u1_count] = r_data;
        
        // 协议判断：以 '#' 结尾
        if (r_data == '#') {
            u1_flag = 1; // 置位标志，通知 main 处理
        } else {
            u1_count++;
            // 缓冲区溢出保护：防止内存越界导致程序崩溃
            if (u1_count >= UART1_RX_MAX_LEN) {
                u1_count = 0;
            }
        }
        
        // 数据回显 (Echo) 用于测试
        USART_SendData(USART1, r_data);
        while (USART_GetFlagStatus(USART1, USART_FLAG_TXE) == RESET);
        
        USART_ClearITPendingBit(USART1, USART_IT_RXNE); // 严谨清除
    }
}
```
