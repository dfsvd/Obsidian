## 一、单片机的复位顺序执行过程
在单片机上电或复位的瞬间，主函数 `main()` 并不是第一个执行的代码。在进入我们熟悉的C语言世界之前，硬件和汇编代码需要完成一系列底层的“铺垫”工作。
### ARM-Cortex-M 处理器的硬件复位行为
当 Cortex-M 处理器（如STM32F4系列）被复位后，它不会立即执行某行代码，而是首先通过硬件机制访问内存空间的起始位置（通常是Flash的0地址），进行“自我定位”。
这个过程严格遵循以下步骤 ：
1. **读取主堆栈指针 (MSP)**：处理器首先读取内存的前四个字节（地址 `0x00000000`），将其内容加载到 **MSP** (Main Stack Pointer) 寄存器中。这是因为后续的C语言函数调用、中断响应都需要依赖堆栈，所以必须在第一时间建立好堆栈环境 。
2. **读取复位向量 (Reset Vector)**：紧接着，处理器读取接下来的四个字节（地址 `0x00000004`）。这个地址存放的实际上是**复位处理函数 (Reset_Handler)** 的入口地址，也就是程序真正开始执行的第一条指令的位置。处理器会将这个地址赋值给程序计数器 **PC** 。
3. **跳转执行**：完成 MSP 和 PC 的初始化后，处理器正式跳转到 `Reset_Handler` 指向的地址开始运行 。
### 启动文件 `startup_stm32f40_41xx.s` 解析
我们在工程中看到的 `.s` 后缀文件（如 `startup_stm32f40_41xx.s`），就是上文中提到的 `Reset_Handler` 的具体实现处。它由汇编语言编写，是系统上电后执行的**第一个程序** 。
这个启动文件不仅仅是程序的入口，它还肩负着以下核心使命 ：
1. **初始化堆栈指针 (SP)**：虽然硬件会自动读取MSP初值，但启动代码中通常会再次确认或调整，确保C语言有良好的内存环境 。
2. **初始化程序计数器 (PC)**：实际上就是定义了 `Reset_Handler`，让 PC 指针有路可走 。
3. **初始化向量表 (Vector Table)**：建立异常入口地址列表，这是后续中断响应的导航图 。
4. **系统时钟配置**：在进入 `main` 函数之前，启动文件会调用 `SystemInit` 函数（通常在 `system_stm32f4xx.c` 中定义）。这一步非常关键，它配置了外部SRAM（如果需要）和系统时钟，确保单片机以正确的速度运行 。
5. **交棒给C语言**：完成上述所有硬件层面的初始化后，汇编代码最后会调用 C 库函数 `__main`，由它引导进入我们在 `main.c` 中编写的 `main()` 函数，从此开始业务逻辑的执行 。
## 二、异常向量表 (Interrupt Vector Table)
### 从 8051 到 STM32：中断机制的进化
为了理解 STM32 的向量表，我们可以对比经典的 8051 单片机。
- **8051模式**：中断入口地址是固定的硬件地址。例如，外部中断0发生时，PC指针强制跳转到 `0x0003`。程序员只能在这些固定的“格子”里编写跳转指令，跳到真正的处理函数 。

- **STM32模式**：采用**向量表**机制。中断发生时，硬件不是跳到固定地址去执行代码，而是去查表。这个表里存放的是**函数地址（指针）**。例如，当中断触发，CPU去查表，发现表里写着 `0x0800xxxx`，于是直接跳转到这个地址去执行函数。这使得中断函数的管理更加灵活 。
### (2) 向量表与链接器的配合
在 STM32 的启动代码中，向量表实际上是一个预先定义好的数组，里面填满了各个中断服务函数（ISR）的名称（即地址）。
**关键问题：单片机怎么知道你写的 C 语言函数就是中断服务函数？** 这依赖于**链接器 (Linker)** 的工作机制。
1. **名称匹配**：启动文件中的向量表已经写好了所有中断函数的“名字”（如 `EXTI0_IRQHandler`）。你在 C 文件中编写中断服务函数时，**函数名必须与启动文件中定义的一模一样** 。
2. **自动填填**：编译链接时，链接器会发现：“咦，用户在 main.c 里定义了一个 `EXTI0_IRQHandler`，它的地址是 `0x08000451`。” 于是，链接器会自动把这个地址填入向量表中对应的位置（如 `0x00000058`）。
我们可以通过查看编译生成的 **`.map` 文件**（位于 `USER/Listings` 目录）来验证这一过程。`.map` 文件中的 **Image Symbol Table** 详细记录了每个函数的实际存储地址。
- **查找实例**：在 `.map` 文件中搜索 `EXTI0_IRQHandler`，你可以看到它被分配到了类似 `0x08000451` 的地址。
- **验证映射**：同时查看向量表偏移 `0x00000058` 的位置，你会发现里面存储的数据正是 `0x08000451`。这证明了链接器成功地将你的函数挂载到了硬件中断线上 。
### `WEAK` 弱声明与 `B.` 死循环
启动文件中定义了所有的中断服务函数，但如果我们不使用某个中断，难道还要一个个去写空函数吗？为了解决这个问题，启动文件使用了汇编语言的巧妙设计。
#### `WEAK` 关键字（弱声明）
启动文件中的中断函数都加上了 `[WEAK]` 属性。
- **含义**：告诉链接器，“这个函数是备胎”。
- **机制**：如果用户在 C 代码中写了一个同名的函数（强定义），链接器就会优先使用用户写的；如果用户没写，链接器就使用启动文件里默认的这个函数。这就实现了“有则用之，无则兜底”的灵活性 。
#### `B.` 指令（默认处理）
那些默认的“备胎”函数内部都只有一条指令：`B .`。
- **含义**：`B` 是跳转指令，`.` 代表当前地址。合起来就是“跳转到当前地址”，即 **死循环**（相当于 C 语言的 `while(1)`）。
- **作用**：这是一个**错误捕获机制**。如果你开启了某个中断（如 `EXTI0`），但忘记在 C 代码中写 `EXTI0_IRQHandler` 函数，或者函数名拼写错了，那么中断触发时，系统就会调用默认的 `WEAK` 函数，进入死循环。
- **调试意义**：当你的单片机莫名其妙“死机”时，暂停调试，如果发现程序停在启动文件的某个 `B .` 处，那就说明你**触发了一个没有处理的中断** 。
