## 寄存器开发与C语言位运算
### 1. 寄存器编程的系统化步骤
在脱离库函数直接操作寄存器时，需要建立清晰的硬件思维流程 ：
1. **硬件原理分析**：
    - 查看开发板原理图，定位目标外设（如LED）连接的引脚（例如PF9）
    - 理解电路逻辑（例如：高电平点亮还是低电平点亮）
2. **程序设计逻辑**：
    - **时钟使能 (RCC)**：STM32为了低功耗，默认关闭所有外设时钟操作GPIO前必须先开启对应的GPIO组时钟（如GPIOF）
    - **GPIO模式配置**：
        - 模式 (Mode)：输出模式
        - 输出类型 (OType)：推挽输出（驱动能力强）或开漏输出
        - 上下拉 (PuPd)：根据电路需要设置
        - 速度 (Speed)：设置引脚翻转速度
    - **电平控制 (ODR/BSRR)**：向输出数据寄存器写入高低电平

### C语言位运算
寄存器操作本质上是**按位**修改内存数据熟练掌握以下操作是嵌入式开发的基石 ：

| 符号   | 名称   | 逻辑说明      | 常用场景                 |
| ---- | ---- | --------- | -------------------- |
| `&`  | 按位与  | 有0则0，全1为1 | **清零**特定位，保留其他位      |
| `\|` | 按位或  | 有1则1，全0为0 | **置位**（置1）特定位，保留其他位  |
| `^`  | 按位异或 | 相同为0，相异为1 | **翻转**特定位            |
| `~`  | 按位取反 | 0变1，1变0   | 生成掩码                 |
| `<<` | 左移   | 整体左移，低位补0 | 构造特定位置1的数（如 `1<<15`） |
| `>>` | 右移   | 整体右移      | 解析高位数据               |

典型试题解析

假设 `unsigned int num = 123456;`（32位数据）
- 将第15位清零，其他位不变
    - **方法**：`num &= ~(1 << 15);`
    - **解析**：
        1. `1 << 15` 得到只有第15位为1，其余为0的数
        2. `~` 取反后，得到只有第15位为0，其余全为1的掩码
        3. `&` 运算后，第15位被强制清零，其他位因与1进行与运算而保持不变
- 将第30位置1，其他位不变
    - **方法**：`num |= (1 << 30);`
    - **解析**：`1 << 30` 只有第30位为1，与原数进行或运算，第30位被强制置1，其他位（与0或）不变
- 将第10位翻转（0变1，1变0）
    - **方法**：`num ^= (1 << 10);`
    - **解析**：利用异或特性（1^0=1, 1^1=0），与1异或实现翻转，与0异或保持不变
- 判断num的第16位是否为1还是为0
	- **方法**：`num & (1<<16）`
    - **解析**：利用与运算特性（1|1=1, 1|0=0,0|0=0），与 1 实现读取当所在位为 1 时表达式为真其余为假

难点：C语言中的绝对地址访问

- 知道一个地址0xC000 0000,向该地址写数据(int)0x12345678
	- **错误写法**：`0xC0000000 = 0x1234;` （编译器报错，左值必须是变量）
	- **正确写法**：`*(unsigned int*)0xC0000000 = 0x1234;`
	    - **第一步**：`(unsigned int*)0xC0000000` 将立即数强制转换为“无符号整型指针”，告诉编译器这是一个地址
	    - **第二步**：`*` 对指针解引用，访问该地址指向的内存空间
    - **注意**：这种操作仅在单片机/驱动开发（裸机）中有效在带操作系统的PC上应用层开发中，直接访问物理地址会触发**段错误**，因为虚拟内存受OS保护
## 位带操作
### 1. 使用位带操作原因
- **传统痛点** ：
    - **51单片机**：支持 `P1.0 = 1;` 这种极其方便的位寻址，代码简洁
![](images/005_%20寄存器与位带操作/file-20260104231026038.jpg)
    - **STM32标准库**：操作一个IO口需要调用 `GPIO_SetBits` 等函数这些函数内部包含断言检查、参数传递、读-改-写 (Read-Modify-Write) 过程步骤繁琐，且函数调用有入栈出栈开销，效率不够极致
- **位带优势** ：
    - **原子性**：位带写入是一条指令完成的，不会被中断打断（在多任务或中断环境中极其重要）
    - **高效性**：省去了读取寄存器、位运算修改、再写回寄存器的三个步骤，直接映射写入
    - **代码简洁**：实现类似51单片机的 `PFout(9) = 1;` 写法
2. 位带操作原理
Cortex-M3/M4 提供了两个**位带区 (Bit-band region)**，这两个区域的每一位（1 bit）都通过硬件映射机制，膨胀映射到了另一个独立的地址区域，称为**位带别名区 (Bit-band alias region)** 的一个字（32 bit）
- **操作逻辑**：
    - 程序员操作“别名区”的一个32位字（赋值0或1）
    - 硬件自动将这个操作转换为对“位带区”对应原始位的修改
    - **注意**：操作别名区时，只有最低位（LSB, Bit0）有效，写1置位，写0清零
2. 内存映射计算公式
STM32主要有两个位带区：
3. **SRAM 区**：`0x2000 0000` ~ `0x200F FFFF` (最低1MB)
4. **片上外设区**：`0x4000 0000` ~ `0x400F FFFF` (最低1MB)
#### 统一计算公式
要计算某个寄存器（Addr）的第 n 位（BitNum）对应的**别名区地址**：
AliasAddr=BaseAlias+(Addr−BaseRegion)×32+BitNum×4
- `BaseAlias`：别名区起始地址（SRAM为 `0x22000000`，外设为 `0x42000000`）
- `BaseRegion`：位带区起始地址（SRAM为 `0x20000000`，外设为 `0x40000000`）
- `Addr`：目标寄存器的物理地址
- `BitNum`：要操作的第几位 (0-31)
- `* 32`：因为1个位膨胀为32位（4字节），所以字与字之间偏移32
- `* 4`：因为别名区是按字（4字节）寻址的
宏定义实现 (sys.h)
为了方便使用，通常封装成宏：
```c
#define BITBAND(addr, bitnum) ((addr & 0xF0000000)+0x02000000+((addr &0xFFFFF)<<5)+(bitnum<<2))
#define MEM_ADDR(addr)  *((volatile unsigned long  *)(addr))
#define BIT_ADDR(addr, bitnum)   MEM_ADDR(BITBAND(addr, bitnum))

// GPIOF 输出控制宏示例
#define PFout(n)   BIT_ADDR((uint32_t)&GPIOF->ODR, n)
// GPIOA 输入读取宏示例
#define PAin(n)    BIT_ADDR((uint32_t)&GPIOA->IDR, n)
```

这样即可直接使用 `PFout(9) = 1;` 来点灯

## 编译器优化
1. 编译优化等级 (-O0 ~ -O3)
编译器为了节省空间或提高速度，会改写用户的代码逻辑
- **-O0 (默认)**：无优化代码按部就班执行，最适合调试，但体积大、速度慢
- **-O1**：轻度优化
- **-O2 (推荐)**：在代码体积和运行速度间取得平衡，是发布产品的常用选项**但在调试时可能会出现“代码乱跳”或变量无法查看的情况**
- **-O3**：最高级优化可能采用极其激进的策略（如循环展开、内联函数），有时会导致逻辑错误

## volatile 关键字
### 内存分布 (Map文件分析)
编译后的程序大小由以下几部分组成：
- **Code**：程序代码指令（存放在Flash）
- **RO-data (Read Only)**：常量，如 `const` 变量、字符串（存放在Flash）
- **RW-data (Read Write)**：已初始化的全局变量/静态变量（Flash中存初值，运行时搬运到RAM）
- **ZI-data (Zero Initialized)**：未初始化或初始化为0的变量（仅占用RAM，上电后清零）
- **结论**：
    - Flash占用大小 = Code + RO-data + RW-data
    - RAM占用大小 = RW-data + ZI-data
1. `volatile` 关键字详解
`volatile`（易变的）是告诉编译器：**“这个变量的值可能会在程序控制之外被改变，请不要对我进行任何优化，每次使用都必须直接从内存地址读取”**
### 必须使用 `volatile` 的三个场景：
1. **软件延时循环**：
    - **现象**：在 `-O2` 优化下，纯粹的 `while(i--);` 延时循环可能被编译器认为“无实际意义”而直接删除，导致延时失效
    - **解决**：定义 `volatile int i;`
2. **中断服务函数 (ISR) 与主循环共享的全局变量**：
    - 如果主循环检测一个由中断修改的标志位，不加 `volatile` 编译器可能会把变量值缓存在寄存器中，导致主循环永远看不到中断修改后的值
3. **硬件寄存器访问**：
    - 硬件寄存器的值会随电路状态变化（如按键输入寄存器 IDR）如果编译器优化，可能只读一次就不再更新，导致无法检测按键
    - **STM32库中所有寄存器定义都加了 `__IO` (即 `volatile`)**

> 1. 需要将单片机通过调试器(j-link就有这个功能)连接到电脑上，就可以在电脑上的keil5软件上去调试单片机

1. 调试环境搭建
- **硬件**：使用 J-Link 或 ST-Link 连接单片机与电脑
- **软件**：Keil MDK 点击 "Start/Stop Debug Session" (红色的d图标)
1. 核心调试功能
- **断点 (Breakpoints)**：在特定行设置红色圆点，程序运行到此处会自动暂停，用于检查逻辑流向
![](images/005_%20寄存器与位带操作/file-20260104231026042.jpg)
- **单步执行**：
    - Step Over (F10)：执行一行，遇到函数不进入
    - Step Into (F11)：执行一行，遇到函数则进入函数内部
- **观察窗口 (Watch Window)**：
    - 实时监控变量的值
    - 可以输入 `num` 或 `GPIOB->ODR` 等表达式查看内存变化
    - **重要技巧**：如果变量被编译器优化掉了，Watch窗口可能会显示 "cannot evaluate"
