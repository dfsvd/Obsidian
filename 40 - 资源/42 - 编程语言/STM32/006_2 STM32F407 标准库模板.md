#stm32
本文档记录了如何配置一套基于 STM32F407VGT6 的现代化开发环境目标是结合 VSCode 的优秀编辑体验与 Keil 的稳定编译和 debug 能力，并解决标准库开发中常见的头文件索引与代码跳转问题
- 环境参数
	- **操作系统 (OS)**：Windows 11
	- **IDE (编辑器)**：VS Code
	- **MCU 型号**：STM32F407VGT6
	- **开发方式**：标准外设库 (StdPeriph_Lib)
	- **编译器**：ARM Compiler 5 (armcc)/ 6(armclang)
	- **构建系统**：Keil Project 引擎
	- **语言服务器**：Clangd
	- **调试/烧录**：DAPLink / J-Link / ST-Link
## 工程目录结构搭建
为了保持工程整洁，建议在工程根目录下手动创建以下文件夹结构这种结构将源代码、库文件和编译中间文件分离开来
1. **USER**：存放用户编写的核心应用代码（如 `main.c`, `stm32f4xx_it.c` 等）
2. **CORE**：存放 Cortex-M4 内核接口文件和芯片启动文件
3. **FWLIB**：存放 ST 官方标准外设库文件（Library）
4. **SYSTEM**：存放通用的系统级代码（如 `delay`, `sys`, `usart` 文件夹）
5. **HARDWARE**：存放用户自定义的硬件驱动（如 `led`, `key`, `lcd` 等）
6. **OBJ**：专门存放编译过程中产生的中间文件（`.hex`, `.o`, `.axf` 等），避免污染源代码目录

## 固件库文件复制与筛选
这一步是将官方库中必要的文件提取到我们的工程文件夹中
### 复制 FWLIB (外设驱动库)
打开官方固件库包，定位到 `\Libraries\STM32F4xx_StdPeriph_Driver` 目录：
- 将该目录下的 **`inc`** (头文件) 和 **`src`** (源文件) 两个文件夹，完整复制到我们工程的 **FWLIB** 目录下
- _注意：后续在 Keil 中添加文件时，可根据需要剔除不用的驱动（如 `fmc` 相关），但物理文件建议全部保留以便查阅_
### 复制 CORE (内核与启动文件)
这里需要精准选择文件，因为官方包里混杂了不同系列的文件
- 启动文件（关键步骤）：
    定位到 \Libraries\CMSIS\Device\ST\STM32F4xx\Source\Templates\arm 目录
    复制 startup_stm32f40_41xxx.s 到工程的 CORE 目录
    - _理由：STM32F407 属于 Foundation Line，对应 `40_41xxx` 命名规则请勿使用 401, 411 或 429 系列的启动文件_
- 内核头文件：
    定位到 \Libraries\CMSIS\Include 目录
    复制以下 4 个文件到工程的 CORE 目录：
    - `core_cm4.h`
    - `core_cmFunc.h`
    - `core_cmInstr.h`
    - `core_cm4_simd.h`
### 复制 USER (工程模板文件)
我们需要官方提供的模板文件来初始化工程
- 关键头文件：
    定位到 \Libraries\CMSIS\Device\ST\STM32F4xx\Include 目录
    复制 stm32f4xx.h 和 system_stm32f4xx.h 到工程的 USER 目录
- 应用层模板：
    定位到 \Project\STM32F4xx_StdPeriph_Templates 目录
    复制以下 5 个文件到工程的 USER 目录：
    - `main.c`
    - `main.h`
    - `stm32f4xx_conf.h` (配置文件，用于开关外设模块)
    - `stm32f4xx_it.c` (中断服务函数模板)
    - `stm32f4xx_it.h`
    - `system_stm32f4xx.c` (系统时钟初始化)

## Keil MDK 工程配置
### 1. 新建工程与添加文件
1. 打开 Keil，点击 `Project` -> `New uVision Project`，保存到工程根目录（或 USER 目录下）
2. **选择芯片**：在弹出的窗口中搜索并选择 **STM32F407VGTx**直接点击 ok 不要手动选择头文件
![](images/006_2%20STM32F407%20标准库模板/file-20260113100304565.jpg)
3. **管理组件**：点击 "Manage Project Items"（三个方块的图标），创建 Group 并添加对应的 `.c` 和 `.s` 文件：
    - **USER Group**: 添加 `main.c`, `stm32f4xx_it.c`, `system_stm32f4xx.c`
    - **CORE Group**: 添加 `startup_stm32f40_41xxx.s`
    - **FWLIB Group**: 添加 `src` 下的所有 `.c` 文件
        - **重要剔除**：找到 **`stm32f4xx_fmc.c`** 并将其移除（Remove）STM32F407 使用的是 FSMC 模块（`stm32f4xx_fsmc.c`），FMC 是 F429 等更高级芯片才有的，不移除会报错
### 2. "魔术棒" 详细设置
点击魔术棒图标，进行关键配置：
#### A. Output 选项卡
- 勾选 **Select Folder for Objects**
- 在弹出的浏览框中，选择我们第一步建立的 **OBJ** 文件夹
- _作用：让编译产生的垃圾文件都进去 OBJ，不弄乱代码目录_
![](images/006_2%20STM32F407%20标准库模板/file-20260113100304567.jpg)
#### B. C/C++ 选项卡 (核心配置)
这是最容易出错的地方，请仔细核对
1. Preprocessor Symbols (预处理宏定义)：
    在 Define 输入框中填入：
    ```Plaintext
    STM32F40_41xxx,USE_STDPERIPH_DRIVER
    ```
    - `STM32F40_41xxx`：告诉库文件当前是 F405/407/415/417 系列，以便正确引用头文件
    - `USE_STDPERIPH_DRIVER`：启用标准外设库，否则无法使用库函数
2. Include Paths (头文件包含路径)：
    点击右侧 ... 按钮，将所有包含 .h 文件的文件夹都加进去通常包括：
    ```Plaintext
    .\USER
    .\CORE
    .\FWLIB\inc
    .\SYSTEM
    .\HARDWARE
    ```
    - _注意：如果 HARDWARE 下还有子文件夹（如 HARDWARE\LED），也要单独添加进去_

3. anguage Code Generation (语言标准)
    - 勾选 **C99 Mode**。
    - _作用：支持更灵活的 C 语言语法（如在 `for` 循环内定义变量：`for(int i=0;...`）。_
4. **Optimization (优化等级)**
    - **可选**：将 Optimization 设置为 **Level 2 (Size)**。
    - _作用：平衡编译速度与代码体积/运行效率。Debug 阶段常用 Level 0 以便调试，正式发布或代码量大时可用 Level 2。_
#### C. Debug 选项卡 (调试配置)
1. **选择仿真器**
    - 在右上角的下拉框中，选择使用的下载器：**J-LINK / J-TRACE**、**ST-Link Debugger** 或 **CMSIS-DAP Debugger**。
2. **详细设置 (Settings)** 点击仿真器右侧的 **Settings** 按钮，进入详细配置：
    - **Debug 标签页**：
        - **Port**: 选择 **SW** (Serial Wire)。
        - _注意：SW 模式比 JTAG 节省引脚且速度快，确认右侧框中能识别到芯片 ID (ARM CoreSight)。_
    - **Flash Download 标签页**：
        - 勾选 **Reset and Run**。
        - _作用：程序下载完成后，自动复位并开始运行，无需手动按开发板上的复位键。_

## VSCode + Clangd 环境配置
为了在 VSCode 中获得极速的代码补全、跳转，并消除红色波浪线报错，我们需要告诉 VSCode (Clangd) 我们的工程配置
操作方法：
在工程的根目录（即包含 USER, CORE 等文件夹的那个目录）下，新建一个名为 compile_flags.txt 的文件
**文件内容**（请直接复制以下内容）：
```Plaintext
# 编译器模式设置
-xc
-std=c99
--target=arm-none-eabi

# 预处理宏定义 (必须与 Keil 中的 Define 一致)
-DSTM32F40_41xxx
-DUSE_STDPERIPH_DRIVER

# 头文件搜索路径 (必须与 Keil 中的 Include Paths 一致)
-IUSER
-ICORE
-IFWLIB/inc
-ISYSTEM
-IHARDWARE

# 如果你有其他子目录，继续以 -I 开头添加
# 例如: -IHARDWARE/LED
```

**生效方式**：保存该文件后，重启 VSCode，或者按 `F1` 输入 `clangd: Restart language server`此时尝试点击 `GPIO_Init` 等函数，应能正常跳转

## 优化体验
### 双向同步优化 (Keil 自动重载)
keil 默认没有开启外部修改文件的自动重新加载导致每次在 VSCode 修改后还需要点击确认影响体验, 为了为了实现“VSCode 写代码 -> 保存 -> 切换 Keil 直接编译”的流畅体验，必须开启 Keil 的自动刷新功能
1. 在 Keil 菜单栏点击 **Edit** (编辑) -> **Configuration** (配置)
2. 切换到 **Editor** (编辑器) 选项卡
3. 找到右侧的 "File & Project Handling"
4. **勾选** ✅ **Automatic reload of externally modified files**
5. 点击 OK 保存
![](images/006_2%20STM32F407%20标准库模板/file-20260113100304568.jpg)
### 一键清理中间文件
Keil 在编译过程中会产生大量的中间文件（如 `.o`, `.d`, `.crf`, `.htm` 等），这些文件虽然对调试有用，但会占用大量磁盘空间，且在需要打包、备份或传输工程给他人时显得非常臃肿。
通过创建一个批处理脚本，我们可以一键清理这些“垃圾”文件，使工程瞬间“瘦身”
**操作步骤**：
1. 在工程根目录下（即包含 `USER`, `CORE` 等文件夹的目录），新建一个文本文件。
2. 将文件名修改为 `keilkill.bat`（注意后缀名必须是 `.bat`）
3. 右键点击该文件选择“编辑”，将以下内容复制进去并保存：
```bat
del *.bak /s
del *.ddk /s
del *.edk /s
del *.lst /s
del *.lnp /s
del *.mpf /s
del *.mpj /s
del *.obj /s
del *.omf /s
::del *.opt /s  ::不允许删除JLINK的设置，保留调试配置
del *.plg /s
del *.rpt /s
del *.tmp /s
del *.__i /s
del *.crf /s
del *.o /s
del *.d /s
del *.axf /s
del *.tra /s
del *.dep /s           
del JLinkLog.txt /s
 
del *.iex /s
del *.htm /s
del *.sct /s
del *.map /s
exit
```
**使用提示**：
- **何时使用**：在需要压缩打包工程发送给他人，或者想要彻底重新编译整个工程之前
- **如何使用**：直接双击运行工程目录下的 `keilkill.bat` 即可

### 解决 Clangd 无法跳转到 .c 文件定义
- **问题原因**：由于 `compile_flags.txt` 只是一个通用的编译参数列表，Clangd 默认不知道工程中包含哪些具体的源文件（如 `misc.c` 或 `stm32f4xx_gpio.c`），因此无法建立文件间的索引关联，导致无法跳转到函数定义。此外，Keil (ARMCC) 的非标语法（如 `__asm`, `__inline`）会导致 Clangd 解析时出现大量红色波浪线
- **解决方法**：放弃 `compile_flags.txt`，转而使用 **`compile_commands.json`**（编译数据库）配合 **`.clangd`** 配置文件。我们需要编写一个 Python 脚本，自动读取 Keil 的 `.uvprojx` 工程文件，识别芯片型号并生成 Clangd 能识别的索引与语法补丁文件。
#### 操作步骤：
1. **清理旧配置**
    - 删除工程根目录下的 `compile_flags.txt` 文件（如果存在）。
2. **创建脚本目录**
    - 在工程根目录下新建一个名为 **`TOOLS`** 的文件夹。
3. **新建集成转换脚本**
    - 在 `TOOLS` 文件夹内新建文件 [keil2json](../../49%20-%20代码片段/keil2json.py)，并写入以下代码：
    ```Python
import xml.etree.ElementTree as ET

import json

import os

import glob

import sys



## 脚本会探测以下目录寻找 .uvprojx

SEARCH_DIRS = [".", "USER", "Project", "MDK-ARM"]

KEIL_INC_PATH = "D:/Program/Development/Keil_v5/ARM/ARMCC/include"



DEVICE_MAP = {

    "STM32F405": {"macro": "STM32F40_41xxx", "arch": "cortex-m4"},

    "STM32F407": {"macro": "STM32F40_41xxx", "arch": "cortex-m4"},

    "STM32F417": {"macro": "STM32F40_41xxx", "arch": "cortex-m4"},

    "STM32F429": {"macro": "STM32F429_439xx", "arch": "cortex-m4"},

    "STM32F401": {"macro": "STM32F401xx",    "arch": "cortex-m4"},

    "STM32F103ZE": {"macro": "STM32F10X_HD", "arch": "cortex-m3"},

    "STM32F103VE": {"macro": "STM32F10X_HD", "arch": "cortex-m3"},

    "STM32F103RC": {"macro": "STM32F10X_HD", "arch": "cortex-m3"},

    "STM32F103RB": {"macro": "STM32F10X_MD", "arch": "cortex-m3"},

    "STM32F103C8": {"macro": "STM32F10X_MD", "arch": "cortex-m3"},

}

## ===========================================



def generate_dot_clangd(output_dir, chip_config):

    """生成 .clangd 到指定的项目根目录"""

    clangd_content = f"""# cSpell:disable

CompileFlags:

  Add: [

    "-I", "{KEIL_INC_PATH}",

    "--target=arm-none-eabi",

    "-mcpu={chip_config['arch']}",

    "-D{chip_config['macro']}",

    "-DUSE_STDPERIPH_DRIVER",

    "-fms-extensions",

    "-fms-compatibility",

    "-fdeclspec",

    "-D__CC_ARM",

    "-D__ARMCC_VERSION=5060000",

    "-D__STATIC_INLINE=static inline",

    "-D__inline=inline",

    "-D__forceinline=inline",

    "-D__asm(x)=",          

    "-D__asm=",              

    "-Dasm=",                

    "-D__ALIGNED(x)=",

    "-D__task=",

    "-D__declspec(x)=",

    "-D__value_in_regs=",

    "-D__breakpoint(x)=",

    "-Wno-invalid-noreturn",

    "-Wno-unused-parameter",

    "-Wno-missing-declarations",

    "-Wno-implicit-function-declaration"

  ]



Index:

  Background: Build



Diagnostics:

  UnusedIncludes: None

  Suppress: [

    "ms_attributes_not_enabled",

    "unknown_typename",

    "pp_hash_error",

    "fatal_too_many_errors"

  ]

"""

    with open(os.path.join(output_dir, ".clangd"), "w", encoding='utf-8') as f:

        f.write(clangd_content)



def parse_keil_project(file_path):

    tree = ET.parse(file_path)

    root = tree.getroot()

    # 记录 .uvprojx 所在的绝对路径目录

    proj_file_dir = os.path.dirname(os.path.abspath(file_path))

    device_node = root.find(".//Device")

    device_name = device_node.text if device_node is not None else ""

    chip_config = {"macro": "STM32F40_41xxx", "arch": "cortex-m4"} # 默认 F4

    for key, config in DEVICE_MAP.items():

        if key in device_name:

            chip_config = config

            break



    defines = []

    def_node = root.find(".//VariousControls/Define")

    if def_node is not None and def_node.text:

        defines = [d.strip() for d in def_node.text.split(",") if d.strip()]

    if chip_config['macro'] not in defines: defines.append(chip_config['macro'])

    if "USE_STDPERIPH_DRIVER" not in defines: defines.append("USE_STDPERIPH_DRIVER")



    includes = []

    inc_node = root.find(".//VariousControls/IncludePath")

    if inc_node is not None and inc_node.text:

        for inc in inc_node.text.split(";"):

            # 路径拼接基于 .uvprojx 所在的目录

            abs_path = os.path.normpath(os.path.join(proj_file_dir, inc.strip()))

            includes.append(abs_path.replace("\\", "/"))



    sources = []

    for f_node in root.findall(".//File"):

        f_path = f_node.find("FilePath")

        if f_path is not None and f_node.find("FileType").text == "1":

            abs_src = os.path.normpath(os.path.join(proj_file_dir, f_path.text))

            sources.append(abs_src.replace("\\", "/"))

    return includes, defines, sources, chip_config



if __name__ == "__main__":

    # 1. 确定工作区根目录

    workspace_root = os.getcwd()

    # 2. 在工作区及其子目录中搜索 .uvprojx

    project_files = glob.glob("./**/*.uvprojx", recursive=True)

    if not project_files:

        print("[Error] No .uvprojx found in this directory or subdirectories!")

        sys.exit(1)

    # 优先选择搜索路径中最浅层的文件

    target_project = sorted(project_files, key=len)[0]

    print(f"[Info] Target Project: {target_project}")



    try:

        inc, defi, src, chip_config = parse_keil_project(target_project)

        # 3. 生成编译指令数据库

        cmds = []

        base_flags = ["arm-none-eabi-gcc", "-c", "-std=c99", f"-mcpu={chip_config['arch']}", "-mthumb"]

        base_flags += [f"-I{i}" for i in inc] + [f"-D{d}" for d in defi]

        for s in src:

            cmds.append({

                "directory": workspace_root.replace("\\", "/"),

                "command": " ".join(base_flags) + " " + s,

                "file": s

            })

        # 4. 始终将结果生成到当前运行脚本的根目录下

        with open(os.path.join(workspace_root, "compile_commands.json"), "w", encoding='utf-8') as f:

            json.dump(cmds, f, indent=4)

        generate_dot_clangd(workspace_root, chip_config)

        print(f"[Success] Project configured for {chip_config['macro']}.")

        print(f"          Output: {workspace_root}/compile_commands.json & .clangd")

    except Exception as e:

        print(f"[Error] {e}")
    ```

- **生成配置**
    - 在 VSCode 终端中运行命令：`python TOOLS/keil2json.py`。
    - 观察根目录是否生成了 `compile_commands.json`（解决跳转）与 `.clangd`（消除报错）。
- **生效验证**
    - 按 `F1` 输入 `Clangd: Restart language server` 重启服务。
    - 尝试按住 `Ctrl` 点击函数名，此时应能正常跳转到 `.c` 文件定义处
