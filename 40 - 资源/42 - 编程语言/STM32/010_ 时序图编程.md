在嵌入式开发中，从简单的GPIO操作进阶到复杂外设驱动，**时序图分析**是必经之路很多初学者习惯于调用现成的库函数，但一旦涉及底层驱动调试或非标准协议对接，无法看懂时序图往往成为技术瓶颈

本文将以STM32为平台，通过HC-SR04超声波、DHT11温湿度传感器和HS0038红外接收头三个经典模块，深度解析“单总线”及“脉宽调制”类时序的处理技巧这不仅仅是驱动代码的编写，更是对微秒级时间控
## HC-SR04 超声波
### 模块说明
**HC-SR 04** 超声波测距模块可提供 **2 cm-400 cm** 的非接触式距离感测功能，测距精度可达 **3 mm**；模块包括超声波发射器、接收器与控制电路

#### 基本工作原理
测距过程由模块内部硬件自动完成，控制流程如下：
1. 触发信号：
    MCU（单片机）向模块的 TRIG 引脚输入一个持续时间 至少 10μs 的高电平脉冲，以此启动测距周期
2. 内部发射：
    模块接收到触发信号后，内部自动发送 8 个 40kHz 的方波（超声波脉冲），并自动切换为接收模式检测是否有信号返回
    (注：发送 8 个脉冲是为了确保信号强度足够且易于识别)
3. 回响信号：
    一旦检测到回波信号，模块会将 ECHO 引脚拉高高电平持续的时间即为超声波从发射出去到反射回来的总时长
4. 距离计算：
    根据声波在空气中的传播速度，距离公式为：
    $$\text{测试距离} = \frac{\text{高电平时间} \times \text{声速}(340m/s)}{2}$$

> 在量具量仪的术语中：
> - **精度 (Accuracy)**：一般等同于**误差**，指测量值与真实值之间的接近程度（本模块为 3mm）
> - **分辨力/分辨率 (Resolution)**：实际上是**最小读数值**，即系统能识别到的最小变化量

> - **防烧毁**：建议**断电连接**若必须带电操作，务必**优先连接 GND 端**，防止电流倒灌烧毁芯片

### 时序图
阅读嵌入式驱动的时序图，核心技巧遵循 **“从上到下，从左到右”** 的原则——从上到下看不同信号引脚的电平配合，从左到右看时间轴上的先后因果
#### 硬件信号映射

在分析时序之前，必须先将抽象的时序信号与开发板的物理引脚对应起来如下图所示，**Trigger 触发信号**由 MCU 的 **PB6** 引脚控制（需配置为推挽输出），而 **Echo 回响信号**则由 **PE6** 引脚捕获（需配置为输入模式）

#### 时序逻辑
明确引脚关系后，结合下方的标准时序图，我们可以将一次完整的测距过程拆解为四个紧密咬合的阶段（t1 - t4）：
**1. 触发启动 (t1阶段)**
- **物理动作**：MCU 需要向 **PB6 (Trig)** 引脚输出一个持续时间 **$\ge 10\mu s$** 的 TTL 高电平脉冲
- **原理逻辑**：这个 10 微秒的延时并非随意设定，它充当了启动模块的“数字密钥”，用于防止电源波动或电磁干扰误触发模块
- **代码映射**：程序层面对应简单的 GPIO 操作：`PB6=1; delay_us(10); PB6=0;`
**2. 内部发射 (t2阶段)**
- **物理动作**：模块内部硬件会自动产生并向外发射 **8 个 40kHz** 的声波脉冲
- **原理逻辑**：此过程对用户是**透明且不可控**的模块选用 40kHz 频率是因为该频段在空气中传播效率较高且避开了人耳听觉范围；发送 8 个脉冲则是为了确保信号能量足够强，以便在遇到障碍物后能产生清晰的回波
**3. 信号监测 (t3阶段)**
- **物理动作**：发射结束后，模块会将 **PE6 (Echo)** 引脚拉高
- **原理逻辑**：Echo 引脚变高，标志着模块已经完成了发射任务，正式进入“监听模式”
- **代码映射**：MCU 侧的任务是从“发送指令”切换为“等待响应”，代码通常使用 `while(PE6==0)` 轮询等待 Echo 引脚的上升沿
**4. 距离计量 (t4阶段 - 核心)**
- **物理动作**：**PE6** 将持续保持高电平，直到模块接收到返回的超声波信号，PE6 才会随即变低
- **原理逻辑**：这是时序图中最关键的一环——**高电平的持续宽度 (Pulse Width)** 在物理意义上完全等同于超声波在空气中往返飞行的时间（Time of Flight）

- **代码映射**：这是算法计算的基础MCU 必须在 PE6 为高电平期间开启计数器（或在循环中累加延时），一旦 PE6 变低，立即停止计数最终获得的计数值，就是计算距离公式中唯一的变量 $t$

### 注意事项
在实际编程与应用中，需严格遵守以下 4 点工程细节：
#### 温度补偿
不同的温度，声音的传播速度是不一样的
- **公式**：$c = 331.4 \times \sqrt{1 + T/273} \approx 331.4 + 0.607T (m/s)$
- **数据参考**：例如 20℃ 时声速约为 344m/s，30℃ 时约为 349m/s
#### 动态速度切换
超声波代码编写时，以后测量距离**必须根据温湿度传感器提供的温度代入上述公式**，动态切换声音传播速度值
#### 测量精度与时间换算
超声波的测量精度为 3mm，可根据 3mm 的测距求出测量时间
求算如下：

$$\frac{340 \times 100 \times 10mm}{1000000us} = \frac{3mm}{t}$$

$$t \approx 9us$$

(注：即程序中每延时 9us 计数一次，代表距离增加了 3mm)
### 代码实现
#### 编程思路
1. 初始化阶段 (`HC_SR04_Init`)
	- **硬件配置**：
	    - **时钟使能**：超声波模块连接了两个不同的 GPIO 端口（PB6 和 PE6），需要分别使能 `GPIOB` 和 `GPIOE` 的时钟
	    - **引脚模式**：
	        - **TRIG (PB6)**：作为触发信号，MCU 需要向模块发送脉冲，因此配置为 **推挽输出模式 (Output)**
	        - **ECHO (PE6)**：作为回响信号，MCU 需要接收模块的高电平脉冲，因此配置为 **输入模式 (Input)**
	    - **初始状态**：将 TRIG 引脚拉低，确保上电后不会误触发
##### 2. 测距阶段 (`HC_SR04_GetDis`)
测距过程严格遵循时序图逻辑，分为三步：
- **第一步：触发 (Trigger)**
    - 将 TRIG 拉高，维持至少 **10us**
    - 拉低 TRIG，结束触发信号
- **第二步：检测回响 (Echo)**
    - **等待高电平**：监测 ECHO 引脚，等待其变高（表示模块已发射超声波并准备接收回波）需配合**超时处理**防止程序死锁
    - **测量持续时间**：一旦 ECHO 变高，开始计时（或计数），直到 ECHO 变低（表示接收到回波）
    - **计数技巧**：利用之前推导的公式，每延时 **9us** 计数一次，该计数值对应的物理意义即为声波传播了 3mm
- **第三步：计算与返回**
    - 根据计数值计算距离
    - 返回类型建议使用 `float` 以保留更高精度
#### 代码实现
```c
#include "stm32f4xx.h" // 根据实际工程引用头文件

// 宏定义，方便移植
#define TRIG_PIN  GPIO_Pin_6
#define TRIG_PORT GPIOB
#define ECHO_PIN  GPIO_Pin_6
#define ECHO_PORT GPIOE

// 位带操作或库函数宏定义 (示例)
#define PBout(n)  *(volatile uint32_t *)(0x42000000 + (GPIOB_BASE-0x40000000)*32 + (n)*4)
#define PEin(n)   *(volatile uint32_t *)(0x42000000 + (GPIOE_BASE-0x40000000)*32 + (n)*4)
#define TRIG      PBout(6)
#define ECHO      PEin(6)

/**
 * @brief  初始化HC_SR04超声波模块
 * @note   TRIG(PB6) -> 输出; ECHO(PE6) -> 输入
 */
void HC_SR04_Init(void)
{
    GPIO_InitTypeDef  GPIO_InitStructure;

    // 1. 使能GPIO时钟 (GPIOB 和 GPIOE)
    RCC_AHB1PeriphClockCmd(RCC_AHB1Periph_GPIOB | RCC_AHB1Periph_GPIOE, ENABLE);

    // 2. 配置TRIG引脚 (PB6) 为输出
    GPIO_InitStructure.GPIO_Pin = TRIG_PIN;
    GPIO_InitStructure.GPIO_Mode = GPIO_Mode_OUT; // 输出模式
    GPIO_InitStructure.GPIO_OType = GPIO_OType_PP; // 推挽输出
    GPIO_InitStructure.GPIO_Speed = GPIO_Speed_100MHz;
    GPIO_InitStructure.GPIO_PuPd = GPIO_PuPd_NOPULL;
    GPIO_Init(TRIG_PORT, &GPIO_InitStructure);

    // 3. 配置ECHO引脚 (PE6) 为输入
    GPIO_InitStructure.GPIO_Pin = ECHO_PIN;
    GPIO_InitStructure.GPIO_Mode = GPIO_Mode_IN;  // 输入模式
    GPIO_InitStructure.GPIO_PuPd = GPIO_PuPd_NOPULL; // 浮空输入或下拉
    GPIO_Init(ECHO_PORT, &GPIO_InitStructure);

    // 4. 初始化引脚状态
    TRIG = 0; // 拉低触发引脚，准备工作
}

/**
 * @brief  获取HC_SR04测量的距离
 * @retval 成功返回距离(mm)，失败返回特定错误码(如-1.0, -2.0)
 */
float HC_SR04_GetDis(void)
{
    uint32_t t = 0;
    float distance = 0.0f;

    // --- 第一步：产生触发信号 ---
    // 1. 设置TRIG高电平
    TRIG = 1;
    // 2. 延时至少10us (这里给20us保险)
    delay_us(20);
    // 3. 拉低TRIG
    TRIG = 0;

    // --- 第二步：检测ECHO引脚状态 ---
    
    // 1. 等待ECHO变高 (模块发射信号)
    // 加入超时处理，防止硬件故障导致死循环
    t = 0;
    while (ECHO == 0)
    {
        t++;
        delay_us(1);
        if (t >= 1000000) return -1.0f; // 超时错误：未检测到响应
    }

    // 2. 测量ECHO高电平持续时间 (声波往返时间)
    t = 0;
    while (ECHO == 1)
    {
        // 核心算法：每9us计数一次
        // 原理：340m/s * 9us ≈ 3mm (声波传播距离)
        delay_us(9); 
        t++;
        
        if (t >= 1000000) return -2.0f; // 超时错误：回响信号过长(超出量程)
    }

    // --- 第三步：计算距离 ---
    // t代表有多少个"3mm"的声波行程
    // 距离 = (时间对应的声波路程) / 2
    // 路程 = t * 3mm
    distance = (float)t * 3.0f / 2.0f;

    return distance; // 返回单位：mm
}
```

#### 重点解析
1. **精度控制 (`delay_us(9)`)**：代码中没有使用定时器捕获，而是使用了简单的延时计数法选取 **9us** 是基于 $340m/s$ 声速计算得出的（$340m/s \times 9us \approx 3.06mm$），简化了后续的乘除法运算
2. **超时保护 (Timeout)**：在 `while` 循环中必须加入超时判断如果模块损坏或线缆断开，ECHO 引脚可能永远不翻转，没有超时保护会导致程序卡死在 `while` 循环中
3. **数据类型**：虽然计数值 `t` 是整数，但为了保持计算精度或后续滤波处理，返回值采用 `float` 类型
**关于超时处理（容错处理）的原因**：
4. **硬件问题**：引脚连接有问题、超声波模块的损坏
5. **软件问题**：延时不准确
