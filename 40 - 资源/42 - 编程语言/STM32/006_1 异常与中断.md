## 中断基本概念
### 中断含义
- 核心定义：
    中断是指 CPU 在正常执行程序的过程中，遇到了外部（如片外外设模块、按键、传感器）或内部（如片内外设、内核、定时器）的紧急事件需要处理，此时，CPU 必须暂时中止当前程序的执行，转而去为该紧急事件服务（即执行中断服务函数）。待服务完毕后，再自动返回到暂停处（称为“断点”）继续执行原来的程序
    
- **生活化场景**：
- ![](images/006_1%20异常与中断/file-20260113100259954.jpg)
    - **正常生活（主程序）**：学生（坤坤）正在教室里听讲师上课。这对应程序中的 `while(1)` 死循环，一直在执行主任务
    - **突发事件（中断请求）**：讲师的老大（温工）突然在窗外喊学生去打篮球。这对应外部信号的触发（如引脚电平变化，标志位 `flag` 变 1）
    - **处理事件（中断响应）**：学生听到喊声，暂停听课，离开教室去操场打球。这对应 CPU 跳转到中断服务函数去执行紧急任务
    - **恢复正常（中断返回）**：球打完了，学生回到教室座位上，继续听刚才没讲完的课。这对应 CPU 处理完中断后，返回断点继续执行
- 中断服务函数的原则：
    在“打篮球”（中断服务函数）期间，虽然干什么都可以，但有一个绝对原则：不能够干扰主程序的运行。
    1. 不能有复杂的运算（例如：复杂的浮点型逐算）
    2. 不能有大延时（死等）
        

### 事件的“偶然性”与“必然性”
- **偶然性**：我们无法预知用户什么时候会按下键盘、什么时候会移动鼠标，这些对 CPU 来说是完全随机的“偶然事件”。
- **必然性**：虽然事件发生是偶然的，但计算机系统设计时必须包含中断机制，为这些偶然事件提供一个**必然**的处理通道和机会。
   ![](images/006_1%20异常与中断/file-20260113100300259.jpg)
### 中断的作用
- **核心作用**：提高硬件的响应速度，能够及时处理突发情况 6。
- **智能门锁案例对比** ：
    - **场景**：门锁上有一个红外模块，用于检测是否有人靠近。
    - **方案一：无中断（轮询方式）**
        - **做法**：程序在 `while(1)` 里一直写 `if(HW == 1)` 来检查引脚电平。
        - **缺点**：CPU 必须一直醒着干活，效率极低，且如果人走得很快，轮询的一瞬间可能刚好没查到，导致漏检，响应慢。
    - **方案二：有中断（中断方式）**
        - **做法**：CPU 可以去处理别的事甚至休眠。一旦红外模块检测到人靠近，引脚发生电平跳变，硬件直接触发外部中断
        - **效果**：CPU 立即被唤醒，执行“唤醒屏幕”并播报“欢迎回家”的动作。**响应非常之快**
### 中断的优先级
事件具有不同的轻重缓急，系统必须保证最紧急的事件优先被处理，这就引出了**抢占优先级**和**响应优先级**的概念。

生活案例1：核酸检测排队
- **抢占式优先级**：**老师 vs 学生**。
    - 老师的优先级高于学生。如果学生正在做核酸，老师来了，老师可以“抢占”位置先做（当然现实中是插队，计算机里是嵌套）。这叫**抢占式优先级**。
- **响应式优先级**：**老师 vs 老师**。
    - 如果两个老师同时来，或者都在排队，他们之间不能互相打断，只能按照谁先排队（或谁资历更深）来决定顺序。这叫**响应式优先级**。
生活案例2：银行办理业务
这是一个非常经典的例子，用于理解“高响应”为什么不能打断“正在运行的低响应”。
- **场景设定**：
    - **小方**：VIP用户（高抢占），早上8:00已预约（高响应），但迟到了，8:20才到。
    - **小明**：VIP用户（高抢占），没有预约或预约晚（低响应），8:10开始办理业务，8:20正在办理中。
- 关键提问：
    当8:20小方到达时，能不能把正在办业务的小明赶下来，自己先办？
- 回答：
    不行！
- **解析**：
    1. **身份相同**：小方和小明都是 VIP，意味着他们的**抢占式优先级相同**（平级）。
    2. **先来后到**：虽然小方预约了（响应优先级更高），按理说排队时他排前面。但是，**小明已经在办理了**（任务已经在运行中）。
    3. **规则**：在抢占优先级相同的情况下，**高响应优先级无法打断正在运行的低响应优先级**,小方只能等小明办完。
        

### 优先级总结
1. **高抢占**可以打断**低抢占**：这是实现中断嵌套的唯一条件。执行完高抢占任务后，才会回到低抢占任务。
2. **低抢占**不可以打断**高抢占**。
3. **高响应**不可以打断**低响应**：前提是抢占优先级相同，且低响应已经在执行中。
4. **数值越小，优先级越高**：在 STM32 中，优先级序号 0 比 15 更高。
    
### 中断源与分类
- **中断源**：介于外部事件与 CPU 之间的电路模块，负责监测事件并产生信号。
- **中断请求信号**：由中断源产生的、能被单片机识别的电信号。
- **中断类型**：
    - **外部中断**：由单片机**外部**事件引发（如按键按下、传感器信号）。
    - **内部中断**：由单片机**内部**事件引发（如定时器计数到了、ADC 转换完成了）。

### 异常与中断
#### 定义
- **异常 (Exception)**：是指导致程序流程改变的事件统称。当异常发生时，处理器暂停当前任务，转而执行异常处理程序。
- **中断 (Interrupt)**：是异常的一种特定类型。通常由外设或外部输入产生，也可以由软件触发。中断服务程序被称为 **ISR** (Interrupt Service Routine)。
- **关系**：所有的中断都是异常，但异常不一定是中断（例如复位、硬件错误属于系统异常）
#### 异常编号体系
Cortex-M 内核对异常进行了统一编号管理：
- **1 - 15**：系统异常 (System Exceptions)。
    - **No.1 Reset (复位)**：优先级最高 (-3)。
    - **No.2 NMI (不可屏蔽中断)**：优先级 -2。
    - **No.3 HardFault (硬件错误)**：优先级 -1，处理所有未定义的错误。
    - **No.15 SysTick (系统滴答定时器)**：常用于操作系统的心跳。
- **16 及以上**：外部中断 (Interrupts)。
- **数量**：NVIC 设计上支持最多 240 个中断，但在实际 STM32 芯片设计中，为了平衡功耗和芯片面积，通常只实现 16 到 100 个中断。
#### 核心控制器：NVIC
**NVIC (嵌套向量中断控制器)** 是 Cortex-M 处理器内部的一个核心组件，它是中断系统的“大管家”
- **四大核心功能**：
    1. **灵活管理**：配置异常和中断的使能与失能。
    2. **支持嵌套**：允许高优先级中断打断低优先级中断。
    3. **向量化入口**：硬件自动定位中断服务函数地址，无需软件查找。
    4. **中断屏蔽**：可以快速屏蔽所有中断。

#### 向量表 (Vector Table)
- **定义**：向量表是一个存储在系统内存（Flash开始处）中的地址数组。
- **作用**：数组中的每一个元素都存储了一个异常处理函数的**起始地址**。当异常发生时，CPU 根据异常号查表，直接跳转到对应的地址执行代码
> [!tip]
> 这就是为什么我们在编写中断服务函数时，函数名必须和启动文件（`startup_stm32f40_41xxx.s`）中定义的一模一样，否则 CPU 查表时找不到入口。

![](images/006_1%20异常与中断/file-20260113100259639.jpg)
#### 中断控制流程
系统复位后，默认所有中断都是禁用的。要使用一个中断，必须完成以下三步：
1. **设置优先级**（可选，不设置则使用默认）。
2. **外设层面使能**：开启外设产生中断信号的能力（例如配置 EXTI 寄存器）。
3. **内核层面使能**：在 NVIC 中开启该中断通道。

### 外部中断说明

STM32F407 等芯片虽然有 100 多个 GPIO 引脚，但只有 **16 个外部中断/事件线 (EXTI0 - EXTI15)**。如何分配呢？
- **多路分选器 (SYSCFG)**：STM32 内部使用 SYSCFG 模块作为选择器。
- **映射规则**：所有 GPIO 端口的**同号引脚**共用一条 EXTI 线。
    - `PA0`, `PB0`, `PC0` ... `PI0` -> 连接到多路选择器 -> 输出给 **EXTI0**。
    - `PA1`, `PB1`, `PC1` ... `PI1` -> 连接到多路选择器 -> 输出给 **EXTI1**。
- **排他性结论**：在同一时刻，你只能选择 PA0 或者 PB0 作为外部中断0的输入源，**不能同时使用**。
    ![](images/006_1%20异常与中断/file-20260113100259716.jpg)

### 标准库代码开发步骤
#### 详细配置步骤
1. **使能 GPIO 时钟**：使用 `RCC_AHB1PeriphClockCmd`。
2. **使能 SYSCFG 时钟**：使用 `RCC_APB2PeriphClockCmd`。
    - **特别注意**：这是初学者最容易遗漏的一步，如果不开启 SYSCFG 时钟，外部中断映射将无法工作
3. **配置 GPIO 工作模式**：使用 `GPIO_Init` 将引脚初始化为**输入模式**（上拉/下拉/浮空）
4. **配置中断线映射**：使用 `SYSCFG_EXTILineConfig` 将具体的 GPIO 引脚连接到 EXTI 线
5. **配置 EXTI 初始化**：使用 `EXTI_Init`。
    - 设置模式为中断模式 (Interrupt)
    - 设置触发边沿（上升沿/下降沿/双边沿）。
    - 使能该中断线
6. **配置优先级分组**：使用 `NVIC_PriorityGroupConfig`
    - 通常在 `main` 函数的最开头配置一次即可，全工程通用。
7. **配置 NVIC 初始化**：使用 `NVIC_Init`
    - 指定中断通道（如 `EXTI0_IRQn`）
    - 设置抢占优先级。
    - 设置响应优先级。
    - 使能该通道。
8. **编写中断服务函数**：在 `stm32f4xx_it.c` 或其他位置编写 ISR，处理具体逻辑

### 关键函数接口与代码原型

以下是标准库中用于中断开发的核心函数原型，掌握这些即可灵活开发
#### 引脚映射函数
```
// 选择用作 EXTI 线的 GPIO 引脚
// 参数1: 端口 (如 EXTI_PortSourceGPIOA)
// 参数2: 引脚源 (如 EXTI_PinSource0)
void SYSCFG_EXTILineConfig(uint8_t EXTI_PortSourceGPIOx, uint8_t EXTI_PinSourcex);
```
#### 外部中断初始化函数

```
// 根据结构体参数初始化 EXTI 外设
void EXTI_Init(EXTI_InitTypeDef* EXTI_InitStruct);
```
#### 中断控制器初始化函数
```
// 初始化 NVIC，配置优先级和通道使能
void NVIC_Init(NVIC_InitTypeDef* NVIC_InitStruct);
```

#### 状态检查与清除函数（ISR专用）
```
// 检查指定 EXTI 线的中断标志位状态 (返回 SET 或 RESET)
ITStatus EXTI_GetITStatus(uint32_t EXTI_Line);

// 清除指定 EXTI 线的挂起标志位 (必须调用)
void EXTI_ClearITPendingBit(uint32_t EXTI_Line);
```
#### 中断服务函数标准写法
```
// 函数名必须查阅启动文件，不可自定义
void EXTI0_IRQHandler(void)
{
    // 1. 检查标志位，确认是否是 EXTI0 触发的中断
    if(EXTI_GetITStatus(EXTI_Line0) == SET)
    {
        // 2. 执行硬件控制逻辑
        PFout(9) = 0;  // 例如：点亮 LED
        
        PFout(9) = 1;  // 例如：熄灭 LED

        // 3. 清除挂起标志位 (至关重要)
        // 如果不清除，CPU 会认为当前中断未处理完，退出后会立即再次进入中断，导致主程序卡死
        EXTI_ClearITPendingBit(EXTI_Line0);
    }
}
```

> [!tip]
> **中断服务函数的名称是固定的，不可随意自定义** 函数名必须与启动文件（`startup_stm32f40_41xxx.s`）向量表中预定义的名称严格匹配
> 具体对应关系取决于初始化时使用的中断线：例如配置为 `EXTI_Line0` 时，可在启动文件中搜索关键字 "Line0"，找到对应的中断入口函数名为 `EXTI0_IRQHandler`

### 中断优先级
#### 优先级分组表
STM32 将优先级寄存器分为 5 组 (Group 0-4)，每组定义了**抢占优先级**和**响应优先级**所占的位宽。

| **分组参数**                 | **抢占优先级位宽**   | **响应优先级位宽**   | **特点描述**           |
| ------------------------ | ------------- | ------------- | ------------------ |
| **NVIC_PriorityGroup_0** | 0 位 (无抢占)     | 4 位 (0-15)    | 无嵌套功能，所有中断按响应排队    |
| **NVIC_PriorityGroup_1** | 1 位 (0-1)     | 3 位 (0-7)     | 支持 2 级嵌套           |
| **NVIC_PriorityGroup_2** | **2 位 (0-3)** | **2 位 (0-3)** | **最常用配置，平衡了抢占和响应** |
| **NVIC_PriorityGroup_3** | 3 位 (0-7)     | 1 位 (0-1)     | 支持 8 级嵌套           |
| **NVIC_PriorityGroup_4** | 4 位 (0-15)    | 0 位 (无响应)     | 强嵌套模式，无响应级区分       |

#### 优先级判定三大法则
在 STM32 中，优先级数值**越小**，代表优先级**越高**。判断顺序遵循以下三条法则：
1. **抢占优先法则（决定能否插队）**
    - **规则**：高抢占优先级的中断可以打断正在执行的低抢占优先级中断。
    - **结果**：这是实现**中断嵌套**的唯一条件。
2. **响应排队法则（决定排队顺序）**
    - **规则**：当**抢占优先级相同**时，高响应优先级的中断**不可以**打断低响应优先级的中断。
    - **结果**：高响应优先级只能等待前者执行完毕。但如果两个中断**同时**发生，高响应优先级的会先执行。
3. **硬件保底法则**
    - **规则**：当抢占优先级和响应优先级都完全相同时。
    - **结果**：按照硬件向量表中的固定地址顺序执行（地址越低越优先）。例如 `EXTI0` 的硬件编号比 `EXTI1` 靠前，则 `EXTI0` 先执行。

### 应用场景与实验任务
#### 现实应用场景
1. **人机交互**：
    - 触摸屏点击响应、手机电源键锁屏、音量键调节。这些操作要求系统必须实时反馈，不能有迟钝，因此必须使用中断。
2. **模块状态检测（蓝牙案例）**：
    - **背景**：蓝牙模块通常有一个 `STATE` 引脚，连接成功输出高电平，断开输出低电平。
    - **实现**：将单片机的引脚（如 PA8）连接到蓝牙 `STATE`，配置为**外部中断输入**（上升/下降沿触发）。
    - **优势**：无需主程序死循环查询蓝牙状态，一旦连接状态改变，自动触发中断处理，极大节省 CPU 资源。
