在嵌入式系统开发中，时间的准确性是许多应用场景（如数据日志记录、定时任务触发等）的基石。STM32 的实时时钟（RTC）模块作为一个高度集成的独立定时器/计数器，为开发者提供了强大的日历和闹钟功能。本篇笔记将深入探讨 STM32 RTC 的核心机制、配置要点及其实战应用

---

## 一、RTC 的概述
**RTC（Real Time Clock）** 即实时时钟 。在 STM32 中，它不仅是一个简单的计数器，更是一个独立的 **BCD（Binary-Coded Decimal）** 定时器/计数器 。这意味着它内部以二进制编码的十进制格式存储时间信息 。
RTC 的核心功能包括：
- **日历与时间**：提供秒、分钟、小时、星期、日期、月份和年份信息。它能够自动处理月份天数（28、29、30、31 天），并支持 **闰年补偿** 及 **夏令时补偿** 。
* **闹钟与唤醒**：内置两个可编程闹钟（闹钟 A 和闹钟 B） ，并具备周期性可编程唤醒标志，其作用类似于外设定时器的时间更新中断 。
* **低功耗管理**：RTC 包含自动唤醒单元，即使在器件处于低功耗模式或复位状态下，只要电源电压正常，RTC 就会持续运行 。
* **精度校准**：通过数字校准功能，开发者可以对晶振精度的偏差进行微调补偿 。
![](images/007_%20RTC时钟/file-20260113095816156.jpg)

为了防止误操作，上电复位后所有的 RTC 寄存器都会受到写保护，必须通过特定的序列才能解锁访问 。

## 二、中断配置注意事项

根据《STM32F4xx 中文参考手册》
- RTC 的所有中断都通过 **EXTI 控制器** 进行管理。这一设计允许 RTC 在低功耗模式下通过 EXTI 线唤醒内
* **闹钟中断使能顺序**：
	1. 配置 **EXTI 线 17** 为上升沿触发的中断模式并使能
	2. 在 NVIC 中配置并使能 **RTC_Alarm IRQ** 通道
	3. 最后在 RTC 模块内配置具体的闹钟事件（A 或 B）
* **唤醒中断使能顺序**：
	1. 配置 **EXTI 线 22** 为上升沿触发的中断模式并使能
	2. 在 NVIC 中配置并使能 **RTC_WKUP IRQ** 通道
	3. 配置 RTC 生成唤醒定时器事件

## 程序设计

STM32 的 RTC 模块位于备份域中，其程序设计不仅涉及外设本身的配置，还需处理电源管理与时钟源的可靠性
### RTC 的初始化流程
在进行 RTC 配置前，首要任务是解锁对备份域的访问限制。由于系统上电复位后 RTC 寄存器处于写保护状态以防止非正常访问，必须先使能电源时钟（PWR Clock），随后调用 `PWR_BackupAccessCmd(ENABLE)` 函数来允许对 RTC 寄存器的访问
初始化代码的核心在于时钟源的选择。在理想情况下，我们优先选择 **LSE（外部低速时钟，32.768kHz）** 以获得高精度。然而，考虑到硬件设计的复杂性，代码中通常加入检测机制：若 LSE 无法稳定工作，则自动切换至 **LSI（内部低速时钟，约 32kHz）** 作为备选方案
```c
RTC_InitTypeDef  RTC_InitStructure;
RTC_DateTypeDef RTC_DateStructure;
RTC_TimeTypeDef RTC_TimeStructure;

void rtc_init(void) {
    /* 1. 使能电源时钟并允许访问备份域 */
    RCC_APB1PeriphClockCmd(RCC_APB1Periph_PWR, ENABLE); 
    PWR_BackupAccessCmd(ENABLE); 
    
    /* 2. 时钟源配置逻辑：尝试 LSE，不成功则切换至 LSI */
#if 0 // 假设优先使用 LSE
    RCC_LSEConfig(RCC_LSE_ON); 
    while(RCC_GetFlagStatus(RCC_FLAG_LSERDY) == RESET); 
    RCC_RTCCLKConfig(RCC_RTCCLKSource_LSE); 
#else 
    RCC_LSICmd(ENABLE); 
    while(RCC_GetFlagStatus(RCC_FLAG_LSIRDY) == RESET); 
    RCC_RTCCLKConfig(RCC_RTCCLKSource_LSI); 
#endif

    /* 3. 使能 RTC 并等待影子寄存器同步 */
    RCC_RTCCLKCmd(ENABLE); 
    RTC_WaitForSynchro();

    /* 4. 分频配置以获得 1Hz 的日历时钟 */
    // 公式：ck_spre = RTCCLK / (AsynchPrediv + 1) / (SynchPrediv + 1) 
#if 0 // 针对 LSE (32768Hz)
    RTC_InitStructure.RTC_AsynchPrediv = 0x7F; // 128分频
    RTC_InitStructure.RTC_SynchPrediv = 0xFF;  // 256分频
#else // 针对 LSI (~32KHz)
    RTC_InitStructure.RTC_AsynchPrediv = 0x7F;
    RTC_InitStructure.RTC_SynchPrediv = 0xF9;  // 针对 LSI 的偏差进行微调
#endif
    RTC_InitStructure.RTC_HourFormat = RTC_HourFormat_24; 
    RTC_Init(&RTC_InitStructure);

    /* 5. 初始日期与时间设置（BCD格式） */
    RTC_DateStructure.RTC_Year = 0x17; 
    RTC_DateStructure.RTC_Month = RTC_Month_November;
    RTC_DateStructure.RTC_Date = 0x29;
    RTC_DateStructure.RTC_WeekDay = RTC_Weekday_Wednesday;
    RTC_SetDate(RTC_Format_BCD, &RTC_DateStructure);

    RTC_TimeStructure.RTC_H12     = RTC_H12_PM;
    RTC_TimeStructure.RTC_Hours   = 0x14;
    RTC_TimeStructure.RTC_Minutes = 0x56;
    RTC_TimeStructure.RTC_Seconds = 0x55;
    RTC_SetTime(RTC_Format_BCD, &RTC_TimeStructure);
    
    /* 6. 唤醒中断与 EXTI 线 22 的链路配置 */
    RTC_WakeUpCmd(DISABLE); 
    RTC_WakeUpClockConfig(RTC_WakeUpClock_CK_SPRE_16bits);
    RTC_SetWakeUpCounter(1-1); // 设置自动重载计数值
    RTC_ClearITPendingBit(RTC_IT_WUT); 
    RTC_ITConfig(RTC_IT_WUT, ENABLE); 
    RTC_WakeUpCmd(ENABLE);

    // 映射 EXTI 外部中断线 22
    EXTI_InitStructure.EXTI_Line = EXTI_Line22;
    EXTI_InitStructure.EXTI_Mode = EXTI_Mode_Interrupt;
    EXTI_InitStructure.EXTI_Trigger = EXTI_Trigger_Rising;
    EXTI_InitStructure.EXTI_LineCmd = ENABLE;
    EXTI_Init(&EXTI_InitStructure);
    
    // NVIC 通道使能
    NVIC_InitStructure.NVIC_IRQChannel = RTC_WKUP_IRQn;
    NVIC_InitStructure.NVIC_IRQChannelPreemptionPriority = 0x03; 
    NVIC_InitStructure.NVIC_IRQChannelSubPriority = 0x03;
    NVIC_InitStructure.NVIC_IRQChannelCmd = ENABLE;
    NVIC_Init(&NVIC_InitStructure);
}
```

### 重载值寄存器 (RTC_WUTR)
![](images/007_%20RTC时钟/file-20260113095816284.jpg)
RTC 唤醒定时器寄存器（RTC_WUTR）决定了周期性唤醒事件的频率。该寄存器包含一个 16 位的自动重载值位段 `WUT[15:0]`
当唤醒定时器被使能时，每经过 $(WUT[15:0] + 1)$ 个 `ck_wut` 时钟周期，硬件就会将唤醒标志位（WUTF）置 1 并触发中断 9。这种“$N+1$”的计数逻辑在配置时需要特别注意。通过 `RTC_CR` 寄存器中的 `WUCKSEL` 位，开发者可以灵活选择时钟源（如分频后的 RTCCLK 或 1Hz 的 `ck_spre`），从而实现从毫秒级到天级的精准唤醒
### RTC 起振
在硬件层面，STM32 的 RTC 对外部晶振的要求极为严苛。网络上常有关于 LSE 难以起振的吐槽，这主要是因为 STM32 内部 RTC 振荡电路是针对 **6pF** 低负载电容晶振设计的

目前市面上主流晶振多为 **12.5pF**，若直接焊接使用，往往会导致起振失败或频率大幅偏移。许多开发者反馈，这种不地道的电路设计增加了采购成本和调试难度。在试样或小批量产阶段，若无法订购到精准匹配的晶振，建议程序内保留检测逻辑，在 LSE 故障时自动切换至 **LSI**，并结合联网校时功能来弥补 LSI 精度不足的问题
### RTC 的唤醒中断服务函数

当唤醒事件发生时，系统进入 `RTC_WKUP_IRQHandler`。在该函数中，必须首先通过 `RTC_GetITStatus` 验证中断源是否为唤醒事件（WUT）。处理完业务逻辑后，需要同步清除 RTC 内部标志位及 EXTI 外部中断线的挂起位，否则系统将陷入死循环反复进入中断
```c
void RTC_WKUP_IRQHandler(void) {
    if(RTC_GetITStatus(RTC_IT_WUT) != RESET) { 
        printf("RTC_WKUP_IRQHandler triggered.\r\n"); 
        
        // 关键步骤：清除中断标志
        RTC_ClearITPendingBit(RTC_IT_WUT); 
        EXTI_ClearITPendingBit(EXTI_Line22); 
    } 
}
```

### 获取时间与日期
在读取 RTC 数据时，为了保证数据的一致性，建议在一次读取操作中同时调用获取时间和日期的函数。由于影子寄存器的存在，读取时间后日期会被锁定，确保两者匹配
```c
// 以 BCD 格式获取并展示当前状态 
RTC_GetTime(RTC_Format_BCD, &RTC_TimeStructure); 
printf("Time %02x:%02x:%02x\r\n",
    RTC_TimeStructure.RTC_Hours,
    RTC_TimeStructure.RTC_Minutes,
    RTC_TimeStructure.RTC_Seconds);

RTC_GetDate(RTC_Format_BCD, &RTC_DateStructure);
printf("Date 20%02x/%02x/%02x Week:%x\r\n",
    RTC_DateStructure.RTC_Year,
    RTC_DateStructure.RTC_Month,
    RTC_DateStructure.RTC_Date,
    RTC_DateStructure.RTC_WeekDay);
```

## BCD 码和 BIN 码
**BCD 码**，即二进制编码的十进制数，其核心思想是利用 **4 位二进制码** 来精确代表十进制中的一个数符（0 到 9）。在 4 位二进制所拥有的 16 种组合中，BCD 码仅选取前 10 种（0000 至 1001）来对应十进制数，这种设计最直接的优势在于简化了数字显示逻辑，使得每一位十进制数都能独立映射到硬件寄存器或显示译码器中。

目前最常用的形式是 **8421BCD 码**，其中的 8、4、2、1 分别代表了 4 位二进制数从高到低的位权值 4。如下表所示，这种对应关系让十进制与二进制之间的“位对位”转换变得极其直观：

|**十进制数**|**8421BCD 编码**|
|---|---|
|0|0000|
|1|0001|
|2|0010|
|3|0011|
|4|0100|
|5|0101|
|6|0110|
|7|0111|
|8|1000|
|9|1001|
### BCD 码设置
当选择以 BCD 码设置 RTC 时钟时，其本质是将十进制数的每一位“拆分”后进行重组编码。例如，十进制数字 **10** 在 BCD 格式下被表示为 `0001 0000`（即十位的 1 和个位的 0 分别编码），而数字 **15** 则表示为 `0001 0101`
在 STM32 具体的寄存器操作中，这意味着我们需要将转换后的 BCD 值分别填入 RTC 相关寄存器的对应位段。以设置小时为 10 为例，程序会将 `0001 0000` 写入 `RTC_HOUR` 寄存器。这种方式虽然在数值计算上不如纯二进制高效，但在观察寄存器状态（如通过调试器查看十六进制值）时，`0x10` 恰好代表 10 点，极大地方便了开发者肉眼查错。

### BIN 码
与 BCD 码不同，**BIN 码（普通二进制）** 直接使用计算机最原始的二进制数值表示法。在这种格式下，十进制数字 **10** 的表示方式是其纯粹的二进制形式 `0000 1010`（即十六进制的 `0x0A`）
在 STM32 中使用 BIN 码时，开发者无需关注十进制位与位之间的拆分，直接将计算好的二进制数值写入寄存器即可。例如，要设置小时为 10，直接向 `RTC_HOUR` 寄存器对应位写入 `0000 1010` 。对于需要进行频繁加减运算（如计算时间差）的场景，BIN 码由于符合 C 语言标准的运算逻辑，应用更为广泛。
### 示例代码
在实际开发中，具体使用哪种编码取决于应用需求及所选用的库函数 。STM32 的库函数通常提供参数项（如 `RTC_Format_BIN` 或 `RTC_Format_BCD`）供开发者切换。以下是使用 **BIN 码格式** 进行日期与时间配置及获取的典型流程：
```c
/* 设置日期: 2024/04/03 Wednesday (星期三) */
RTC_DateStructure.RTC_Year = 24;                 // 2024年 [cite: 161]
RTC_DateStructure.RTC_Month = RTC_Month_April;   // 4月 [cite: 162]
RTC_DateStructure.RTC_Date = 03;                 // 3日 [cite: 163]
RTC_DateStructure.RTC_WeekDay = RTC_Weekday_Wednesday; // 星期三 
RTC_SetDate(RTC_Format_BIN, &RTC_DateStructure); // 使用BIN格式写入 

/* 设置时间：14h 42mn 55s PM (下午2点42分55秒) */
RTC_TimeStructure.RTC_H12     = RTC_H12_PM;      // 下午制式
RTC_TimeStructure.RTC_Hours   = 14;              // 14点 
RTC_TimeStructure.RTC_Minutes = 42;              // 42分 
RTC_TimeStructure.RTC_Seconds = 55;              // 55秒
RTC_SetTime(RTC_Format_BIN, &RTC_TimeStructure); // 使用BIN格式写入 

// 获取并打印当前时间
RTC_GetTime(RTC_Format_BIN, &RTC_TimeStructure);
printf("Time %02d:%02d:%02d\r\n", 
    RTC_TimeStructure.RTC_Hours, 
    RTC_TimeStructure.RTC_Minutes, 
    RTC_TimeStructure.RTC_Seconds);             

// 获取并打印当前日期
RTC_GetDate(RTC_Format_BIN, &RTC_DateStructure); 
printf("Date 20%02d/%02d/%02d Week:%d\r\n", 
    RTC_DateStructure.RTC_Year, 
    RTC_DateStructure.RTC_Month, 
    RTC_DateStructure.RTC_Date, 
    RTC_DateStructure.RTC_WeekDay);             
```

> [!tip]
> 开发者需根据函数定义的参数类型来确定编码。如果库函数要求 BCD 格式却传入了 BIN 数值，会导致 RTC 寄存器识别出非法的时间参数（例如在 BCD 下读取到 `0x0A` 会造成逻辑混乱），因此在调用相关 API 时检查格式参数是确保 RTC 稳定运行的关键步骤

## 拓展：闹钟代码

配置闹钟时，一个重要的实战技巧是：在修改配置前必须 **先关闭闹钟** 。如果不先关闭 `RTC_Alarm_A`，可能会触发逻辑漏洞（BUG），导致无论如何配置，只要秒钟到“00”就会产生中断 。

**闹钟掩码（RTC_AlarmMask）** 提供了极大的灵活性 ：

* 
**RTC_AlarmMask_DateWeekDay**：屏蔽日期，实现 **每天** 的固定时间响铃 。


* 
**RTC_AlarmMask_None**：匹配所有字段，可实现 **指定某月某日** 的精确提醒 。


* 此外，通过 `RTC_AlarmDateWeekDaySel` 还可以灵活切换匹配“日期”还是“星期几” 。

在 STM32 的 RTC 模块中，闹钟功能是最具实用性的扩展特性之一，它不仅能实现精确定时触发，还能在低功耗模式下唤醒内核，是构建智能硬件任务调度的核心 1111。以下是对闹钟功能的深度解析与程序设计指南。

### 七、拓展-闹钟代码

#### (1) 闹钟初始化
闹钟的初始化本质上是打通“RTC外设 -> EXTI控制器 -> NVIC中断向量表”这一链路的过程。在初始化函数 `rtc_alarm_init` 中，我们首先需要使能 RTC 的闹钟 A 中断（RTC_IT_ALRA），并确保清除任何残留的挂起标志位，以防止初始化后立即触发意外中断
特别需要注意的是，闹钟中断是与 **EXTI 控制器线 17** 紧密相连的
这种设计允许闹钟事件产生一个边沿信号来触发系统中断，因此必须将 EXTI 线 17 配置为上升沿触发的中断模式。最后，在 NVIC 中配置 `RTC_Alarm_IRQn` 的优先级，以确保内核能够及时响应闹钟事件
```c
void rtc_alarm_init(void)
{
    /* 1. 允许 RTC 的 A 闹钟触发中断并清空标志位*/
    RTC_ITConfig(RTC_IT_ALRA, ENABLE);
    RTC_ClearFlag(RTC_FLAG_ALRAF);

    /* 2. 使能外部中断控制线 17 的中断*/
    EXTI_ClearITPendingBit(EXTI_Line17);
    EXTI_InitStructure.EXTI_Line = EXTI_Line17;
    EXTI_InitStructure.EXTI_Mode = EXTI_Mode_Interrupt;
    EXTI_InitStructure.EXTI_Trigger = EXTI_Trigger_Rising;
    EXTI_InitStructure.EXTI_LineCmd = ENABLE;
    EXTI_Init(&EXTI_InitStructure);
    
    /* 3. 在 NVIC 中使能闹钟中断通道  */
    NVIC_InitStructure.NVIC_IRQChannel = RTC_Alarm_IRQn;
    NVIC_InitStructure.NVIC_IRQChannelPreemptionPriority = 0;
    NVIC_InitStructure.NVIC_IRQChannelSubPriority = 0;
    NVIC_InitStructure.NVIC_IRQChannelCmd = ENABLE;
    NVIC_Init(&NVIC_InitStructure);
}
```

#### (2) 设定闹钟的时间

在调用 `rtc_alarm_set` 设定具体时间时，存在一个关键的硬件细节：**在配置之前必须先关闭闹钟**。
如果直接在闹钟运行状态下修改寄存器，底层逻辑可能会触发一个常见的“00秒 BUG”，导致无论你如何配置参数，系统只要运行到每分钟的 00 秒就会产生一次误触发中断
STM32 的 RTC 提供两个独立的闹钟（闹钟 A 和闹钟 B），开发者可以根据需要分别配置 。在设置完成后，重新调用 `RTC_AlarmCmd(ENABLE)` 激活闹钟工作
```c
void rtc_alarm_set(RTC_AlarmTypeDef RTC_AlarmStructure)
{
    /* 配置前必须关闭闹钟以规避“每分钟00秒触发”的硬件BUG */
    RTC_AlarmCmd(RTC_Alarm_A, DISABLE);
    
    /* 写入闹钟时间与掩码配置 */
    RTC_SetAlarm(RTC_Format_BCD, RTC_Alarm_A, &RTC_AlarmStructure);
    
    /* 激活闹钟 A  */
    RTC_AlarmCmd(RTC_Alarm_A, ENABLE);
}
```

##### 应用示例：

通过调整结构体中的参数，我们可以轻松实现多种闹钟模式：
- **每天固定时间生效**：将掩码设置为 `RTC_AlarmMask_DateWeekDay`，这意味着日期和星期字段将被忽略，闹钟仅匹配时、分、秒，从而实现每日循环提醒
- **每月指定日期生效**：例如设定在每月 20 号生效，需指定 `RTC_AlarmDateWeekDaySel_Date` 并将日期设为 `0x20`，同时将掩码设为 `None`
- **每周指定星期生效**：例如设定在每周三生效，需选择 `RTC_AlarmDateWeekDaySel_WeekDay` 并指定 `RTC_Weekday_Wednesday`
#### 闹钟相关参数分析
深入理解 `RTC_AlarmTypeDef` 结构体的成员，是实现精准计时的前提：
1. **RTC_AlarmTime**：此成员配置的是一个时间初始化结构体。它决定了闹钟触发的绝对时刻，包括选择 12 小时制（需配合 AM/PM 标志）还是 24 小时制，并填入具体的时、分、秒数值
2. **RTC_AlarmMask（闹钟掩码）**：这是决定闹钟重复频率的关键。通过选择哪些字段“无效（Masked）”，我们可以控制匹配的精度：
    - `RTC_AlarmMask_None`：最高精度，时、分、秒、日期全匹配。
    - `RTC_AlarmMask_DateWeekDay`：日期/星期无效，实现每天在该时刻准时响铃
    - 还可以分别屏蔽 `Hours`、`Minutes` 或 `Seconds`，甚至选择 `RTC_AlarmMask_All` 使闹钟在每一个日历更新周期都触发
3. **RTC_AlarmDateWeekDaySel**：用于决定闹钟匹配的是“日期”还是“星期”。需要强调的是，如果要让这一步配置生效，`RTC_AlarmMask` 绝不能配置为 `RTC_AlarmMask_DateWeekDay`，否则该字段会被硬件逻辑直接忽略
4. **RTC_AlarmDateWeekDay**：具体的日期（1~31）或星期（1~7，对应星期一至星期日）

## 备份寄存器
### 概述
根据《STM32F4xx 中文参考手册》第 582 页的定义，备份寄存器是一组位于备份域中的 **32 位寄存器**，总计 20 个，可为用户提供 **80 字节** 的数据存储空间。这些寄存器并非通用的 RAM，其最显著的特性在于其电源独立性：当主电源 $V_{DD}$ 关闭时，只要通过 $V_{BAT}$ 引脚连接了外部电池（如纽扣电池），备份寄存器就能通过纽扣电池维持上电状态，确保内部数据不丢失
备份寄存器的稳定性极高，它具有以下关键属性：
- **抗复位能力**：这些寄存器不会在系统复位或电源复位时被重置，甚至在器件从待机模式（Standby）唤醒时，内部数据依然保持原样
- **低功耗有效**：在各种低功耗模式下，备份寄存器始终处于激活状态

在实际开发中，备份寄存器最经典的应用场景是 **防止 RTC 时间被重复初始化**。由于 RTC 的初始化代码通常会设定一个固定的初始日期（如 2017/11/29），如果不加判断地每次复位都运行初始化，系统时间将永远停留在“过去”。为了解决这一痛点，我们可以采用以下逻辑步骤：

1. **初次设置标志**：在系统首次运行并成功设置 RTC 时间后，随即向备份寄存器的某个位置（如 `RTC_BKP_DR0`）写入一个预设的“魔术数”（Magic Number，例如 `0x5678`）
2. **启动自检逻辑**：在下一次系统复位启动时，程序首先读取该备份寄存器的值。通过判断该值是否与之前的“魔术数”一致，来决定是否需要重新设置日期和时间。如果一致，则仅需执行基础的时钟、电源和中断初始化，从而跳过重置时间的步骤，维持计时的连续性
此外，备份寄存器还具备一定的硬件安全特性。**PC13 引脚** 可以被配置为 **入侵检测（Tamper Detection）** 功能。一旦系统检测到入侵事件（如设备外壳被拆开导致电平变化），硬件会自动复位所有备份寄存器的值，从而有效保护存储在其中的敏感数据（如加密临时密码）

### 函数接口
在代码实现层面，开发者可以通过标准外设库提供的简洁接口来操作这块存储区域，无需手动计算底层地址。
1. 写备份寄存器函数
该函数用于将特定的 32 位数据写入指定的备份寄存器位置。常用于建立重启标志位，以此判断系统是否需要重新校准 RTC 7。
```c
// 示例：在备份寄存器 DR0 中写入 0x5678 作为时间已初始化的标记
RTC_WriteBackupRegister(RTC_BKP_DR0, 0x5678);
```

2. 读备份寄存器函数
该函数用于获取存储在备份寄存器中的数据，返回值通常作为逻辑判断的条件
```c
// 示例：读取 DR0 中的值并与预设值比对
int rt = RTC_ReadBackupRegister(RTC_BKP_DR0);
if(rt == 0x5678) {
    // 说明 RTC 已经在运行中，无需改写日期时间
}
```
