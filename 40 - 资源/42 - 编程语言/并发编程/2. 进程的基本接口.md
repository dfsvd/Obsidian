## 进程的创建

在 Linux/Unix 系统中，`fork()` 是用于创建新进程的**核心系统调用**，其基本工作模式就是“**细胞分裂**”：一个已存在的进程（父进程）调用 `fork()`，系统会**完整地复制**这个父进程，创造出一个几乎一模一样的子进程。

### `fork()` - 复制进程

- **函数原型**

  ```c
  #include <sys/types.h>
  #include <unistd.h>
  
  pid_t fork(void);
  ```

- 作用

  fork() 最关键的特点是：“调用一次，返回两次”

  1. 当父进程调用 `fork()` 时，内核会创建一个新的子进程。
  2. 这个子进程会**复制**父进程的**所有**资源，包括：
     - 整个内存空间（代码、数据、堆、栈）
     - 环境变量
     - 打开的文件描述符
  3. 调用完成后，父进程和子进程都会从 `fork()` **函数返回之后的下一行代码**开始，**并发执行**
  4. 系统调度器决定接下来先运行父进程还是子进程，它们之间**没有固定的先后顺序**

- **参数详解**

  - `(void)`：此函数不需要任何参数。

- 返回值

  fork() 函数会返回两次，父子进程会得到不同的返回值，这是区分它们的唯一方法：

  - **在父进程中**：返回新创建**子进程的 PID**（一个大于 0 的整数）。
  - **在子进程中**：返回 **0**。
  - **如果出错**：在父进程中返回 **-1**（例如系统进程数已达上限），并且不会创建子进程。

### `getpid()` - 获取当前进程 ID

- **函数原型**

  ```c
  #include <sys/types.h>
  #include <unistd.h>
  
  pid_t getpid(void);
  ```

- **作用** 获取**调用这个函数**的进程的**进程 ID (PID)**。 简单说，就是“我是谁？”

- **参数详解**

  - `(void)`：不需要参数

- **返回值**

  - 返回调用进程的 PID。这个函数总是成功的

### `getppid()` - 获取父进程 ID

- **函数原型**

```c
#include <sys/types.h> 
#include <unistd.h>
pid_t getppid(void);
```

- **作用** 获取**调用这个函数**的进程的**父进程 ID (PPID)**。 简单说，就是“我爸是谁？”。 *（在 `fork()` 后的子进程中调用它，返回的就是父进程的 PID。）*
- **参数详解**
  - `(void)`：不需要参数。
- **返回值**
  - 返回调用进程的父进程的 PID。
  - 如果一个进程的父进程死了，它会变成“孤儿进程”，系统会自动把它“过继”给 1 号进程 `init` 或 `systemd`，这时 `getppid()` 就会返回 1

- **示例代码**

  ```c
  #include <stdio.h>
  #include <sys/types.h>
  #include <unistd.h>
  int main(){
      printf("fork之前\n");
  
      pid_t pid = fork();
  
      printf("[%d]:pid=%d\n",getpid(),pid);
      return 0;
  }
  ```

- **执行流拆解**

  1. 一个进程（假设是你的 `bash` 终端）启动了 `a.out` 程序。此时只有一个进程在执行 `main` 函数。
  2. `printf("[fork之前]\n");`
     - 这行代码只会被**父进程**（也就是最初的 `a.out` 进程）执行**一次**。
  3. `pid_t pid = fork();`
     - 这是**分裂点**。父进程（假设 PID 为 5140）调用 `fork`。
     - 内核复制出一个子进程（假设 PID 为 5141）。
  4. `printf("[%d]: pid=%d\n", getpid(), pid);`
     - **现在有两个进程**（PID 5140 和 PID 5141）都会执行这一行。
     - **在父进程 (5140) 中：**
       - `fork()` 的返回值是子进程的 PID，所以 `pid` 变量 = 5141。
       - `getpid()` 函数获取的是“当前”进程的 ID，所以 `getpid()` = 5140。
       - **父进程打印：`[5140]: pid=5141`**
     - **在子进程 (5141) 中：**
       - `fork()` 的返回值是 0，所以 `pid` 变量 = 0。
       - `getpid()` 函数获取的是“当前”进程的 ID，所以 `getpid()` = 5141。
       - **子进程打印：`[5141]: pid=0`**

- **结果分析与进程树**

  - `getpid()` 总是返回**调用者自己**的 PID。
  - `pid` 变量存的是 `fork()` 的**返回值**。
  - 我们通过检查 `pid` 是否为 0，就能在代码中写出 `if (pid == 0)` 这样的分支，让父子进程去做**不同的**事情。
  - 进程关系是：`bash` (启动者) -> `a.out` (父进程, 5140) -> `a.out` (子进程, 5141)。
  - 当父子进程都执行完 `printf` 并退出后，它们都会被系统回收，控制权最终返回给 `bash`，`bash` 打印出新的命令行提示符

## 进程的回收

`fork()` 只是“生”，有“生”就有“死”，有“死”就得有人“收尸”。如果不“收尸”，子进程死了就会变成“僵尸进程”(Zombie)，白白占着系统资源

### `exit()` - 进程的自我了结

当进程完成任务后，它需要告诉操作系统“我完事儿了”。exit() 就是标准的“退场”方式

- **函数原型**

  ```c
  #include <stdlib.h>
  void exit(int status);
  
  #include <unistd.h>
  void _exit(int status); // _exit 是系统调用，exit 是 C 库函数
  ```

- **作用**

  - `exit(status)`：立即终止当前进程。`status` 是它的“遗言”（退出状态码），父进程可以通过 `wait()` 来获取这个值。
  - **区别**：`exit()` (C库函数) 会在终止前做一些清理工作（比如刷新I/O缓冲区，把你 `printf` 没发出去的东西发出去）；`_exit()` (系统调用) 则“就地去世”，不做任何清理。
  - `main` 函数的 `return status;` 等价于调用 `exit(status);`。

- **参数详解**

  - `status`：一个 `int` 值，但**只有低 8 位** (即 0-255) 会作为退出状态码。

- **返回值**

  - 此函数永不返回。

### `wait()` - “收尸”（阻塞等待）

`wait()` 是父进程用来回收子进程的最简单方式。

- **函数原型**

  ```c
  #include <sys/wait.h>
  pid_t wait(int *wstatus);
  ```

- **作用**

  1. **阻塞 (Blocking)：** 如果父进程调用 `wait()`，而此时它**没有**任何子进程“死亡”，那么父进程会**暂停**（进入阻塞态），直到它的**任意一个**子进程终止
  2. **“收尸” (Reaping)：** 一旦有子进程终止（变成僵尸），`wait()` 会立即回收这个子进程的资源，并返回
  3. **获取状态：** `wait()` 会把子进程的“遗言”（退出状态）填入 `wstatus` 指向的 `int` 变量中。

- **参数详解**

  - `wstatus`：一个 `int` 型指针。操作系统会把子进程的“死亡信息”打包塞进这个 `int` 里。如果你不关心子进程是怎么死的，可以传入 `NULL`

- **返回值**

  - **成功时**：返回**被回收的那个子进程的 PID**

  - **如果出错**：返回 `-1`（例如，当前进程压根没有任何子进程）

    

###  `waitpid()` - “收尸”（精准点名）

`waitpid()` 是 `wait()` 的“专业版”，功能更强大，可以不阻塞，也可以指定回收某一个子进程。

- **函数原型**

  ```c
  #include <sys/wait.h>
  pid_t waitpid(pid_t pid, int *wstatus, int options);
  ```

- **参数详解**

  - `pid`：**你想等谁？**
    - `> 0`：只等那个**特定 PID** 的子进程（例如 `waitpid(123, ...)` 只等 PID=123 的儿子）
    - `-1`：等**任意一个**子进程（此时 `waitpid(-1, ...)` 就等同于 `wait(...)`）
    - `0`：等**同一个进程组**的任意一个子进程
    - `<-1`：等进程组 ID 为 `pid` 绝对值的任意一个子进程
  - `wstatus`：和 `wait()` 一样，用来存放“死亡信息”
  - `options`：**你打算怎么等？**
    - `0`：**默认值，阻塞等待**。和 `wait()` 一样，等到天荒地老
    - `WNOHANG`：**（最常用）非阻塞**。`waitpid()` 会“试探”一下，如果有子进程死了，就回收它；如果没死的，**函数立即返回 0**，父进程继续干别的活
    - `WUNTRACED`：如果子进程进入“暂停”状态，也返回
    - `WCONTINUED`：如果子进程从“暂停”恢复，也返回

- **返回值**

  - **成功时（阻塞）**：返回被回收的子进程 PID
  - **成功时（非阻塞 WNOHANG）**：
    - `> 0`：成功回收了一个子进程，返回值是它的 PID
    - `= 0`：**没有**子进程终止（“孩子还在玩，别催”），父进程可以继续
  - **如果出错**：返回 `-1`

### `wstatus` 详解：如何“验尸”

`wait()` 和 `waitpid()` 返回的 `status` 是一个加密的 `int`，不能直接 `printf`。必须用操作系统提供的“宏”来解密

- `WIFEXITED(status)`：
  - **宏（返回 true/false）：** 判断子进程是不是“**正常退出**”的（即调用 `exit()` 或 `main` 中 `return`）。
  - *“子进程是不是寿终正寝的？”*
- `WEXITSTATUS(status)`：
  - **宏（返回值）：** **如果** `WIFEXITED(status)` 为真，用这个宏来提取子进程的**退出码**（0-255）。
  - *“它留下的遗言（退出码）是啥？”* (例如 `exit(123)`，这里就返回 123)。
- `WIFSIGNALED(status)`：
  - **宏（返回 true/false）：** 判断子进程是不是被**信号“杀死”**的（比如被 `kill -9`，或者 `Ctrl+C` 弄死）。
  - *“子进程是不是被人暗杀的？”*
- `WTERMSIG(status)`：
  - **宏（返回值）：** **如果** `WIFSIGNALED(status)` 为真，用这个宏来提取**杀死它的那个信号的编号**。
  - *“凶器（信号编号）是啥？”* (例如 `kill -9`，这里就返回 9)

### 示例代码

1. wait

```c
#include <stdio.h>
#include <unistd.h>
#include <stdlib.h>
#include <sys/wait.h>

int main(int argc, char const *argv[])
{
    int pid = fork();
    if (pid > 0)
    {
        // --- 父进程 ---
        int Stat;
        printf("父进程开始等待...\n");
        
        // 1. 在这里阻塞，等子进程
        if( wait(&Stat) < 0 ) 
        {
            perror("wait error");
        }
        else{
            // 2. Stat 里现在是“加密”信息
            // 3. 用“宏”来解密
            if ( WIFEXITED(Stat) )  // 3a. 是不是正常退出？
            {
                // 是的，提取退出码
                printf("子进程寿终正寝，退出码【 %d 】\n", WEXITSTATUS( Stat ));
            }
            else if ( WIFSIGNALED(Stat) ) // 3b. 是不是被信号干掉的？
            {
                // 是的，提取信号编号
                printf("子进程被信号杀死，凶手是【 %d 】\n", WTERMSIG( Stat ));
            }
        }
    }
    else if(pid == 0)
    {
        // --- 子进程 ---
        printf("我是子进程【%d】你来砍我呀...\n", getpid());
        
        // --- 实验点 A ---
        // while(1); 
        // 效果：子进程死循环，父进程永远卡在 wait()。
        // 你必须在另一个终端执行 kill [子进程PID]
        // 此时父进程的 WIFSIGNALED(Stat) 会为真。

        // --- 实验点 B ---
        sleep(3); // 模拟干活
        printf("子进程任务结束..\n");
        // return 256; // 退出码 256，父进程 WEXITSTATUS 收到的是 0 (256 % 256)
        exit( 123 ); // 退出码 123，父进程 WEXITSTATUS 收到的是 123
    }
    
    // 父进程回收完子进程后，会执行到这里
    printf("父进程也退出了。\n");
    return 0;
}
```

2. waitpid

```c
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <sys/wait.h>

int main() {
    pid_t pid1, pid2;
    int children_left = 2; // 我们有两个孩子要回收

    // --- 创建第一个子进程 ---
    pid1 = fork();
    if (pid1 == 0) {
        // 子进程 1 ("短命")
        printf("子进程 1 (PID: %d) 开始睡觉 2 秒...\n", getpid());
        sleep(2);
        printf("子进程 1 睡醒了，退出。\n");
        exit(2); // 退出码 2
    }

    // --- 创建第二个子进程 ---
    if (pid1 > 0) { // 只有父进程继续创建
        pid2 = fork();
        if (pid2 == 0) {
            // 子进程 2 ("长命")
            printf("子进程 2 (PID: %d) 开始睡觉 5 秒...\n", getpid());
            sleep(5);
            printf("子进程 2 睡醒了，退出。\n");
            exit(5); // 退出码 5
        }
    }

    // --- 父进程执行区 (pid1 > 0 && pid2 > 0) ---
    if (pid1 > 0 && pid2 > 0) {
        printf("父进程 (PID: %d) 开始轮询...\n", getpid());

        while (children_left > 0) {
            int status;
            
            // 关键：非阻塞等待
            // pid = -1: 等任意子进程
            // options = WNOHANG: 没死的就立刻返回0，别卡住我
            pid_t child_pid = waitpid(-1, &status, WNOHANG);

            if (child_pid > 0) {
                // 哎！回收到了一个
                printf("父进程：回收到了一个子进程 (PID: %d)\n", child_pid);
                if (WIFEXITED(status)) {
                    printf("  > 它的退出码是: %d\n", WEXITSTATUS(status));
                }
                children_left--; // 孩子-1
            } 
            else if (child_pid == 0) {
                // 没动静，孩子还在跑...
                printf("父进程在“玩手机”... (孩子们都还没完事儿)\n");
                sleep(1); // 睡 1 秒再问，免得刷屏
            } 
            else {
                // waitpid 出错 (比如没有子进程了)
                perror("waitpid error");
                break; // 退出循环
            }
        }
        
        printf("父进程：所有孩子都回收完毕！退出。\n");
    }

    return 0;
}
/*
父进程（PID：120739）开始轮询
子进程都没忙完
子进程1（PID：120740）开始睡觉2s
子进程2(PID:120741)开始睡觉4s
子进程都没忙完
子进程1睡醒了退出
子进程都没忙完
父进程：回收了一个子进程（PID：120740）
其退出码为2
子进程都没忙完
子进程睡醒了退出
父进程：回收了一个子进程（PID：120741）
其退出码为5
所有孩子都已经回家！退出
*/
```



## 进程的加载 - `exec` 函数族

`fork()` 只是“生”了个一模一样的娃，但我们通常不希望这个娃跟咱“子承父业”干一样的事儿而是“变身”去干点别的，比如变成 `ls` 或者 `python`。`exec` 函数族就是用来“夺舍变身”的。

###  `exec()` - 进程“夺舍”



`exec` 函数族的核心功能不是创建新进程，而是**加载并执行一个新程序**。

它会用一个全新的程序**彻底覆盖**当前进程的内存空间（包括代码段、数据段、堆栈等）。一旦 `exec` 调用成功，老的程序（就是调用 `exec` 的那个）就**灰飞烟灭**了，**永远不会再执行**。

- **关键点**：`exec` 成功**不返回**，失败才**返回 -1**。

- **经典组合**：这解释了为什么 `exec` 总是和 `fork()` 一起出现。

  1. 父进程 `fork()` 一个子进程（克隆）。
  2. 子进程（在 `if (pid == 0)` 分支里）调用 `exec()`（变身）。
  3. 父进程继续执行原来的代码，子进程则变成了全新的程序。

- **函数原型**

  ```c
  #include <unistd.h>
  
  // 访问系统环境变量
  extern char **environ;
  
  // --- “l” (list) 系列：参数以“列表”形式传入，以 NULL 结尾 ---
  int execl(const char *path, const char *arg, ... /*, (char *) NULL */);
  int execlp(const char *file, const char *arg, ... /*, (char *) NULL */);
  int execle(const char *path, const char *arg, ... /*, (char *) NULL, char * const envp[] */);
  
  // --- “v” (vector) 系列：参数以“指针数组” (argv) 形式传入 ---
  int execv(const char *path, char *const argv[]);
  int execvp(const char *file, char *const argv[]);
  int execvpe(const char *file, char *const argv[], char *const envp[]);
  ```

### `exec` 家族命名“黑话”



这 6 个函数看起来吓人，其实就是 3 个“开关”（`l`/`v`, `p`, `e`）的组合：

- **`l` (List) vs. `v` (Vector)**
  - `l`：表示参数 `arg` 是一个一个**列表** (List) 形式传入的，必须以 `(char *) NULL` 结尾。
    - *用法：`execl("/bin/ls", "ls", "-l", "/", NULL);`*
  - `v`：表示参数 `arg` 是一个**指针数组** (Vector) 形式传入的。
    - *用法：`char \*args[] = {"ls", "-l", "/", NULL}; execv("/bin/ls", args);`*
- **`p` (Path)**
  - **不带 `p`** (如 `execl`, `execv`)：你**必须**提供新程序的**完整路径** (如 `/bin/ls`)。
  - **带 `p`** (如 `execlp`, `execvp`)：你**可以**只提供程序名 (如 `ls`)，`exec` 会自动在系统的 `PATH` 环境变量里帮你搜索。
- **`e` (Environment)**
  - **不带 `e`** (如 `execl`, `execlp`...)：新程序**自动继承**父进程的**所有**环境变量。
  - **带 `e`** (如 `execle`, `execvpe`)：**不继承**。你必须手动传入一个 `envp[]` 数组，作为新程序的新环境变量。





### `exec`函数详解

#### 列表 (l) 系列

- **函数原型**

```
#include <unistd.h>
int execl(const char *path, const char *arg, ... /*, (char *) NULL */);
int execlp(const char *file, const char *arg, ... /*, (char *) NULL */);
int execle(const char *path, const char *arg, ... /*, (char *) NULL, char * const envp[] */);
```

- **参数详解**
  - `path`：要执行程序的**完整路径**（例如 `/bin/ls`）。
  - `file`：（仅 `execlp`）要执行的**程序名**（例如 `ls`），会自动搜索 `PATH`。
  - `arg`：新程序的第一个命令行参数（`argv[0]`），按惯例通常是程序名本身。
  - `...`：后续的命令行参数列表（`argv[1]`...`argv[n]`），**最后一个必须是 `(char \*) NULL`**。
  - `envp[]`：（仅 `execle`）自定义的环境变量数组，也必须以 `NULL` 结尾。

#### 数组 (v) 系列

- **函数原型**

  ```c
  #include <unistd.h>
  int execv(const char *path, char *const argv[]);
  int execvp(const char *file, char *const argv[]);
  int execvpe(const char *file, char *const argv[], char *const envp[]);
  ```

- **参数详解**

  - `path` / `file`：同上（一个要完整路径，一个会自动搜索）。
  - `argv[]`：一个 `char*` 指针数组，包含了新程序的所有命令行参数（`argv[0]` 到 `argv[n]`），数组的**最后一个元素必须是 `NULL`**。
  - `envp[]`：（仅 `execvpe`）自定义的环境变量数组，也必须以 `NULL` 结尾。

- **返回值**
  - **成功时**：**不返回**。当前进程已经被新程序替换。
  - **失败时**：返回 **-1**，并设置 `errno` 错误码（例如，程序未找到、权限不足）。

### 环境变量相关接口

`exec` 默认会继承环境变量。如果你想在 `exec` 变身*之前*修改它们，或者新程序变身*之后*读取它们，就需要这些函数。

#### `getenv`

- **函数原型**：`#include <stdlib.h> \n char *getenv(const char *name);`
- **作用**：获取指定环境变量的值
- **参数详解**：
  - `name`：要查询的环境变量的**名称**（例如 `"PATH"` 或 `"HOME"`）。
- **返回值**：
  - **成功时**：返回一个指向该环境变量**值**的字符串（例如 `"/usr/bin"`）。
  - **失败时**：如果找不到该变量，返回 `NULL`
- **注意**：返回的字符串是“只读”的，你不能修改它

#### `setenv`

- **函数原型**：`#include <stdlib.h> \n int setenv(const char *name, const char *value, int overwrite);`
- **作用**：设置、修改或添加一个环境变量
- **参数详解**：
  - `name`：要设置的变量**名称**
  - `value`：要设置的**值**
  - `overwrite`：一个 `int` 标记
    - 如果为 `0`：若 `name` 已存在，则**不覆盖**，函数返回
    - 如果不为 `0`：若 `name` 已存在，则**强行覆盖**
- **返回值**：
  - **成功时**：返回 `0`
  - **失败时**：返回 `-1`（例如内存不足）

#### `unsetenv`

- **函数原型**：`#include <stdlib.h> \n int unsetenv(const char *name);`
- **作用**：删除一个环境变量
- **参数详解**：
  - `name`：要删除的变量**名称**
- **返回值**：
  - **成功时**：返回 `0`
  - **失败时**：返回 `-1`

#### `secure_getenv`

- **函数原型**：`#include <stdlib.h> \n char *secure_getenv(const char *name);`
- **作用**：`getenv` 的一个安全版本。在某些特殊安全上下文（例如进程的 `UID` 和 `EUID` 不匹配时）它会返回 `NULL`，防止安全漏洞
- **参数详解**：同 `getenv`
- **返回值**：同 `getenv`，但在特定不安全条件下会返回 `NULL`

### 代码示例

```c
#include <stdio.h>
#include <stdlib.h>     // for exit()
#include <unistd.h>     // for fork(), execlp()
#include <sys/wait.h>   // for wait()
#include <sys/types.h>  // for pid_t

int main() {
    pid_t pid;
    int status;

    printf("---父进程(PID: %d)开始，准备fork...\n", getpid());

    pid = fork(); // “生”

    if (pid < 0) {
        // --- Fork 失败 ---
        perror("fork error");
        exit(1); // 失败了就没必要继续了
    } 
    else if (pid == 0) {
        // --- 子进程 (pid == 0) ---
        printf(">>> 子进程(PID: %d)已创建，准备变身！\n", getpid());

        // “夺舍变身”
        // l: 列表传参
        // p: 自动在 PATH 里搜索
        // 参数: ("程序名", "argv[0]", "argv[1]", "argv[2]", ... , NULL)
        execlp("ls", "ls", "-l", "/", (char *) NULL);

        // !! 关键 !!
        // 如果 execlp 成功了，它永远不会返回，
        // 所以下面这行代码 永远 不会被执行。
        
        // 如果它执行了，说明 execlp 失败了！
        perror("execlp error"); // 打印 "execlp error: No such file or directory"
        exit(1); // 变身失败，子进程必须退出，否则它会变回“父进程”的克隆体捣乱
    } 
    else {
        // --- 父进程 (pid > 0) ---
        printf("--- 父进程(PID: %d)正在等子进程(PID: %d)干完活...\n", getpid(), pid);

        // “收尸”
        // 阻塞等待，直到 PID 为 pid 的子进程终止
        waitpid(pid, &status, 0); 
        // wait(&status); // 用这个“傻等”也行

        if (WIFEXITED(status)) {
            printf("--- 父进程：子进程 %d 正常退出了，退出码 %d。\n", pid, WEXITSTATUS(status));
        } else {
            printf("--- 父进程：子进程 %d 异常终止了。\n", pid);
        }
        
        printf("--- 父进程：活干完了，我也收工了。\n");
    }

    return 0;
}
```

## 其他进程加载操作 (`system` 与 `popen`)

如果你只是想“运行个命令就完事儿”，或者想“运行个命令，顺便偷它打印出来的东西”，那 C 库早就为你准备了两个更省事的“快捷方式”

### `system()` - “全自动傻瓜包”

`system()` 函数就是 `fork` + `exec` + `wait` 的“全家桶”。你只管发号施令，它负责“生娃、变身、收尸”所有脏活累活。

- **函数原型**

  ```c
  #include <stdlib.h>
  int system(const char *command);
  ```

- **作用** 执行一个 shell 命令。它在内部帮你完成了 `fork()` -> `exec()` -> `wait()` 的全套动作。

  - **关键点**：`system()` 会**阻塞**你的程序，直到它调用的那个命令执行完毕并返回。

- **参数详解**

  - `command`：一个`const char *`字符串，包含你想在 shell 中执行的完整命令（例如 `"ls -l -a"` 或 `"gcc main.c -o main"`）。

- **返回值**

  - 返回值有点复杂，它返回的是子进程的 `wait()` 状态（就像 `wait()` 里的那个 `status` 变量）。
  - 如果 `fork` 或 `wait` 失败，它会返回 `-1`。
  - *（简单记：如果命令成功执行，通常返回 0，但并不绝对。）*

- **示例代码**

  ```c
  #include <stdio.h>
  #include <stdlib.h>
  int main() {
    printf("开始执行system（）\n");
    system("ls -lah");
    // 这行代码会“卡住”，直到 'ls -l -a' 执行完毕
    printf("执行完成，程序退出\n");
    return 0;
  }
  ```

###  `popen()` / `pclose()` - “半自动高级包”

`system()` 只是执行，但它拿不到命令的*输出*。如果你想运行一个 `ls`，并**读取** `ls` 打印出来的结果，`popen()` 才是你的“瑞士军刀”,`popen` 的意思是“**P**rocess **Open**”（进程打开）。它会运行一个命令，但同时创建一个**管道 (Pipe)**，把那个命令的“标准输入”或“标准输出”接到你的程序里，让你像读写文件一样和它通信。

#### `popen()`

- **函数原型**

  ```c
  #include <stdio.h>
  FILE *popen(const char *command, const char *type);
  ```

- **作用** 执行 `command`，并返回一个标准 `FILE` 指针，你可以用它来读取子进程的输出，或写入子进程的输入。

- **参数详解**

  - `command`：要执行的 shell 命令字符串（例如 `"ls -l"`）。
  - `type`：**关键参数**，决定你是“读”还是“写”：
    - `"r"` (Read)：你想**读取**子进程的**标准输出 (stdout)**。`popen` 返回的 `FILE*` 你可以用 `fgets`, `fgetc` 等来读。
    - `"w"` (Write)：你想**写入**子进程的**标准输入 (stdin)**。`popen` 返回的 `FILE*` 你可以用 `fputs`, `fprintf` 等来写。

- **返回值**

  - **成功时**：返回一个 `FILE *` 文件流指针。
  - **失败时**：返回 `NULL`。

#### `pclose()`

`popen` 有“开”就有“关”。`pclose` 不仅是关闭文件流，它还会负责 `wait()`，等待子进程真正结束并回收它。

- **函数原型**

  ```c
  #include <stdio.h>
  int pclose(FILE *stream);
  ```

- **作用** 关闭 `popen()` 返回的文件流，并**阻塞等待**子进程执行完毕，然后回收它（防止僵尸进程）。

- **参数详解**

  - `stream`：就是 `popen()` 返回的那个 `FILE *` 指针。

- **返回值**

  - 返回子进程的终止状态（就像 `wait()` 里的 `status`）。

#### 示例代码

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h> // bzero 需要
#include <strings.h> // bzero 在这里更标准

int main(int argc, char const *argv[])
{
    FILE * fp;
    
    // 1. "打开" ls -l 进程，并准备“读”(r)它的输出
    fp = popen( "ls -l" , "r" );
    if (fp == NULL) {
        perror("popen error");
        exit(1);
    }

    char msg[128] = {0};
    int count = 0 ;

    // 2. 像读文件一样，一行一行地读
    while (1)
    {
        bzero(msg , sizeof(msg)); // 清空缓冲区
        
        // 从 popen 返回的管道中读取一行
        char * ret = fgets( msg , sizeof(msg) , fp ); 
        
        if (ret == NULL) // 读到末尾了
        {
            break; 
        }
        
        printf("[%s]", msg); // 打印我们读到的内容
        count++;
    }
    
    // ls -l 的第一行是 "total ..."，所以文件数是 count-1
    printf("\n有：%d 个文件\n", count - 1);
    
    // 3. 必须关闭流，并等待子进程退出
    pclose(fp); 
    
    return 0;
}
```

## 进程的“身后事” - 僵尸进程 (Zombie)

“生老病死”是常态，进程也不例外。`fork()` 是“生”，`exit()` 是“死”，但“死”了之后，在“火化”（`wait`）之前，有个尴尬的中间态，就是“僵尸”



### 什么是僵尸进程？

- **定义**：一个进程已经执行完毕（例如 `main` 函数 `return` 或调用了 `exit()`），但它的**父进程还没有来“收尸”**（即没有调用 `wait()` 或 `waitpid()` 来获取它的退出状态）。
- **状态**：此时，这个“已死”的进程就处于 `EXIT_ZOMBIE` 状态，俗称**僵尸进程**。

### 僵尸进程的产生原因

- **存在的必要性**：僵尸进程是生命周期中一个**短暂的必经阶段**。
- **原因**：子进程死了，但不能立刻就“烟消云散”。它必须保留它的“遗言”——即它的进程 ID 和退出状态（是正常死亡还是意外被杀？），保存在进程表（Process Table）中。
- **目的**：它在被动地等待其创建者（父进程）来读取这份“死亡报告”。

### 僵尸进程的危害

- **问题不在内存**：一个常见的误解是僵尸进程占用大量内存。**不是的**，它已经死了，它的绝大部分内存资源（代码段、数据段等）**已被释放**。
- **真正的危害**：它**唯一占用的资源**就是**进程表中的一个条目**（Entry）和**进程号（PID）**。
- **后果**：如果一个父进程“管生不管养”，疯狂 `fork()` 却从不 `wait()`，它会制造出大量的僵尸。当进程表被这些“僵尸”塞满时，系统将**无法创建任何新进程**（连 `ls` 或 `ssh` 都可能无法启动），因为 PID 耗尽了。

### 如何“释放”（处理）僵尸进程

“僵尸”是杀不死的（`kill -9` 对僵尸无效，因为它已经死了），你只能让它的父进程来“收尸”

#### 方法一：“管生不管养”的父进程自己也退出

- **原理**：父进程自己死了。
- **后果**：父进程一死，它名下的所有子进程（包括僵尸）都会变成“孤儿进程”。
- **“甩锅”**：所有孤儿进程会被系统的 1 号进程（`init` 或 `systemd`）自动“收养”。
- **`init` 登场**：`init` 是个“模范好市民”，它的核心职责之一就是循环调用 `wait()`，自动“收养”并“清理”所有它接手的孤儿（僵尸），释放它们占用的进程号。
- **缺点**：这不是个好办法，你总不能指望“自杀”来解决问题。

### 方法二：父进程调用 `wait()` / `waitpid()`

- **原理**：父进程主动“收尸”。这是最正统的办法。
- **`wait()`**：阻塞等待，直到*任意一个*子进程死亡，然后回收它。
- **`waitpid()`**：可以指定*某个*子进程，也可以设置为*非阻塞*（`WNOHANG`）模式。
- **缺点**：如果是阻塞模式（默认），父进程在等子进程时啥也干不了，效率低下。

#### 方法三：使用 `SIGCHLD` 信号（最佳实践）

- **原理**：“异步通知”。
- **`SIGCHLD` 信号**：当一个子进程终止（或暂停）时，内核会**自动**向其父进程发送一个 `SIGCHLD` 信号。
- **问题**：这个信号的**默认动作 (Default Action) 是 `Ign`（忽略）**。
- **解决方案**：父进程**注册一个信号处理函数**（Signal Handler）。
  1. 父进程告诉内核：“嗨，如果收到 `SIGCHLD`，别忽略它，请帮我执行 `myFunc` 这个函数。”
  2. 父进程继续干自己的活（比如 `while(1)`）。
  3. 当子进程死亡时，内核中断父进程，插队执行 `myFunc`。
  4. `myFunc` 函数的核心任务就是调用 `wait()`，把僵尸“收尸”。
  5. `myFunc` 执行完毕，父进程回到 `while(1)` 继续干活。
- **优点**：完美解耦。父进程不需要“傻等”，子进程一死就能“立刻”被处理，效率极高。

### 示例代码

```c
#include <stdio.h>
#include <signal.h>
#include <unistd.h>
#include <stdlib.h>
#include <sys/wait.h>

// 信号处理函数：“收尸”的地方
void myFunc ( int SigNum)
{
    // 1. 当信号传来，立刻调用 wait()
    // 注意：这里用 wait(NULL) 只是示例，
    // 严谨的写法应该用 waitpid(-1, NULL, WNOHANG) 
    // 并且放在一个 while 循环里，防止“信号堆积”导致僵尸没收干净
    pid_t tid = wait(NULL); 
    if (tid > 0) {
        printf("成功处理子进程[%d]的僵尸状态..\n" , tid );
    }
}

int main(int argc, char const *argv[])
{
    pid_t tid = fork();

    if (tid == 0)
    {
        // --- 子进程 ---
        printf("子进程(PID: %d)开始干活...\n", getpid());
        sleep(2); // 模拟干活 2 秒
        printf("子进程干完了，退出。\n");
        exit(0) ; // 子进程死亡，变成僵尸，内核发送 SIGCHLD
    }
    
    else if (tid > 0)
    {
        // --- 父进程 ---
        
        // 关键：注册信号处理器
        // “如果收到 SIGCHLD 信号，就去执行 myFunc 函数”
        signal(SIGCHLD , myFunc ) ;

        // 父进程干自己的“正事”
        while (1)
        {
            printf("我是你大爷(PID: %d)，我正忙...\n", getpid());
            sleep(1);
        }
    }
    
    return 0; // 永远执行不到这里
}
```

**执行流程：**

1. 父进程和子进程启动。
2. 父进程注册了 `SIGCHLD` 处理器，然后开始 `while(1)` 循环，每秒打印“我是你大爷...”。
3. 子进程 `sleep(2)`。
4. （第 1 秒）父进程打印：“我是你大爷...”。
5. （第 2 秒）父进程打印：“我是你大爷...”。
6. （第 2 秒末）子进程 `exit(0)` 死亡。
7. **内核**：检测到子进程死亡，立刻向父进程发送 `SIGCHLD` 信号。
8. **父进程**：正准备 `sleep(1)`，突然被信号中断！
9. **内核**：暂停 `while` 循环，强迫父进程去执行 `myFunc`。
10. **`myFunc` 执行**：`wait(NULL)` 成功回收了子进程，打印“成功处理子进程...”。
11. `myFunc` 返回。
12. **父进程**：回到 `while` 循环被中断的地方，继续执行。
13. （第 3 秒）父进程打印：“我是你大爷...”。
