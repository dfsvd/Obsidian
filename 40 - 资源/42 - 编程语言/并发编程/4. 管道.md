## 概序
进程是独立的、隔离的（拥有独立的虚拟地址空间），一个进程不能直接访问另一个进程的内存但现实中，很多任务需要多个进程协同完成，这就必须有一种机制让它们能互相“递话”，这就是**进程间通信 (Inter-Process Communication, IPC)**

IPC 的方式有很多，如共享内存、消息队列、信号等以下是 IPC“大家族”的主要成员：

- **1. 管道 (Pipe)**
  - 匿名管道 (pipe)：适用于有亲缘关系的进程（如父子）间，一对一通信
  - 具名管道 (fifo)：适用于任何进程间，一对一或多对一通信
- **2. 套接字 (Socket)**
  - **特点：** 最通用的 IPC，不仅能用于同一台机器的进程，更是跨网络进行进程间通信的唯一标准
- **3. 信号 (Signal)**
  - **特点：** 异步通信方式它不传输数据，只用于“通知”进程发生了某个事件（例如 `SIGCHLD`）
- **4. System-V IPC 对象**
  - *（这是一套经典且“重型”的 IPC，功能强大但接口略显老旧）*
  - **共享内存 (Shared Memory)：** 效率最高的方式允许多个进程直接读写同一块物理内存，省去了数据拷贝
  - **消息队列 (Message Queue)：** 相当于一个带“标签”的管道，数据以“消息”为单位存取
  - **信号量 (Semaphore)：** 也称为“信号灯”它不传数据，而是用作一个计数器，专门用来协调（同步/互斥）进程对共享资源的访问
- **5. POSIX 信号量**
  - *（System-V 信号量的“现代版”，接口更明晰）*
  - **POSIX 匿名信号量：** 适用于多线程间的同步
  - **POSIX 具名信号量：** 适用于多进程间的同步
##  管道 (Pipe)
在IPC所有方式中，**管道 (Pipe)** 是其中最经典、最基础的一种
“管道”这个词非常形象：它是在内核中开辟的一块缓冲区，专门用于数据传输，遵循**先进先出 (FIFO)** 的原则数据像水流一样，从管道的一端（写端）流入，从另一端（读端）流出
管道主要分为两大类：
- **匿名管道 (pipe)**
  - **特点：** 它没有名字，只是内核中的一个数据结构，通过一对文件描述符（一个读、一个写）来访问
  - **限制：** 只能用于**有亲缘关系的进程间**（例如，父进程 `fork()` 出子进程后，父子之间使用）
  - **模型：** 严格的**一对一**通信
- **具名管道 (fifo)**
  - **特点：** 也叫 `FIFO` 文件它在文件系统中有一个**可见的路径（文件名）**，任何有权限的进程都可以通过这个“文件名”来访问它
  - **限制：** 打破了匿名管道的亲缘关系限制，允许**任何不相关的进程间**通信
  - **模型：** 更灵活，支持**一对一**或**多对一**
## 匿名管道 (pipe)
匿名管道是 IPC 的“入门款”它是一个**没有名字**、只能在**内核**中访问的缓冲区
### 基本逻辑与特点
- **基本形态**：你可以把它想象成一根“水管”它是在内核中开辟的一块缓冲区，数据从一端（写端）流入，从另一端（读端）流出
<img src="%E8%BF%9B%E7%A8%8B%E9%97%B4%E9%80%9A%E4%BF%A1-%E7%AE%A1%E9%81%93.assets/167929.jpeg" alt="img" style="zoom:67%;" />
- **核心特点**：
  - **匿名性**：它没有文件名，不能通过 `open()` 来访问，只能通过 `pipe()` 函数创建
  - **亲缘性**：**只能用于有亲缘关系的进程**（通常是父子进程）因为它的“把手”（文件描述符）只能通过 `fork()` 来继承
  - **单向/半双工**：数据流是单向的一个文件描述符 (`fd[0]`) 专门用于读，另一个 (`fd[1]`) 专门用于写
  - **FIFO**：严格的“先进先出”
  - **无定位**：你不能用 `lseek()` 来定位读写位置，只能从头读、往尾写
  - **阻塞性**：
    - 如果“水管”（缓冲区）满了，`write()` 会阻塞（卡住），直到有人把数据读走
    - 如果“水管”空了，`read()` 会阻塞，直到有人往里写数据

![img](../../../00%20-%20收件箱/进程间通信-管道.assets/167942.png)

### 函数接口 `pipe()`

- **函数原型**

  ```C
  #include <unistd.h>
  int pipe(int fd[2]);
  ```
- **作用** 创建一个匿名管道
- **参数详解**
  - `fd[2]`：这是一个**输出参数**，是一个包含两个整数的数组
    - **`fd[0]`**：被内核设置为管道的**读端**
    - **`fd[1]`**：被内核设置为管道的**写端**
- **返回值**
  - 成功：返回 `0`
  - 失败：返回 `-1`，并设置 `errno`
### `fork()` 继承机制
匿名管道的魔力在于 `fork()`
1. **`pipe()`**：父进程先调用 `pipe()`，得到两个文件描述符 `fd[0]`(读) 和 `fd[1]`(写)，它们都指向**同一个**内核管道
2. **`fork()`**：父进程调用 `fork()`子进程被创建，它**完整地继承**了父进程的文件描述符表
3. **连接**：此时，子进程的 `fd[0]` 和 `fd[1]` 也指向**同一个**内核管道
4. **通信**：父子进程**约定**好谁读谁写例如，如果父进程想给子进程发消息：
   - 父进程就使用 `fd[1]` 来 `write()`
   - 子进程就使用 `fd[0]` 来 `read()`
### 示例代码
```C
#include <stdio.h>
#include <unistd.h>
#include <stdlib.h>
#include <string.h>

// 父进程的任务：从键盘(stdin)读，往管道(fd_write)写
void ParentProcess ( int fd_write) 
{
    char SendMsg[32] ;
    while (1)
    {
        bzero(SendMsg , sizeof(SendMsg));
        // 1. 从标准输入(键盘)读取一行
        fgets( SendMsg , sizeof(SendMsg) , stdin );
        // 2. 将读取到的内容写入管道
        int ret_val = write( fd_write , SendMsg , strlen(SendMsg) );
        printf("【%d】发送了%d字节数据..\n" , getpid() , ret_val );
    }
}

// 子进程的任务：从管道(fd_read)读，往屏幕(stdout)写
void ChildProcess(int fd_read)
{
    char RecvMsg[32] ;
    while (1)
    {
        bzero(RecvMsg , sizeof(RecvMsg));
        // 3. 从管道读取数据 (如果没数据，这里会阻塞)
        int ret_val = read( fd_read , RecvMsg , sizeof(RecvMsg) );
        // 4. 将读取到的内容打印
        printf("【%d】收到%d字节数据：%s\n" , getpid() , ret_val , RecvMsg );
    }
}

int main(int argc, char const *argv[])
{
    // 定义数组用于接收 读/写 文件描述符
    int pipefd[2] ; // 约定：pipefd[0] 读, pipefd[1] 写

    // 1. 创建管道
    if(pipe( pipefd ))
    {
        perror("pipe error");
        return -1 ;
    }

    // 2. 创建子进程
    pid_t tid = fork();
    if (tid > 0)
    {
        /* 父进程 */
        // 约定父进程是“写者”，它只需要 写的句柄
        // 所以把“写端” fd[1] 传给它
        ParentProcess( pipefd[1] );
    }
    else if (tid == 0)
    {
        /* 子进程 */
        // 约定子进程是“读者”，它只需要 读的句柄
        // 所以把“读端” fd[0] 传给它
        ChildProcess( pipefd[0] );
    }
    
    return 0;
}
```
## 具名管道 (FIFO)
匿名管道（pipe）解决了“父子”通信问题，但如果两个“毫不相干”的进程想对话，匿名管道就无能为力了，因为它没有“名字”，别的进程找不到它**具名管道 (FIFO)** 就是为了解决这个问题而生的
### 概念与特性
具名管道，也称为 `FIFO` (First In First Out)，是一种特殊的**文件**
![img](../../../00%20-%20收件箱/进程间通信-管道.assets/167949.png)
- **与匿名管道的异同**：
  - **同**：它在内核中依然是一个“管道”（遵循 FIFO、单向、阻塞、无 `lseek` 定位等特性）
  - **异**：它在文件系统中有一个**可见的路径（文件名）**
- **核心特性**：
  1. **可见性**：因为它是一个文件，你可以用 `ls -l` 看到它（文件类型为 `p`）
  2. **“中介”**：它允许**任何**两个（或多个）不相关的进程通过这个“文件名”找到对方，进行通信
  3. **创建**：必须使用 `mkfifo()` 函数或 `mkfifo` 命令来**显式创建**，而不是 `pipe()`
  4. **使用**：创建后，进程就像使用普通文件一样，使用 `open()` 来打开它，使用 `read()` / `write()` 来读写
  5. **多写支持**：支持**多路**进程同时向一个 FIFO 写入（匿名管道不具备）

### 函数接口 `mkfifo()`
- **函数原型**
  ```c
  #include <sys/types.h>
  #include <sys/stat.h>
  
  int mkfifo(const char *pathname, mode_t mode);
  ```
- 作用
  在文件系统中创建一个具名管道（FIFO）文件
- **参数详解**
  - `pathname`：你希望创建的管道的**路径+文件名**（例如 `"/tmp/my_fifo"` 或 `"./myfifo"`）
  - `mode`：指定文件的**访问权限**（例如 `0666`，表示所有者、组用户、其他用户均可读写）
  - **注意**：最终的文件权限会受到 `umask` 掩码的影响（`final_mode = mode & ~umask`）
- **返回值**
  - 成功：返回 `0`
  - 失败：返回 `-1`，并设置 `errno`
### FIFO 的使用：`open()` 的阻塞特性
`mkfifo()` 只是“创建”了管道，进程间**使用**它必须通过 `open()``open()` 操作 FIFO 时有非常重要的阻塞规则：
- **读打开 (`O_RDONLY`)**：`open(..., O_RDONLY)` 会**阻塞（卡住）**，直到有另一个进程以“写”方式 (`O_WRONLY`) 打开**同一个** FIFO
- **写打开 (`O_WRONLY`)**：`open(..., O_WRONLY)` 会**阻塞（卡住）**，直到有另一个进程以“读”方式 (`O_RDONLY`) 打开**同一个** FIFO
- **读写打开 (`O_RDWR`)**：`open(..., O_RDWR)` **不会阻塞**因为它自己既是读者又是写者，满足了“读写端必须同时存在”的条件
### 示例代码分析 (读/写端)
运行前提：
你必须先在终端中创建这个管道文件：`mkfifo /home/even/myfifo`
**程序一：写进程 (Writer)**
```c
#include <fcntl.h>
#include <stdio.h>
#include <string.h>
#include <strings.h> 
#include <unistd.h>

int main() {
  
  // 运行前，必须先在终端执行: mkfifo ./myfifo
  
  // 1. 打开具名管道文件
  // O_RDWR: 以“读写”模式打开
  // 这是一个技巧：
  //   如果用 O_WRONLY，open() 会阻塞，直到“读”端也 open()
  //   如果用 O_RDWR，open() 不会阻塞
  int fd = open("./myfifo", O_RDWR);
  if (fd == -1) {
    perror("open error!"); // open 失败
    return -1;
  }
  
  // 加上 \n 确保 printf 的缓冲区被刷新，能立刻看到打印
  printf("open fifo OK\n"); 
  
  char buf[32];

  while (1) {
    // 2. 清空缓冲区
    // bzero 是 <strings.h> 里的，memset(buf, 0, sizeof(buf)) 更通用
    bzero(buf, sizeof(buf));
    
    // 3. 从标准输入(stdin，即键盘)读取一行
    // fgets 会把最后的回车 \n 也读进来
    fgets(buf, sizeof(buf), stdin);
    
    // 4. 将缓冲区的内容写入管道
    // strlen(buf) 计算实际长度
    int ret_val = write(fd, buf, strlen(buf));
    printf("成功写入%d字节的数据..\n", ret_val);
  }
  
  // (虽然 while(1) 导致这里执行不到，但规范写法要有 close)
  close(fd);
  return 0;
}
```

**程序二：读进程 (Reader)**

```c
#include <fcntl.h>
#include <stdio.h>
#include <strings.h>
#include <unistd.h>

int main() {  
  // 1. 打开同一个具名管道文件
  // O_RDWR: 同样使用读写模式，避免 open() 阻塞
  int fd = open("./myfifo", O_RDWR);
  if (fd == -1) {
    perror("open error!"); // open 失败
    return -1;
  }

  // 加上 \n 确保 printf 的缓冲区被刷新
  printf("open fifo OK\n"); 
  
  char buf[32];
  
  while (1) {
    // 2. 清空缓冲区
    bzero(buf, sizeof(buf));
    
    // 3. 从管道中读取数据
    // 如果管道为空，read() 会在此处阻塞，等待“写”端写入
    int ret_val = read(fd, buf, sizeof(buf));
    
    // 4. 判断 read() 的返回值
    if (ret_val == 0) {
      // 当所有“写”端都 close() 了，read() 会返回 0，表示 EOF
      printf("写端已经关闭，读取退出！\n"); // (修正了错别字)
      break;
    }
    
    // 5. 打印读取到的内容
    printf("成功读取%d字节内容：%s\n", ret_val, buf);
  }
  
  close(fd);
  return 0;
}
```
### 管道的读写特性

要深刻理解管道，我们首先要明确两个“术语约定”：
- **“读者”**：指**任何拥有**对该管道的**读权限文件描述符**的进程（*并不仅仅*是正在 `read()` 的进程）
- **“写者”**：指**任何拥有**对该管道的**写权限文件描述符**的进程（*并不仅仅*是正在 `write()` 的进程）
**举例说明：**
1. **纯粹的写者**：
   ```c
   int fd[2];
   pipe(fd);
   close(fd[0]); // 关闭读端
   // 此时，该进程只持有写端 fd[1]，是一个纯粹的“写者”
   ```
2. **既是读者也是写者**：
   ```c
   // O_RDWR 打开，是为了防止 open() 阻塞
   int fd = open("fifo", O_RDWR);
   // 此时，该进程同时持有读和写权限，它既是“读者”也是“写者”
   ```
基于这两个定义，管道的读写行为可以用下表清晰概括：
#### 读操作 (`read`)

| **条件**   | **管道中有数据**        | **管道中无数据**                      |
| ---------- | ----------------------- | ------------------------------------- |
| **有写者** | **正常读取**            | **阻塞等待** (等待写者写入)           |
| **无写者** | 正常读取 (读完剩余数据) | **立即返回 0** (表示 `EOF`，读到末尾) |
> **`read` 总结**：`read` 什么时候会返回 `0`？**当且仅当**所有“写者”都关闭了它们的写端，且管道中剩余的数据也已被读完时
#### 写操作 (`write`)

| **条件**  | **缓冲区未满** | **缓冲区已满**                           |
| ------- | --------- | ----------------------------------- |
| **有读者** | **正常写入**  | **阻塞等待** (等待读者取走)                   |
| **无读者** | (N/A)     | **立即收到 `SIGPIPE` 信号** (Broken pipe) |

> **`write` 总结**：`write` 什么时候会出错？**当所有**“读者”都关闭了它们的读端时，如果“写者”还试图写入，内核会发送 `SIGPIPE` 信号，该信号的默认动作是**终止进程**

### 管道的阻塞特性
从上表可以看出，管道在“无数据可读”或“缓冲区已满”时的**默认行为**是**阻塞 (Blocking)**
- **什么是阻塞？**
  - 阻塞并不是一种错误，而是一种**挂起 (suspend)** 状态
  - 当进程 `read` 一个空管道时，内核会剥夺该进程的 CPU，使其进入休眠（挂起）状态，直到有数据被写入
  - 这是一种高效率的机制，避免了进程在“空等”时（例如使用 `while(1)` 轮询）空转 CPU，提高了系统吞吐量
- **修改阻塞特性：`fcntl`**
  - 管道文件默认是阻塞的，但这个属性是**可以修改**的
  - 我们可以使用 `fcntl` (File Control) 函数，为文件描述符添加 `O_NONBLOCK`（非阻塞）标志

- **函数原型**

  ```c
  #include <fcntl.h> // 需要此头文件
  int fcntl(int fd, int cmd, ... /* arg */ );
  ```

- **设置非阻塞的代码示例**：

  ```c
  #include <fcntl.h> // 确保包含了此头文件
  ...
  // 假设 fd[0] 是我们想操作的管道读端
  
  // 1. 获取当前的文件描述符属性
  long flag = fcntl(fd[0], F_GETFL);
  
  // 2. 把“非阻塞”属性 (O_NONBLOCK) 添加到 flag 中
  //    (使用“按位或”操作)
  flag |= O_NONBLOCK;
  
  // 3. 把添加了“非阻塞”属性的 flag 重新设置回文件描述符中
  fcntl(fd[0], F_SETFL, flag);
  ```
- **设为非阻塞后的效果**：
  - 对一个**空**管道执行 `read()`：**立即返回 -1**，并设置 `errno` 为 `EAGAIN` (或 `EWOULDBLOCK`)，而不是阻塞
  - 对一个**满**管道执行 `write()`：**立即返回 -1**，并设置 `errno` 为 `EAGAIN` (或 `EWOULDBLOCK`)，而不是阻塞
