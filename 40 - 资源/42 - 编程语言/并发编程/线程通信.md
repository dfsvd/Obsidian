# 线程概念



线程是应用层的最小执行单元。在 Linux 内核中，并没有真正“线程”的实体，所有的调度实体都被称为**任务 (Task)**。

进程（Process）和线程（Thread）的主要区别在于资源共享：

- **进程（重量级）**：拥有**一整套完整的、独立的资源**，如独立的虚拟地址空间、文件描述符表、PCB 等。
- **线程（轻量级）**：线程是“进程内的任务”，它本身**不拥有资源**，而是**共享其所属进程的绝大部分资源**（如地址空间、全局变量、打开的文件等）。

如图所示：

- **单线程进程**：进程本身（PCB）和它的执行流（T1）是合一的，它拥有完整的资源。
- **多线程进程**：进程（PCB）拥有资源，但内部有多个执行流（T1, T2...）。这些执行流**共享**进程的资源，但各自拥有**独立的**上下文（如程序计数器、寄存器）和**栈 (Stack)**。

因此，线程常被称为“轻量级进程”，它提供了一种高效的任务处理方式，因为线程间的切换和通信（直接读写全局变量）远快于进程。



# 2. 基本接口





## 2.1 线程的创建



创建一条 POSIX 线程非常简单，只需指定线程的执行函数即可。

- **函数原型**

  C

  ```
  #include <pthread.h>
  
  int pthread_create(pthread_t *thread, 
                     const pthread_attr_t *attr,
                     void *(*start_routine) (void *), 
                     void *arg);
  ```

- 作用

  创建一个新的线程，并使其开始执行 start_routine 函数。

- **参数详解**

  - `thread`：一个**输出参数**，类型为 `pthread_t`（通常是 `unsigned long`）。当函数成功返回时，这个指针指向的内存将被填入新创建线程的 **TID (Thread ID)**。
  - `attr`：线程属性。用于设置线程的栈大小、调度策略、分离状态等。如果传入 `NULL`，则表示使用**默认属性**。
  - `start_routine`：**线程函数指针**。这是新线程的“入口点”（类似于进程的 `main` 函数）。当线程被调度时，它将从此函数开始执行。
  - `arg`：传递给 `start_routine` 函数的**参数**。`pthread_create` 不关心 `arg` 的具体类型，只是原样将其（作为 `void*`）传递给 `start_routine`。如果需要传递多个参数，通常定义一个结构体，并将结构体的地址作为 `arg` 传入。

- **返回值**

  - 成功：返回 `0`。

  - 失败：返回一个**正数的错误码**（例如 `EAGAIN`）。

  - 注意：Pthreads 函数族的错误处理方式与标准

    Linux API 不同。它们不设置全局 errno 变量，而是直接通过返回值报告错误。



## 2.2 并发性



线程最重要的特性是**并发 (Concurrency)**。

与普通函数调用（串行）不同，`pthread_create` 调用后，`start_routine` 函数会与主线程（`main` 函数）**同时运行**（在多核CPU上可能是并行，在单核上是并发）。

这种并发性带来了极高的效率，但也引入了挑战：由于所有线程共享进程的全局变量和堆区内存，当多个线程同时访问（尤其是“读-改-写”）同一块共享资源时，必须特别小心，否则会导致**数据争抢 (Race Condition)**。



### 示例代码：并发执行（有隐患）



以下代码展示了 `main` 线程（作为“生产者”）和 `myTask` 线程（作为“消费者”）如何并发地访问一个全局变量 `Num`。

> **注意：** 此代码使用 `bool falg` 试图进行同步，这是一种“忙等” (Busy-Waiting) 的方式，效率低下且**不是线程安全的**，仅用于演示并发。

```
#include <stdio.h>
#include <pthread.h>
#include <stdlib.h>
#include <stdbool.h>
#include <time.h> // 需要 time() 和 srand()
#include <unistd.h> // 需要 bzero (虽然 stdbool.h 已经包含了)

// 注释修正：falg -> false
// false 表示可以判断奇偶    （资源可读，消费者可运行）
// true 表示可以修改共享资源 （资源可写，生产者可运行）
bool  falg = true; // 这是一个共享资源，用作简易的“锁”

/*
 * 线程任务（消费者）
 */
void *myTask (void * arg )
{
    // 接收共享资源的地址
    int * ptr = (int *)arg ;

    while (1)
    {
        // 1. 检查“锁”是否为 false (轮询，忙等)
        //    意味着生产者已经生产完毕，轮到消费者了
        if (falg == false)
        {
            // 2. 消费资源：判断奇偶
            if ( *ptr % 2 )
            {
                printf("[%d]是一个奇数\n" , *ptr );
            }
            else{
                printf("[%d]是一个偶数\n" , *ptr );
            }
            
            // 3. 释放“锁”，通知生产者可以再次生产
            falg = true ;
        }
        // else { usleep(1); } // 实际应用中，忙等会空耗CPU，应使用 sleep 或条件变量
    }
}


int main(int argc, char const *argv[])
{
    // 作为共享资源
    int Num = 0 ;

    pthread_t  tid  ;
    // 1. 创建线程，立即返回。myTask 和 main 开始并发执行
    pthread_create( &tid , NULL , myTask ,  (void *)&Num );

    // 设置随机种子
    // 把当前时间作为种子（计算的起始值）
    srand(time(NULL));

    /*
     * 主线程任务（生产者）
     */
    while (1)
    {
        // 2. 检查“锁”是否为 true (轮询，忙等)
        //    意味着消费者已经消费完毕，轮到生产者了
        if (falg == true)
        {
            // 3. 生产资源：生成一个随机数
            Num = rand() % 1000  ;
            
            // 4. 释放“锁”，通知消费者可以消费
            falg = false ;
        }
        // else { usleep(1); }
    }
    
    return 0; // 实际走不到这里
}
```



## 2.3 线程的退出



与进程类似，当一条线程执行完其任务时，可以使用如下接口退出。

- **函数原型**

  C

  ```
  #include <pthread.h>
  
  void pthread_exit(void *retval);
  ```

- 作用

  终止当前的调用线程，并返回一个retval值，这个值可以被其他接合（join）该线程的线程获取。

- **参数详解**

  - `retval`：一个 `void*` 指针，作为线程的**返回值**。
  - **重要**：`retval` **不能**指向一个**位于该线程栈上**的局部变量。因为线程退出时，其私有栈会立即被销毁，这将导致一个悬空指针。通常，`retval` 指向一个全局变量、静态变量，或是在堆上 `malloc` 的内存。

- **`pthread_exit()` vs `exit()`**

  - `pthread_exit(NULL);`：仅退出**当前线程**。进程中的其他线程继续运行。
  - `exit(0);`：退出**整个进程**，即终结进程中的所有线程。



## 2.4 线程的接合



与进程退出后会留下“僵尸进程”类似，线程退出后，其占有的部分系统资源（如线程ID、退出状态）不会立即释放。它会成为一个**“僵尸线程” (Zombie Thread)**。

其他线程必须调用 `pthread_join()` 来**接合**（reap）这个已退出的线程，以释放其剩余资源，并获取其退出时返回的值。该接口函数也被称为线程的接合函数。

- **函数原型**

  C

  ```
  #include <pthread.h>
  
  int pthread_join(pthread_t tid, void **val); //
  ```

- 作用

  阻塞（等待），直到 tid 所指定的线程终止。

- **参数详解**

  - `tid`：要等待的目标线程的 ID。
  - `val`：一个**输出参数**（二级指针）。如果 `val` 不为 `NULL`，`pthread_join` 会将目标线程通过 `pthread_exit()` 或 `return` 返回的 `void*` 值，存入 `val` 指向的位置。

- **接口说明**

  1. 若指定 `tid` 的线程尚未退出，那么 `pthread_join` 将**持续阻塞**。
  2. 若只想阻塞等待 `tid` 退出，而不想获取其返回值，那么 `val` 可置为 `NULL`。
  3. 若 `tid` 线程处于分离状态 (Detached)，或不存在，则 `pthread_join` 会出错返回。

------



### 其他接合接口



`pthread_join` 是永久阻塞的。GNU C 库 (glibc) 还提供了一些扩展的 `_np` (non-portable, 非可移植) 接口，允许非阻塞或超时接合。

- **函数原型**

  C

  ```
  #define _GNU_SOURCE // 必须定义此宏才能使用
  #include <pthread.h>
  
  // 尝试接合，不阻塞
  int pthread_tryjoin_np(pthread_t thread, void **retval);
  
  // 在指定的时间点(绝对时间)前阻塞等待
  int pthread_timedjoin_np(pthread_t thread, void **retval,
                           const struct timespec *abstime);
  ```

- **`pthread_tryjoin_np`**：非阻塞版本。如果 `thread` 尚未终止，该函数立即返回 `EBUSY` 错误，而不是阻塞。

- **`pthread_timedjoin_np`**：超时等待版本。`abstime` 指定的是一个**绝对时间**（从 1970-01-01 至今的时刻），而不是一个时间段（如“等待5秒”）。如果到了 `abstime` 时刻 `thread` 仍未退出，则函数返回 `ETIMEDOUT` 错误。



### 示例代码：接合的三种模式



此代码演示了 `pthread_join`（阻塞）、`pthread_tryjoin_np`（非阻塞）和 `pthread_timedjoin_np`（超时）的用法。

C

```
#define _GNU_SOURCE  // 必须在 include 之前定义，以启用 _np 函数
#include <stdio.h>
#include <pthread.h>
#include <unistd.h>
#include <errno.h>   // 用于 perror
#include <time.h>    // 用于 time() 和 struct timespec

#define BLOCKING     0
#define NON_BLOCKING 0
#define TIME_OUT     1 // 切换这三个宏的值 (0 或 1) 来测试不同模式

void * MyTask(void * arg) 
{
    // 工作线程..........
    printf("工作线程开始，预计耗时12秒...\n");
    sleep(12);

    // 关键：Num 必须是 static (静态) 或 global (全局) 或 heap (堆)
    // 如果是普通的 'int Num = 123;'，它在线程栈上，
    // 线程退出时栈被销毁，main中得到的将是悬空指针。
    static int Num = 123 ;

    printf("myTask 退出，返回值地址:%p\n" , &Num) ;

    // 返回工作结果
    // return &Num ;  // return 效果与 pthread_exit 相同
    pthread_exit(&Num); // 结束线程
}

int main(int argc, char const *argv[])
{
    pthread_t tid ;
    pthread_create( &tid , NULL , MyTask , NULL );

    int *ret ; // 用于接收线程的返回值
    int err;   // 用于接收 join 函数的返回值

#if BLOCKING
    /********** 1. 阻塞等待 **************/
    printf("Main: 使用 pthread_join() 阻塞等待...\n");
    // 阻塞等待线程退出
    err = pthread_join(tid, (void **)&ret );
    if (err == 0) {
        printf("Main: 成功接合！\n");
    } else {
        printf("Main: 接合失败，错误码: %d\n", err);
    }

#elif NON_BLOCKING
    /********** 2. 非阻塞 **************/
    printf("Main: 使用 pthread_tryjoin_np() 非阻塞尝试...\n");
    sleep(1); // 睡1秒，确保 MyTask 正在运行
    
    // 非阻塞接合，此时 MyTask (睡12秒) 肯定还没退出
    // err 会被设置为 EBUSY (Resource temporarily unavailable)
    err = pthread_tryjoin_np(tid , (void **)&ret  );
    
    // 使用 errno 全局变量是错误的，pthread 函数不设置它
    // 应该检查返回值 err
    // perror(" join error "); // 错误用法
    
    if (err == EBUSY) {
        printf("Main: 尝试接合失败，目标线程仍在运行 (EBUSY)\n");
    } else {
        printf("Main: 尝试接合结果: %d\n", err);
    }
    
    // (为了让程序能正常结束，我们在这里再阻塞等一次)
    pthread_join(tid, (void **)&ret);


#elif TIME_OUT
    /********** 3. 在限定时间内阻塞等待 **************/
    printf("Main: 使用 pthread_timedjoin_np() 超时等待 (2秒)...\n");
    
    // 定义绝对时间结构体
    struct timespec abstime;
    
    // 1. 获取当前系统的秒级时间 (绝对时间)
    abstime.tv_sec = time(NULL);
    printf("当前时间: %ld\n" , abstime.tv_sec );
    
    // 2. 在当前时间上加2秒，作为“超时时刻”
    abstime.tv_sec += 2 ;
    abstime.tv_nsec = 0; // 纳秒设为0
    printf("超时时刻: %ld\n" , abstime.tv_sec );
    
    // 3. 等待接合，直到 abstime 时刻
    // MyTask 要睡12秒，所以这个函数必定在2秒后超时
    err = pthread_timedjoin_np(tid , (void **)&ret  , &abstime);
    
    if (err == ETIMEDOUT) {
        printf("Main: 等待超时 (ETIMEDOUT)！\n");
    } else {
         printf("Main: 接合结果: %d\n", err);
    }

    // (为了让程序能正常结束，我们在这里再阻塞等一次)
    pthread_join(tid, (void **)&ret);

#endif

    printf("Main: 最终获取的返回值地址:%p\n" , ret) ;
    if (ret != NULL) {
        printf("Main: 获取的返回值内容: %d\n", *ret);
    }

    return 0;
}
```



# 3. 关于多线程编译的问题



在某些环境下（尤其是在编译链接时），如果代码中使用了 `pthread` 库函数（如 `pthread_create`），可能会遇到链接错误，提示**“undefined reference to ...”**（未定义的引用）。

Bash

```
$ gcc 02\\ 线程的退出与接合.c
/tmp/cc59vokO.o: In function `main':
...: undefined reference to `pthread_create'
...: undefined reference to `pthread_timedjoin_np'
collect2: error: ld returned 1 exit status
```

- 原因分析

  这是因为 pthread 相关的函数不在标准 C 库 (libc.so)中，它们被实现在一个单独的共享库——libpthread.so 中。

  编译（Compile）阶段可以找到头文件 `<pthread.h>`，所以不报错；但在链接（Link）阶段，链接器 `ld` 默认只链接 `libc`，找不到 `pthread_create` 等函数的实现，因此报错。

- 解决方案

  在 gcc 编译链接时，必须手动链接线程库，方法是增加 -lpthread 选项（l 表示 link，pthread 是库名）。

  Bash

  ```c
  $ gcc 02\\ 线程的退出与接合.c -lpthread
  $ ./a.out 
  (程序正常运行)
  ```
