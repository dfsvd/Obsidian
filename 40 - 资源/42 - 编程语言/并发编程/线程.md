# 线程概念

线程是操作系统中一个轻量级的执行单元。在 Linux 内核中，所有的调度实体（包括进程和线程）都被称为**任务 (task)**。

线程与进程的核心区别在于资源所有权：

- **进程（Process）**：是资源分配的基本单位。它拥有**一整套完整的、独立的资源**，例如独立的虚拟地址空间、文件描述符表和全局变量。
- **线程（Thread）**：是 CPU 调度的基本单位。一个进程可以包含多个线程，这些线程**共享**其所属进程的大部分资源，但仍然拥有少量**独占**的资源。

**资源共享与私有**

- **共享资源**：
  - **虚拟地址空间**：所有线程共享同一份代码段、数据段、堆（Heap）等。这意味着线程间可以直接读写全局变量和堆上分配的数据，无需像进程间通信（IPC）那样复杂。
  - **文件描述符表**：一个线程打开的文件，其他线程也可以读写。
- **私有资源**：
  - **线程ID (TID)**：每个线程都有一个唯一的标识符。
  - **栈空间 (Stack)**：每个线程都有自己**独立**的栈，用于存储自己的局部变量、函数参数和返回地址。
  - **寄存器 (Registers)**：包括程序计数器 (PC) 和栈指针 (SP)，用于追踪各自的执行位置。
  - `errno` 变量：每个线程有自己的 `errno` 副本，防止相互干扰。

这种“轻量级”的设计使得线程的创建、切换和通信开销远小于进程，使其成为实现并发（Concurrency）的首选模型。

# 基本接口

## 线程的创建 `pthread_create()`

`pthread_create` 函数用于在当前进程中创建一个新的线程。

- **函数原型**

  ```c
  #include <pthread.h>
  
  int pthread_create(pthread_t *thread, 
                     const pthread_attr_t *attr,
                     void *(*start_routine) (void *), 
                     void *arg);
  ```

- **作用**

  创建一个新的执行流（线程），该线程将从 `start_routine` 函数开始执行。

- **参数详解**

  - `thread`：一个**输出参数**。它指向一个 `pthread_t` 类型的变量，函数成功时，会将新创建线程的 **TID**（线程ID）写入此变量。
  - `attr`：指向线程属性对象的指针。用于设置新线程的各种属性（如栈大小、调度策略等）。如果传入 `NULL`，则表示使用**默认属性**。
  - `start_routine`：一个**函数指针**。这是新线程的入口点，即线程创建后要执行的**任务函数**。该函数必须接受一个 `void *` 类型的参数，并返回一个 `void *` 类型的值。
  - `arg`：传递给 `start_routine` 函数的参数。如果你需要传递多个参数，应将它们封装在一个结构体中，再将该结构体的地址（强制转换为 `void *`）作为 `arg` 传入。

- **返回值**

  - **成功**：返回 `0`。
  - **失败**：返回一个非零的**错误码**（注意：Pthreads 函数失败时通常不设置 `errno`，而是直接返回错误码）。

## 并发性

线程最重要的特性是**并发 (Concurrency)**。

这与普通函数的**串行 (Serial)** 调用有着本质区别。一个普通的函数调用（例如 `doSomething()`），`main()` 函数必须等待它执行完毕才能继续。

但当 `pthread_create()` 创建一个新线程来执行 `myTask()` 时，`main()` 函数**不会等待**，而是会**同时**（或在操作系统调度下，在宏观上同时）与 `myTask()` 一起运行。

### 竞态条件 (Race Condition)

正是由于这种并发性，当多个线程（例如 `main` 线程和 `myTask` 线程）访问**共享资源**时，必须格外小心。

如果不对访问进行控制，多个线程就会“争抢”该资源，其最终结果取决于线程执行的**时序**（谁先谁后），这就形成了**竞态条件 (Race Condition)**。

最典型的共享资源就是全局变量，或如此例中在线程间共享地址的 `Num` 变量。竞态条件会导致程序逻辑混乱、数据损坏，是并发编程中最棘手的问题。因此，访问共享资源的代码区域（称为“临界区”）必须受到保护，以确保“线程安全”。

### 示例代码

```c
#include <stdio.h>
#include <pthread.h>
#include <stdlib.h>
#include <stdbool.h>
#include <time.h> // 用于 srand
#include <unistd.h> // 假设需要 usleep

// fale (false) 表示可以判断奇偶    （资源可读）
// true 表示可以修改共享资源 （资源可写）
bool  falg = true; // 全局变量，作为共享资源

// 共享资源（在 main 栈上，但地址被共享）
int Num = 0 ;

// 消费者线程：等待 flag 变为 false，然后读取 Num
void *myTask (void * arg )
{
    // ptr 指向了 main 线程栈上的 Num
    int * ptr = (int *)arg ;

    while (1)
    {
        /**
         * 3. 消费者检查标志位
         * 这是一个“忙等”（Busy-Waiting）或“轮询”（Polling）
         * 当 falg 为 true 时，这个循环会空转，消耗 CPU
         */
        if (falg == false)
        {
            // 4. falg 变为 false，轮到自己工作
            if ( *ptr % 2 )
            {
                printf("[%d]是一个奇数\n" , *ptr );
            }
            else{
                printf("[%d]是一个偶数\n" , *ptr );
            }
            // 5. 工作完成，将标志位设置回 true，通知 main 线程
            falg = true ; 
        }   
    }
}


int main(int argc, char const *argv[])
{
    pthread_t  tid  ;
    // 1. 创建线程，myTask 开始并发执行
    //    将 main 栈上 Num 变量的地址作为参数传递
    pthread_create( &tid , NULL , myTask ,  (void *)&Num );

    srand(time(NULL));

    while (1)
    {
        /**
         * 2. 生产者检查标志位
         * 同样是“忙等”
         */
        if (falg == true)
        {
            // 6. falg 变为 true，轮到自己工作
            //    产生一个 0-999 的随机数并写入共享变量 Num
            Num = rand() % 1000  ;
            // 7. 工作完成，将标志位设置为 false，通知 myTask 线程
            falg = false ;
        }
    }
    
    return 0;
}
```

- **代码分析**：
  1. **并发模型**：此代码实现了一个简单的“生产者-消费者”模型。`main` 线程扮演“生产者”（写入`Num`），`myTask` 线程扮演“消费者”（读取`Num`）。
  2. **同步机制（“忙等”）**：代码使用 `falg` 标志位，试图实现一种“交替”访问的同步。但两个 `while(1)` 循环都在**空转 CPU** 来检查 `falg` 的值。这是一种**效率极低**的同步方式，在线程等待时会占满 CPU 资源。
  3. **潜在风险（内存可见性）**：在现代多核 CPU 上，由于编译器优化（指令重排）和 CPU 缓存（缓存一致性问题），一个 CPU 核心对 `falg` 变量的修改可能不会被另一个核心**立即**看到。这可能导致数据不同步或死锁。
  4. **结论**：这种使用普通 `bool` 变量的同步方式**不是线程安全**的，且效率低下。专业的并发控制应使用操作系统提供的**互斥锁 (Mutex)** 和**条件变量 (Condition Variable)**，它们能实现高效的“阻塞-唤醒”机制，而不是“忙等”。

## 线程的退出 `pthread_exit()`

`pthread_exit` 用于显式地终止调用它的线程。

- **函数原型**

  ```c
  #include <pthread.h>
  
  void pthread_exit(void *retval);
  ```

- **作用**

  终止当前线程，并指定一个返回值 `retval`，这个值可以被其他接合（join）该线程的线程获取。

- **参数详解**

  - `retval`：一个 `void *` 类型的指针，指向线程的退出状态（返回值）。
  - **重要**：`retval` **不应该**指向一个在线程栈上分配的**局部变量**。因为线程退出时，其栈空间会被立即销毁，导致该指针变为“野指针”。
  - **正确做法**：可以返回一个指向**全局变量**、**静态变量 (static)**或**堆内存**（`malloc` 分配）的指针。

- **`pthread_exit()` vs `return` vs `exit()`**

  - **在 `start_routine` 中**：`return value;` 的效果与 `pthread_exit(value);` **几乎相同**。
  - **在 `main` 函数中**：`return` 或 `exit()` 会导致**整个进程**（包括其所有线程）立即终止。而 `pthread_exit()` 只会终止主线程，进程会继续存在，直到所有其他子线程都退出。

## 线程的接合

线程退出后，会保留其退出状态等资源（成为“僵尸线程”）。`pthread_join` 函数用于**阻塞**等待一个指定线程的终止，并回收其资源。

- **函数原型 `pthread_join()`**

  ```
  #include <pthread.h>
  
  int pthread_join(pthread_t tid, void **retval);
  ```

- **`pthread_join` 作用与参数**

  - **作用 1 (等待)**：调用 `pthread_join` 的线程会**阻塞（挂起）**，直到 `tid` 指定的目标线程终止。
  - **作用 2 (回收)**：成功“接合”后，`pthread_join` 会**回收**目标线程的所有资源。这类似于进程的 `waitpid` 回收僵尸进程。
  - `tid`：要等待的目标线程的 ID。
  - `retval`：一个**输出参数**，它是“指针的指针”。用于存储目标线程返回的 `void *` 类型的退出值。如果不需要获取返回值，可以传入 `NULL`。

- **其他接合接口 (非标准，需 `_GNU_SOURCE`)**

  - `pthread_tryjoin_np(tid, &retval)`：**非阻塞**版本。如果目标线程仍在运行，它立即返回 `EBUSY` 而不是阻塞。
  - `pthread_timedjoin_np(tid, &retval, &abstime)`：**限时阻塞**版本。它会阻塞等待，直到目标线程退出，或者 `abstime` 指定的**绝对时间**（注意：不是“等待5秒”，而是“等到 xx:xx:05 秒”）超时。



### 示例代码

```c
#define _GNU_SOURCE 
#include <stdio.h>
#include <pthread.h>
#include <unistd.h>
#include <errno.h>
#include <time.h> // time()

// 定义宏来切换三种 join 模式
#define BLOCKING  0
#define NON_BLOCKING 0
#define TIME_OUT 1 // 我们测试 TIME_OUT 模式

void * MyTask(void * arg) 
{
    printf("子线程：开始工作，预计耗时 12 秒...\n");
    sleep(12);

    /**
     * 关键点：使用 static
     * 如果 Num 是普通局部变量 (int Num = 123)，
     * 它在 MyTask 返回时栈空间被销毁，主线程会拿到一个野指针。
     * 使用 static，Num 存储在全局/静态数据区，在函数退出后依然存在。
     */
    static int Num = 123 ;

    printf("子线程：工作完成。myTask 中 Num 的地址是: %p\n" , &Num) ;

    // 返回工作结果
    // return &Num ;  // 效果同下
    pthread_exit(&Num); // 显式地结束线程，并返回 Num 的地址
}

int main(int argc, char const *argv[])
{
    pthread_t tid ;
    pthread_create(  &tid , NULL , MyTask , NULL );

    int *ret = NULL; // 用于接收子线程返回的指针

#if BLOCKING
    /********** 1. 阻塞等待 **************/
    printf("Main: 使用 pthread_join() 阻塞等待...\n");
    // 阻塞等待线程退出 (会等待 12 秒)
    pthread_join(tid, (void **)&ret );
    printf("Main: 子线程已退出。\n");

#elif NON_BLOCKING
    /********** 2. 非阻塞 **************/
    printf("Main: 使用 pthread_tryjoin_np() 非阻塞尝试...\n");
    // 循环尝试接合
    int join_ret = 0;
    while ( (join_ret = pthread_tryjoin_np(tid , (void **)&ret)) == EBUSY ) 
    {
        // 如果返回 EBUSY，说明子线程还在运行
        printf("Main: tryjoin 失败 (EBUSY)，1 秒后再试...\n");
        sleep(1);
    }
    // 成功时 join_ret 为 0
    printf("Main: tryjoin 最终状态码: %d\n", join_ret);

#elif TIME_OUT
    /********** 3. 在限定时间内阻塞等待 **************/
    printf("Main: 使用 pthread_timedjoin_np() 限时等待...\n");
    struct timespec abstime;
    // 1. 获取当前时间
    abstime.tv_sec = time(NULL);
    abstime.tv_nsec = 0; // 纳秒必须初始化

    // 2. 设置 5 秒后的“绝对时间点”作为超时
    abstime.tv_sec += 5 ;
    
    printf("Main: 当前时间 %ld, 等待到 %ld\n" , time(NULL) , abstime.tv_sec );

    // 在 5 秒内阻塞等待
    int join_ret = pthread_timedjoin_np(tid , (void **)&ret  , &abstime);

    if (join_ret == ETIMEDOUT) {
        printf("Main: 等待 5 秒超时 (ETIMEDOUT)！子线程还在运行。\n");
        ret = NULL; // 超时未获取到
    } else {
        printf("Main: 在 5 秒内接合成功。\n");
    }

#endif

    // 检查是否成功获取到返回值
    if (ret != NULL) {
        printf("Main: 成功获取到子线程的返回值: %d, 地址是: %p\n" , *ret, ret) ;
    } else {
        printf("Main: 未获取到返回值 (可能超时或失败)。\n");
    }

    // 最终清理：
    // 如果是 TIME_OUT 模式且超时了，子线程仍在运行。
    // 调用一个阻塞的 join 确保子线程结束，避免 main 退出导致子线程被强行终止
    pthread_join(tid, NULL); 
    printf("Main: 退出。\n");

    return 0;
}
```

- **代码分析**：
  1. **安全返回值**：代码非常正确地使用了 `static int Num` 来确保返回给 `main` 线程的指针是有效的。
  2. **`BLOCKING` 模式**：`main` 线程会卡在 `pthread_join` 处，直到 `MyTask` 的 12 秒 `sleep` 结束并退出。
  3. **`NON_BLOCKING` 模式**：`main` 线程会立即调用 `pthread_tryjoin_np`，因 `MyTask` 还在 `sleep`，调用会失败并返回 `EBUSY`。`while` 循环会每隔 1 秒重试一次，直到 12 秒后 `MyTask` 退出，`pthread_tryjoin_np` 成功返回 `0`。
  4. **`TIME_OUT` 模式**：`main` 线程会阻塞在 `pthread_timedjoin_np`。
     - 它设置了 5 秒的**绝对时间**超时。
     - `MyTask` 需要 12 秒。
     - 因此，5 秒后 `pthread_timedjoin_np` 会因超时（`ETIMEDOUT`）而返回，此时 `ret` 不会被赋值。

# 关于多线程库的链接

在使用 `pthread_create` 或 `pthread_join` 等 Pthreads API 时，仅仅 `#include <pthread.h>` 是不够的。

- **问题**：Pthreads 库（POSIX 线程库）并不是标准 C 库 (`libc`) 的一部分。它是一个**单独的动态链接库** (`libpthread.so`)。

- **现象**：如果尝试像编译普通 C 程序一样（例如 `gcc test.c`），编译器（`gcc`）在最后**链接**阶段会找不到这些函数的定义，从而报错：


```bash
  /tmp/cc59voKO.o: In function `main':
  test.c:(.text+0x69): undefined reference to `pthread_create'
  test.c:(.text+0xc6): undefined reference to `pthread_timedjoin_np'
  collect2: error: ld returned 1 exit status
```





  - `undefined reference to ...` 是典型的链接错误，意味着链接器（`ld`）在所有指定的库中都找不到该函数的实现。

- **解决方案**： 必须在 `gcc` 编译时，使用 `-l` 标志显式地告诉链接器去链接 `libpthread` 库。


  # 错误
  gcc 线程的退出与接合.c
  
  # 正确 (必须添加 -lpthread)
  gcc 线程的退出与接合.c -lpthread


  - `-l`：是链接器选项，表示“链接库 (Link Library)”。
  - `pthread`：是库的名字（`libpthread.so` 的缩写）。

# 其他接口

## 检测文件的权限 `access()`



`access` 函数用于检查调用进程（real user ID, RUID）对指定文件是否具有特定的访问权限，或文件是否存在。

- **函数原型**


  #include <unistd.h>

  int access(const char *pathname, int mode);


- **作用**

  检查调用进程对 `pathname` 指向的文件的访问能力。这在执行 `exec` 系列函数前，或在以特定方式打开文件前，用来预先判断操作是否可行非常有用。

- **参数详解**

  - `pathname`：需要检测的目标文件的路径名。
  - `mode`：需要检测的目标权限。这是一个位掩码，可以通过以下一个或多个常量的“按位或” (`|`) 组合而成：
    - **`R_OK`**：测试文件是否**可读**。
    - **`W_OK`**：测试文件是否**可写**。
    - **`X_OK`**：测试文件是否**可执行**。
    - **`F_OK`**：测试文件**是否存在**。

- **返回值**

  - **成功**：返回 `0`。表示所有请求的权限都已通过。
  - **失败**：返回 `-1`，并设置 `errno` 来指示错误原因（例如 `EACCES` 表示权限不足，`ENOENT` 表示文件不存在）。

# 线程的属性

`pthread_create` 的第二个参数 `attr` 允许我们对新线程的行为进行精细控制。由于线程属性众多，Pthreads 库采用了一个“属性对象”(`pthread_attr_t`) 的机制：

1. 我们不直接将分离状态、栈大小等几十个参数传给 `pthread_create`。
2. 而是先创建一个统一的**属性变量（`pthread_attr_t`）**。
3. 然后通过专门的 `pthread_attr_set...` 系列函数将所需属性（如“设置为分离”）“添加”到这个属性变量中。
4. 最后再将这个**配置好**的属性变量传递给 `pthread_create`。

## 线程属性概览

线程的属性种类繁多，Pthreads 库提供了一一对应的 `get`（获取）和 `set`（设置）函数来操作它们。

以下是常用属性及其操作函数：

| **属性功能** | **获取属性 API**                 | **设置属性 API**                 |
| ------------ | -------------------------------- | -------------------------------- |
| **分离属性** | `pthread_attr_getdetachstate()`  | `pthread_attr_setdetachstate()`  |
| 栈警戒区大小 | `pthread_attr_getguardsize()`    | `pthread_attr_setguardsize()`    |
| 继承调度策略 | `pthread_attr_getinheritsched()` | `pthread_attr_setinheritsched()` |
| 调度策略     | `pthread_attr_getschedpolicy()`  | `pthread_attr_setschedpolicy()`  |
| 调度参数     | `pthread_attr_getschedparam()`   | `pthread_attr_setschedparam()`   |
| 竞争范围     | `pthread_attr_getscope()`        | `pthread_attr_setscope()`        |
| CPU 亲和度   | `pthread_attr_getaffinity_np()`  | `pthread_attr_setaffinity_np()`  |
| 栈地址和大小 | `pthread_attr_getstack()`        | `pthread_attr_setstack()`        |
| 栈大小       | `pthread_attr_getstacksize()`    | `pthread_attr_setstacksize()`    |

- **核心属性解析：分离属性 (Detach State)**
  - 这是最重要的属性之一。它决定了线程终止时的资源回收方式。
  - **`PTHREAD_CREATE_JOINABLE`** (默认)：线程是“可接合”的。线程终止后，其资源（如 TID、退出状态）将**被保留**，直到另一个线程调用 `pthread_join()` 来“接合”它（即回收资源）。
  - **`PTHREAD_CREATE_DETACHED`** (分离)：线程是“分离”的。线程一旦终止，其所有资源将**立即被系统自动回收**。你**不能**（也**不需要**）对一个分离的线程调用 `pthread_join()`。

## 属性变量的使用



操作属性变量必须遵循“初始化 -> 设置 -> 销毁”的生命周期。

- **函数原型：初始化与销毁**


  #include <pthread.h>

  int pthread_attr_init(pthread_attr_t *attr);
  int pthread_attr_destroy(pthread_attr_t *attr);


- **`pthread_attr_init()`**：

  - **作用**：初始化 `attr` 属性对象。在调用 `init` 后，`attr` 会被填充为一套**默认**的属性值（例如，默认属性是 `PTHREAD_CREATE_JOINABLE`）。

- **`pthread_attr_destroy()`**：

  - **作用**：销毁 `attr` 属性对象，释放其可能占用的资源。`destroy` **不**影响已经使用此 `attr` 创建的线程，它只释放 `attr` 变量本身。

- **线程属性的标准使用步骤：**

  1. **定义变量**：`pthread_attr_t attr;`
  2. **初始化**：`pthread_attr_init(&attr);`
  3. **设置属性**：通过 `pthread_attr_set...()` 函数将所需属性（例如 `PTHREAD_CREATE_DETACHED`）设置到 `attr` 中。
  4. **启动线程**：使用此 `attr` 启动线程：`pthread_create(&tid, &attr, ...);`
  5. **销毁属性**：在所有使用 `attr` 的 `pthread_create` 调用完成后，立即销毁该属性对象：`pthread_attr_destroy(&attr);`

## 示例代码


#include <stdio.h>
#include <pthread.h>
#include <stdlib.h>
#include <unistd.h>
#include <errno.h>


void* TaskFunc(void * arg )
{
    printf("子线程: 启动，休眠 2 秒后自动退出...\n");
    sleep(2);
    printf("子线程: 退出。\n");

    // 线程退出时，由于是 DETACHED 状态，资源将自动回收
    pthread_exit(NULL);
}

int main(int argc, char const *argv[])
{
    // 1. 定义属性变量
    pthread_attr_t attr;

    // 2. 初始化属性变量（载入默认值）
    pthread_attr_init(&attr);

    /**************设置需要的属性到 attr 中****************/

    // 3. 添加分离属性
    pthread_attr_setdetachstate(&attr, PTHREAD_CREATE_DETACHED );

    // 3. (可选) 设置调度策略为轮转 (Round-Robin)
    // pthread_attr_setschedpolicy(&attr , SCHED_RR );
    
    // 4. 使用配置好的属性变量启动线程
    pthread_t tid ;
    pthread_create( &tid , &attr , TaskFunc , NULL );

    // 5. 销毁属性变量 (不再需要它了)
    pthread_attr_destroy(&attr);

    // 尝试接合一个“分离”线程
    errno = pthread_join(tid , NULL) ;
    if (errno == 0)
    {
        printf("Main: 成功接合线程。\n");
    }
    else{
        /* * 设置分离属性后，join 函数会立即返回错误。
         * 常见的错误码是 EINVAL (Invalid argument)，
         * 因为该 tid 对应的线程不可接合。
         */
        fprintf(stderr, "Main: join error (code: %d) - ", errno);
        perror("Join error reason");
    }
    
    /**
     * 保持主线程存活。
     * 如果主线程在此处退出，整个进程将终止，
     * 正在运行的 TaskFunc 线程也会被强行终止。
     * pause() 使主线程挂起，等待信号。
     */
    while(1)
    {
        printf("Main: 存活，等待子线程...\n");
        sleep(1);
    }

    return 0;
}

- **代码分析**：

  1. **设置分离**：`pthread_attr_setdetachstate` 是核心。它告诉 `pthread_create`，这个新线程“无需接合”。
  2. **Join 失败**：正因为线程是分离的，`pthread_join` 无法等待它，而是立即失败并返回错误码。`perror` 将打印出类似 "Join error reason: Invalid argument" 的信息，这完全符合预期。
  3. **主线程存活**：`while(1)` 循环（或 `pause()`）在此处是**必需的**。如果 `main` 函数在 `pthread_join` 失败后直接 `return 0;`，整个进程会立即退出，那个正在 `sleep(2)` 的子线程也会被强行杀死，根本没有机会执行完毕。主线程的存活保证了进程地址空间的存在，让子线程可以完整运行并自动退出。

- 另一种分离方式 pthread_detach()

  如果你创建了一个**默认的（JOINABLE）**线程，但随后又决定不需要接合它，你可以使用 `pthread_detach()`：


  pthread_t tid;
  // 1. 创建一个默认的 (JOINABLE) 线程
  pthread_create(&tid, NULL, TaskFunc, NULL);

  // 2. 立即将其“分离”
  // 这告诉系统：“我不打算 join 它了，它结束后请自动回收资源”
  pthread_detach(tid);

  // 3. 此时再调用 pthread_join(tid, NULL) 同样会失败
