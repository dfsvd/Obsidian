## 基础概念
### 进程

- 进程是程序的一次**动态**执行实例它是操作系统进行**资源分配和保护**的基本单位
- **属性**
  - 动态性：有其生命周期（创建、运行、等待、终止）
  - 资源所有权 ：作系统会为每个进程分配一个独立的**虚拟地址空间**
  - 隔离性 : 进程之间默认是严格隔离的，一个进程无法直接访问另一个进程的内存空间
- 类比
  - 舞台
  - 进程是**动态的**，是“剧本活了”当你运行程序（剧本）时，操作系统就搭起了一个舞台（进程）

### 线程

-  线程是**进程内**的一个执行流它是操作系统进行**CPU 调度**（分派）的基本单位
- **属性：**
  - **执行单元：** 线程是 CPU 真正执行指令的实体
  - **上下文 ：** 每个线程拥有自己独立的**执行上下文**
    - 程序计数器 (Program Counter, PC)
    - 寄存器组 (Register Set)
    - 栈 (Stack)（用于存储局部变量和函数调用）
  - **资源共享：** 同一个进程内的所有线程**共享**该进程的绝大部分资源
- 类比
  - 舞台上的演员
  -  线程是**真正干活的**（执行的）一个舞台（进程）至少要有一个演员（主线程）才能开演

### 程序

- 程序是一个**静态**的实体它是一组有序的指令（代码）和相关数据的集合，通常以可执行文件的形式存储在二级存储（如硬盘）上
- **属性：**
  - **被动性：** 程序本身不执行任何操作它只是一个文件
  - **静态性：** 它的内容在执行前是固定不变的
- 类比
  - 剧本
  - 程序是**静态的**详细描述了故事的每一步、需要哪些角色，但它自己躺在那里，什么也不会发生它是一种“死的”资源

### 总结

#### 核心对比

- **单位区分：** 进程是**资源分配**的最小单位；线程是 **CPU 调度**的最小单位

- **开销：**

  - **进程：** 资源消耗更大，创建和切换的开销都很大（搭一个新舞台很贵）
  - **线程：** 共享同一套资源，开销小（在同一个舞台上多请个演员很便宜）

- **稳定性：**

  - **进程：** 内存隔离，相对独立稳定，一个进程崩溃（舞台A塌了）不会直接影响另一个进程（舞台B）
  - **线程：** 共享内存，一个线程的异常操作（演员A把道具砸了）可能导致整个进程（整个舞台）崩溃

- **通信：**

  - **进程：** 需通过复杂的 IPC（进程间通信）机制（跨舞台喊话）

  - **线程：** 共享资源，数据传输（演员间递个眼神）简单，但也因此需要处理同步和互斥问题

    

#### 调度关系（多线程/多进程）

不管是进程还是线程，只要是并发，我们都需要处理好任务间的调度关系：

- **同步：**
  - **问题：** 解决“排队”问题
  - **定义：** 并发的任务与任务之间有**明确的先后顺序**
  - 例子：演员A必须说完台词，演员B才能接话
- **互斥：**
  - **问题：** 解决“抢占”问题
  - **定义：** 并发的任务与任务之间**不能同时做某一个操作**（访问同一个资源）
  - 例子：舞台中央的唯一聚光灯，同一时间只能给一个演员

## 进程详解

### 进程的组织方式

### 进程的创建：复刻 (fork)

在 Linux/Unix 系统中，除了那个“老祖宗”进程（`init` 或 `systemd`），所有新进程的创建都不是“平地而起”，而是通过 `fork()` 系统调用**复刻**出来的

这个过程就像细胞分裂，一个父进程（Parent）分裂出一个几乎一模一样的子进程（Child）

![](images/1.%20基础概念/file-20251116224949885.jpg)

- **“复刻”了什么**
  - **身份和环境：** 实际用户 ID (UID)、组 ID (GID)、环境变量、当前工作路径
  - **内存空间：** 整个虚拟地址空间，包括代码段、数据段、堆、栈等
    - **注意：** 现代系统很聪明，不会真的去复制所有内存它们使用一种叫*写时复制*的技术父子进程一开始共享同一份物理内存，只有当其中一个*试图写入*内存时，系统才会为它复制那“一小块”被修改的内存
  - **打开的文件：** 父进程在 `fork` 之前打开的所有文件描述符
    - **重点：** 子进程继承的是**打开的文件状态**这意味着如果父进程打开了一个文件，子进程和父进程会共享同一个文件偏移量（就是那个“光标”位置）
- **“变异”了什么**
  - **进程 ID (PID)：** 这是最关键的区别子进程会获得一个**全新的、唯一的 PID**父进程的 `fork()` 调用会返回子进程的 PID，而子进程的 `fork()` 调用会返回 0，这就是它们用来区分“谁是谁”的办法
  - **文件锁：** 父进程设置的文件锁，子进程不会继承
  - **挂起的信号：** 正在等待父进程处理的信号（“待决信号”）不会被子进程继承


### 进程的状态——生命周期

进程在其生命周期中会在不同状态间切换经典的模型将其归纳为“三态”和“五态”

#### 经典三态模型

这是最基础的划分，包含进程运行的核心循环：

- **运行态 (Running)**
  - **定义：** 进程**正在** CPU 上执行
- **就绪态 (Ready)**
  - **定义：** 万事俱备，只欠 CPU进程在就绪队列中排队，等待被调度
- **阻塞态 (Blocked / Waiting)**
  - **定义：** 进程因**等待**某个事件（如 I/O 操作、`sleep`、等待信号）而主动让出 CPU

![](images/1.%20基础概念/file-20251116225037300.jpg)

#### 经典五态模型

是三态模型的扩展，更完整地描述了从“出生”到“死亡”的全过程：

- **新建态 (New)**
  - **定义：** 进程刚被 `fork()` 创建，操作系统正在为其分配资源和初始化
- **就绪态 (Ready)**
  - **定义：** 同三态模型在队列里排队等 CPU
- **运行态 (Running)**
  - **定义：** 同三态模型正在 CPU 上执行
- **阻塞态 (Blocked / Waiting)**
  - **定义：** 同三态模型等待某个事件
- **终止态 (Terminated)**
  - **定义：** 进程执行完毕，正在等待父进程回收或已被回收
  - 这是两个阶段的总和：
    - **僵尸态 (EXIT_ZOMBIE)：** 进程已死，但父进程未调用 `wait()`“收尸”，资源未完全释放
    - **死亡态 (EXIT_DEAD)：** 父进程已“收尸”，进程被彻底清理

![](images/1.%20基础概念/file-20251116225047836.jpg)


#### 进程的死亡

进程从“运行态”走向“死亡”主要有四条路：

1. **正常退出：** `main` 函数执行 `return`
2. **主动退出：** 调用 `exit()` 或 `_exit()` 函数
3. **线程退出：** 最后一个线程执行了 `pthread_exit()`
4. **异常终止：** 被信号“杀死”（例如 `SIGKILL` 或 `SIGTERM`）
