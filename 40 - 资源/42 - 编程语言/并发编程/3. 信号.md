# Linux 信号

在进程的生命周期中，它需要一种机制来响应来自系统外部的异步事件信号（Signal）便是 Linux/Unix 系统为此设计的核心通信范式它允许内核或其他进程打断一个进程的正常执行流程，以通知其发生了某个特定事件

## 信号基本概念

- **定义**：信号（Signal）是 Linux/Unix 系统上的一种**异步**的进程间通信（IPC）机制它用于**通知**一个进程发生了某个特定的事件
- **异步特性**：信号会**打断**进程的正常执行流程当一个进程接收到信号时，它会**暂停**当前正在执行的代码，转而去执行该信号的“处理函数”（Handler），执行完毕后，再返回到被打断的地方继续执行（除非处理方式是终止进程）
- **信号的来源**：
  1. **硬件**：如键盘按下 `Ctrl+C`（`SIGINT`）或 `Ctrl+Z`（`SIGTSTP`），或硬件故障（如非法内存访问 `SIGSEGV`）
  2. **内核**：当内核检测到某个系统事件时，如子进程终止（`SIGCHLD`）、定时器超时（`SIGALRM`）
  3. **进程**：一个进程可以通过 `kill()` 系统调用向另一个进程（或自己）发送信号

**信号的分类** Linux 系统中的信号主要分为两大类：

- **1. 标准信号 (Standard Signals) / (非实时信号)**

  - **范围**：信号编号 1 (`SIGHUP`) 到 31 (`SIGSYS`)
  - **特点**：
    - 这是从经典 Unix 系统继承而来的信号
    - **不可靠性 (Merging)**：标准信号**不会排队**如果一个信号（如 `SIGINT`）已经处于“未决”状态（即已产生但尚未被处理），那么后续所有*同类型*的 `SIGINT` 信号都会被**丢弃**
    - **结果**：无论 `Ctrl+C` 在短时间内被按了 1 次还是 100 次，进程最终都只“递达”1 次

- **2. 实时信号 (Real-time Signals)**

  - **范围**：信号编号 32 (`SIGRTMIN`) 到 64 (`SIGRTMAX`)
  - **特点**：
    - 这是 Linux 扩展的“可靠信号”
    - **可靠性 (Queuing)**：实时信号**会排队**如果一个进程连续收到 5 个 `SIGRTMIN+5` 信号，系统会把这 5 个信号都放入一个队列中
    - **结果**：进程会依次“递达” 5 次，信号不会丢失（只要队列未满）
    - 它们没有特定的预设事件，完全由用户程序自定义其含义

# 信号的默认处理动作

每种信号在被内核定义时，都预设了一个默认的处理方式当进程没有“自定义”处理方式时，内核就按此默认方式执行

信号处理方式主要有以下几种：

- **`Term` (终止)**：终止进程这是 `SIGINT` (Ctrl+C)、`SIGTERM` (kill 默认) 等信号的默认动作
- **`Ign` (忽略)**：忽略该信号，进程仿佛无事发生`SIGCHLD`（子进程终止）的默认动作就是忽略
- **`Core` (核心转储)**：终止进程，并生成一个 `core` 文件（包含进程死前的内存快照），用于事后调试`SIGSEGV`（段错误）、`SIGBUS`（总线错误）等是此类
- **`Stop` (暂停)**：暂停（冻结）进程`SIGTSTP` (Ctrl+Z) 是此类
- **`Cont` (继续)**：如果进程处于暂停状态，则恢复其运行`SIGCONT` 是此类

> **注意**：`SIGKILL` (信号 9) 和 `SIGSTOP` (信号 19) 是两个“特权”信号它们既不能被捕捉（自定义处理）、也不能被忽略、更不能被屏蔽



## 信号的生命周期与状态

一个信号从产生到被处理，会经历以下状态：

1. **信号产生 (Generation)**：硬件、内核或 `kill()` 触发了一个信号
2. **信号未决 (Pending)**：信号已经产生，但尚未被“递达”给进程此时，信号被保存在进程的“**未决信号集**”中
3. **信号递达 (Delivery)**：内核将“未决”的信号传递给进程，进程**必须**对其进行响应
   - 响应方式：按照该信号设置的“处理方式”（Disposition）来执行（可能是默认动作 `Term`/`Ign`，也可能是自定义函数）



# 信号处理方式的设定 `signal()`

`signal()` 函数用于修改一个信号的“处理方式”（Disposition），即决定信号在“递达”时，进程该做什么

- **函数原型**

  ```c
  #include <signal.h>
  typedef void (*sighandler_t)(int);
  sighandler_t signal(int signum, sighandler_t handler);
  ```

- 作用

  设置 signum 信号的处理方式为 handler

- **参数详解**

  - `signum`：要设置的信号编号，例如 `SIGINT`, `SIGCHLD`
  - `handler`：一个 `sighandler_t` 类型的函数指针，指定处理方式：
    - **`SIG_DFL`**：(Default) 恢复该信号的**默认处理方式**
    - **`SIG_IGN`**：(Ignore) **忽略**该信号
    - **一个自定义的函数地址**（例如 `myFunc`）：当信号递达时，转而去执行这个函数

- **返回值**

  - 返回该信号*之前*的处理方式（`handler`），以便后续恢复失败则返回 `SIG_ERR`

- **例子**

  -  设置**SIGINT**的默认处理方式为忽略

    ```c
    // 设置SIGINT的默认处理为 忽略
    signal(SIGINT , SIG_IGN );
    ```

  - 捕获信号并设置响应函数

    ```c
    #include <stdio.h>
    #include <signal.h>
    
    // 信号的响应函数
    void myFunc(int arg)
    {
        printf("正在处理信号[%d]..\n" , arg );
    }
    
    int main(int argc, char const *argv[])
    {
        // 设置SIGINT的默认处理为 执行myFunc 函数
        signal(SIGINT ,  myFunc );
        while (1)
        {
            printf("师兄弟就来砍我...\n");
            sleep(1);
        }
        return 0;
    }
    ```

# 信号的屏蔽 (Block) 与 `sigprocmask()`

“屏蔽”和“忽略”是完全不同的概念：

- **忽略 (`SIG_IGN`)**：信号*会*递达，但进程的响应是“什么也不做”
- **屏蔽 (`Block`)**：信号*根本不会*递达它会被卡在“未决”(Pending) 状态，直到进程**解除屏蔽**

进程通过一个“**信号屏蔽字**”(Signal Mask) 来维护当前被屏蔽的信号`sigprocmask()` 就是用来操作这个“屏蔽字”的函数

## 信号集 (`sigset_t`) 操作

`sigprocmask` 操作的是一个“信号集合”（`sigset_t`），你需要先用以下函数来“配置”这个集合：

```c
#include <signal.h>
// 1. 定义一个信号集变量
sigset_t set;

// 2. 清空集合
int sigemptyset(sigset_t *set);

// 3. 填满集合（包含所有信号）
int sigfillset(sigset_t *set);

// 4. 添加一个信号到集合中
int sigaddset(sigset_t *set, int signum);

// 5. 从集合中移除一个信号
int sigdelset(sigset_t *set, int signum);

// 6. 检查信号是否在集合中
int sigismember(const sigset_t *set, int signum);
```

## `sigprocmask()`

- **函数原型**

  ```c
  #include <signal.h>
  int sigprocmask(int how, const sigset_t *set, sigset_t *oldset);
  ```

- 作用

  设置或修改当前进程的“信号屏蔽字”

- **参数详解**

  - `how`：如何修改？
    - **`SIG_BLOCK`**：**阻塞**在当前屏蔽字的基础上，*加上* `set` 集合中的信号（`new_mask = old_mask | set`）
    - **`SIG_UNBLOCK`**：**解除阻塞**在当前屏蔽字的基础上，*移除* `set` 集合中的信号（`new_mask = old_mask & ~set`）
    - **`SIG_SETMASK`**：**设置***直接*将 `set` 集合设为新的屏蔽字（`new_mask = set`）
  - `set`：指向你配置好的那个“信号集合”的指针
  - `oldset`：如果不为 `NULL`，则用于备份*修改前*的旧屏蔽字，方便后续还原

- **返回值**

  - 成功返回 0，失败返回 -1

# 示例代码

```c
#include <stdio.h>
#include <signal.h>
#include <unistd.h>

// 3. 这是信号的“处理函数” (Disposition)
void  myFunc( int SigNum )
{
    printf("信号递达 sigNum:%d\n" , SigNum)  ;
}

int main(int argc, char const *argv[])
{
    // 1. 设置 "Disposition"：
    // 告诉内核，SIGINT (Ctrl+C) 一旦“递达”，就去执行 myFunc
    signal( SIGINT , myFunc );
    
    // 2. 准备“信号集”，用于屏蔽
    sigset_t set;
    sigemptyset(&set);          // 清空集合
    sigaddset(&set, SIGINT );   // 把 SIGINT 添加到集合中

    // 3. 设置“信号屏蔽字” (戴上耳机)
    // 使用 SIG_SETMASK，将进程的屏蔽字设为（只包含 SIGINT）
    // 从这一刻起，SIGINT 信号将无法“递达”，只能处于“未决”
    printf("已设置屏蔽，5秒内 SIGINT 处于未决...\n");
    sigprocmask( SIG_SETMASK , &set , NULL );
    
    // ------------------- 临界区开始 -------------------
    sleep(5); 
    // 在这 5 秒内，无论你按多少次 Ctrl+C，
    // SIGINT 信号都只会被内核记录为“未决”，myFunc 不会被执行
    // ------------------- 临界区结束 -------------------
    
    printf("5秒结束，解除屏蔽\n");

    // 4. 恢复“信号屏蔽字” (摘下耳机)
    // 使用 SIG_UNBLOCK，从屏蔽字中移除 SIGINT
    sigprocmask( SIG_UNBLOCK , &set , NULL );
    
    // (5). 就在上一步解除屏蔽的瞬间，内核会检查：
    // “是否有处于未决状态的 SIGINT？”
    // “有！”
    // 于是，SIGINT 信号在此刻“递达”，内核立刻调用 myFunc
    
    // 6. pause()：使进程挂起，直到有任何一个信号递达
    //    (如果解除屏蔽时没有未决信号，程序会在这里等待下一个 Ctrl+C)
    while (1)
    {
        pause(); 
    }
    
    return 0;
}
```
# 单词记忆
## `signal`
- **含义：** 信号，暗号，标志；发信号
- **音标：** /ˈsɪɡnəl/
- **谐音：** **西格-呢** (xī gé ne) 或 **赛格-诺** (sài gé nuò)
- **记忆：** 想象一下你看到的“交通信号灯”（Traffic Signal Light）。红灯亮起（这是一个 **signal**），你就知道必须停车。这个词的根本含义就是一种用来“**传递信息以触发特定动作**”的标志或事件。在编程中，`Ctrl+C` 就是一个“信号”，它告诉程序“请停止”。
## `empty`
- **含义：** 空的；使……变空
- **音标：** /ˈɛmpti/
- **谐音：** **俺-扑-题** (ǎn pū tí)
- **记忆：** 想象一个**空**的（empty）盒子或房间，里面什么都没有。在编程中，`sigemptyset` 就是把信号“集合”里的所有东西都倒出去，让它变**空**。
## `fill`
- **含义：** 填满；填充
- **音标：** /fɪl/
- **谐音：** **费-哦** (fèi o)
- **记忆：** 想象给一个杯子**倒满**（fill）水，直到溢出来。在编程中，`sigfillset` 就是把**所有**可能的信号都**塞进**这个“集合”里，把它**填满**。
## `add`
- **含义：** 添加；增加
- **音标：** /æd/
- **谐音：** **艾-德** (ài dé)
- **记忆：** 就是数学里的“加法”（+）。想象你有一个篮子，你往里面**添加**（add）一个苹果。在编程中，`sigaddset` 就是往信号“集合”里**添加**一个特定的信号。
## `delete`
- **含义：** 删除
- **音标：** /dɪˈliːt/
- **谐音：** **迪-力-特** (dí lì tè)
- **记忆：** 电脑键盘上的“Delete”键，按下它就可以**删除**文件或文字。在编程中，`sigdelset` (del 是 delete 的缩写) 就是从信号“集合”里**删除**一个特定的信号。
## `set`
- **含义：** 集合；一组；设置
- **音标：** /sɛt/
- **谐音：** **赛-特** (sài tè)
- **记忆：** 想象“一套（a set of）工具”或“一套餐具”。它表示一堆同类东西的**集合**。在编程中，`sigset_t` 的 `set` 就是指这是一个“信号的**集合**”。
## `is`
- **含义：** 是（动词 be 的一种形式）
- **音标：** /ɪz/
- **谐音：** **伊-子** (yī zi)
- **记忆：** 这是英语中最基本的单词之一，用来做**判断**。比如 "He **is** a doctor." (他**是**医生)。在编程中，`sigismember` 就是在**判断**：“这个信号 **是** 不是这个集合的成员？”
## `member`
- **含义：** 成员；会员
- **音标：** /ˈmɛmbər/
- **谐音：** **慢-博** (màn bó)
- **记忆：** 想象一个俱乐部或家庭的**成员**（member）。在编程中，`sigismember` 就是在问：“这个信号是不是这个‘集合大家庭’里的一个**成员**？”
## `process`
- **含义：** 进程；过程；处理
- **音标：** /ˈprɒsɛs/ (英式) 或 /ˈprɑːsɛs/ (美式)
- **谐音：** **普-肉-赛斯** (pǔ ròu sài si)
- **记忆：** 电脑里“正在运行的程序”就叫一个**进程**（process）。你可以把它想象成一个正在厨房里按步骤做菜的“厨师”。在编程中，`sigprocmask` (proc 是 process 的缩写) 就是用来管理这个**进程**的信号。
## `mask`
- **含义：** 掩码；面具；遮罩
- **音标：** /mæsk/
- **谐音：** **马-斯-克** (mǎ sī kè)
- **记忆：** 想象戴上一个**面具**（mask）或口罩，把脸**遮住**。在编程中，“掩码”就是用来**遮蔽**或**屏蔽**某些信号的，告诉系统：“这些被‘遮住’的信号我暂时不想理会。”
