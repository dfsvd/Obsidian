## 基础概念
**TCP (Transmission Control Protocol，传输控制协议)** 是面向连接的、可靠的、基于字节流的传输层通信协议。如果说 UDP 是“写信”，那么 TCP 就是**打电话**。
### 核心特性
- **面向连接 (Connection-oriented)**
    - 通信双方在传输数据前，必须先建立连接（即“三次握手”）。
    - 通信结束后，必须断开连接（即“四次挥手”）。
- **可靠传输 (Reliable)**
    - **有确认**：一方收到数据后，会给发送方回执确认（ACK）。
    - **重传机制**：如果数据丢失，发送方会自动重发。
    - **有序性**：保证数据按顺序到达，且不重复。
- **流式通信 (Byte Stream)**
    - TCP 采用**字节流**方式，不保留消息边界（不同于 UDP 的数据报边界）。
    - **自动调节**：如果网络拥堵，会自动调节发送速率（流量控制、拥塞控制）。
> **类比理解**： TCP 就像**打电话**。通话前必须先拨通（建立连接），对方接听后才能说话。通话过程中，你会确认对方是否听到（“喂？听得到吗？”）。结束时双方都要挂断。这种方式虽然繁琐（资源开销大），但能保证对方准确无误地收到信息。
### 适用场景
由于 TCP 提供了高可靠性，但资源开销比 UDP 大，因此适用于**对传输质量要求高**，但对实时性要求稍低（或能接受连接建立开销）的场景：
1. **文件传输**：FTP、网盘上传下载（绝不能丢数据）。
2. **网页浏览**：HTTP/HTTPS 协议（必须完整加载页面代码）。
3. **远程登录**：SSH、Telnet（指令不能出错）。
4. **邮件发送**：SMTP、POP3。
5. **账户与支付**：用户登录、银行转账等关键业务。
## 通信流程
TCP 通信区分**客户端 (Active/Client)** 和 **服务端 (Passive/Server)**。
### 服务端流程 (被动方)
1. **创建套接字 (`socket`)**：建立通信端点。
2. **绑定地址 (`bind`)**：将套接字与本机 IP 和端口绑定（对外公开联系方式）。
3. **设置监听 (`listen`)**：将套接字设置为“被动监听”状态，准备接听电话。
4. **等待连接 (`accept`)**：阻塞等待客户端的连接请求。一旦连接成功，返回一个新的**连接套接字**。
5. **收发数据 (`read/write`)**：使用**连接套接字**进行通信。
6. **关闭 (`close`)**：通信结束，释放资源。
### 客户端流程 (主动方)
1. **创建套接字 (`socket`)**：建立通信端点。
2. **发起连接 (`connect`)**：向服务端的 IP 和端口发起连接请求（拨打电话）。
3. **收发数据 (`read/write`)**：连接成功后，直接通信。
4. **关闭 (`close`)**：挂断电话。
## 关键 API 接口
### 1. 地址绑定 `bind()`

通常用于服务端，明确自己要在哪个 IP 和端口“待客”。
```c
int bind(int sockfd, const struct sockaddr *addr, socklen_t addrlen);
```
- **功能**：将套接字 `sockfd` 与指定的 IP+PORT 绑定。
- **注意**：一个端口在同一时间只能被一个套接字绑定。
- **返回值**：成功返回 0，失败返回 -1。
### 2. 设置监听 `listen()`
```c
int listen(int sockfd, int backlog);
```
- **功能**：将套接字状态由“主动”变为“被动监听”。
- **参数 `backlog`**：指定同时等待处理的连接请求的最大数量（排队队列长度）。
    - _注意_：这不是最大连接数，而是正在进行三次握手或等待 accept 的连接数。
- **返回值**：成功返回 0，失败返回 -1。
### 3. 等待连接 `accept()`
**这是 TCP 服务端最核心、也最容易混淆的接口。**
```c
int accept(int sockfd, struct sockaddr *addr, socklen_t *addrlen);
```
- **功能**：阻塞等待客户端的连接请求。
- **参数**：
    - `sockfd`：**监听套接字**（仅用于监听，不传输数据）。
    - `addr`：(可选) 用于存储连上来的客户端的地址信息。
- **返回值**：
    - 成功：返回一个**全新的文件描述符**（称为**连接套接字 `connfd`**）。
    - 失败：返回 -1。
- **重点说明**：
    > `accept` 返回的 `connfd` 是专门用于和该客户端收发数据的。原来的 `sockfd` 继续保持监听状态，等待下一个人的连接。**千万不要混用这两个套接字。**
### 4. 发起连接 `connect()`
客户端使用的接口。
```c
int connect(int sockfd, const struct sockaddr *addr, socklen_t addrlen);
```
- **功能**：触发 TCP 三次握手，向指定服务端发起连接。
- **行为**：在网络拥堵或连接建立前，该函数会阻塞。
- **返回值**：成功返回 0，失败返回 -1。
## 示例代码
本示例演示了一个**TCP 消息反弹服务**。客户端发给服务器什么消息，服务器就原样发回什么消息。
### 服务端 (Server)
文件：`TCP-reflectionServer.c`
```c
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <string.h>
#include <strings.h>
#include <sys/socket.h>
#include <arpa/inet.h>

int main(int argc, char **argv)
{
    // 1. 创建TCP套接字 (监听套接字)
    int sockfd = socket(AF_INET, SOCK_STREAM, 0);
    if(sockfd < 0) { perror("socket"); exit(1); }

    // 2. 准备地址结构体并绑定
    struct sockaddr_in addr;
    bzero(&addr, sizeof(addr));
    addr.sin_family = AF_INET;
    addr.sin_addr.s_addr = htonl(INADDR_ANY); // 自动获取本机所有IP
    addr.sin_port = htons(50021);             // 绑定端口 50021

    if(bind(sockfd, (struct sockaddr *)&addr, sizeof(addr)) != 0)
    {
        perror("绑定失败");
        exit(0);
    }

    // 3. 设置为被动监听状态
    listen(sockfd, 3);
    printf("TCP服务器启动，监听端口: 50021\n");

    // 4. 阻塞等待客户端连接
    struct sockaddr_in peeraddr;
    socklen_t len = sizeof(peeraddr);
    int connfd; // 连接套接字

    // accept 返回的 connfd 专门用于通信
    if((connfd = accept(sockfd, (struct sockaddr *)&peeraddr, &len)) > 0)
    {
        printf("发现客户端[%s:%hu]连接！\n", 
               inet_ntoa(peeraddr.sin_addr), ntohs(peeraddr.sin_port));
    }

    // 5. 循环收发数据
    char buf[100];
    int n;
    while(1)
    {
        bzero(buf, 100);
        // 从连接套接字读取数据
        n = read(connfd, buf, 100);
        
        if(n == 0) {
            printf("客户端已关闭连接。\n");
            break;
        } else if(n < 0) {
            perror("读取失败");
            break;
        }

        printf("收到消息: %s", buf);

        // 将消息原样回写给客户端
        write(connfd, buf, strlen(buf));
    }

    // 6. 关闭套接字
    close(connfd); // 断开与当前客户端的连接
    close(sockfd); // 关闭服务器监听（不再接受新连接）

    return 0;
}
```
### 客户端 (Client)
```c
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <string.h>
#include <strings.h>
#include <sys/socket.h>
#include <arpa/inet.h>

int main(int argc, char **argv)
{
    // 检查参数，必须传入服务器IP
    if(argc != 2)
    {
        printf("用法: %s <服务器IP>\n", argv[0]);
        exit(0);
    }

    // 1. 创建TCP套接字
    int sockfd = socket(AF_INET, SOCK_STREAM, 0);

    // 2. 准备服务器地址结构体
    struct sockaddr_in addr;
    bzero(&addr, sizeof(addr));
    addr.sin_family = AF_INET;
    // 将命令行参数输入的字符串IP转换为网络整型
    addr.sin_addr.s_addr = inet_addr(argv[1]); 
    addr.sin_port = htons(50021); // 服务器的端口

    // 3. 发起连接请求 (三次握手)
    if(connect(sockfd, (struct sockaddr *)&addr, sizeof(addr)) == 0)
        printf("连接服务器成功！\n");
    else {
        perror("连接失败");
        exit(0);
    }

    char sendbuf[100];
    char recvbuf[100];

    while(1)
    {
        bzero(sendbuf, 100);
        printf("请输入发送内容: ");
        fgets(sendbuf, 100, stdin); // 获取键盘输入

        // 4. 发送数据
        if(write(sockfd, sendbuf, strlen(sendbuf)) <= 0)
        {
            perror("发送失败或连接断开");
            break;
        }

        // 5. 接收回弹消息
        bzero(recvbuf, 100);
        if(read(sockfd, recvbuf, 100) > 0 )
            printf("服务器回弹: %s", recvbuf);
    }

    close(sockfd);
    return 0;
}
```
### 代码分析与注意点
1. **`listen` vs `accept`**：
    - `listen` 只是把门打开，告诉系统“我准备好接客了”。
    - `accept` 才是真正的“接待客人”，它会返回一个新的 `connfd`。
2. **客户端无需 `bind`**：
    - 客户端通常不需要手动绑定端口。在调用 `connect` 时，操作系统会自动为客户端分配一个临时的随机端口。
3. **连接断开的检测**：
    - 当 `read` 返回 `0` 时，表示对端已经关闭了连接（即收到 TCP FIN 包）。此时应跳出循环并关闭本地套接字。
## 思考与练习

**思考题**： 实际互联网服务器（如百度、淘宝）都是基于 TCP 的，我们并未事先连接它们，为什么能直接访问？

- **答案**：因为这些服务器的 IP 和端口（如 HTTP 的 80，HTTPS 的 443）是**周知**且公开的，并长期处于 `listen` 和 `accept` 状态。我们在浏览器输入网址时，通过 DNS 解析得到 IP，浏览器自动帮我们发起了 `connect` 连接。
    

**练习题**： 改造上述“消息反弹”服务器：

1. **功能变更**：服务器不再反弹消息内容，而是反弹**客户端的端口号**。
    
2. **验证**：客户端接收到数字后，打印出来，并获取自己当前的端口号 (`getsockname`) 进行对比，验证是否一致。

## TCP 缓冲区与带外数据

在 TCP 协议的底层，内核为每个套接字维护了两个核心缓冲区：发送缓冲区和接收缓冲区。理解并合理设置它们，对于优化网络传输性能至关重要。此外，为了处理紧急情况，TCP 还提供了“带外数据”机制。
### TCP 数据缓冲区
- **发送缓冲区 (Send Buffer)**
    - **作用**：当应用层调用 `write` 发送数据时，数据并未立即发往网络，而是先拷贝到内核的发送缓冲区。缓冲区中的数据用于在网络丢包时进行**重传**（TCP 自动重传机制）。
    - **大小**：Linux 下通常在 **4608 ~ 425984** 字节之间。
- **接收缓冲区 (Receive Buffer)**
    - **作用**：暂存从网络接收到的数据，等待应用层调用 `read` 取走。它配合 TCP 的滑动窗口机制进行流量控制，防止发送方发得太快淹没接收方。
    - **大小**：Linux 下通常在 **2304 ~ 425984** 字节之间。
### 水位线 (Low Water Mark)

仅仅设置接收缓冲区大小（如 100 字节）并不能强迫 `read` 等凑齐 100 字节才返回。默认情况下，只要缓冲区有 **1 字节** 数据，`read` 就会立即返回。
- **定义**：将缓冲区视为水池，**水位线**规定了数据量必须达到多少，套接字才会进入“读就绪”状态（触发 `read` 返回或 `select` 可读）。
- **默认值**：通常为 0 或 1。
- **应用**：常用于定长包传输，减少系统调用次数，降低 CPU 负载。
### OOB 带外数据 (Out-of-Band Data)
当接收方设置了很高的水位线或缓冲区已满时，普通数据会被阻塞。如果有紧急指令（如“取消操作”），需要一种机制能突破排队限制。
- **特性**：
    - **冲破限制**：能突破接收缓冲区和水位线的限制，被接收方优先感知。
    - **容量**：每次只能发送 **1 个字节** 的紧急数据。
    - **通知机制**：OOB 数据的到达会触发 `SIGURG` 信号，或在 `select` 中触发**异常就绪**状态
### 关键 API 接口
#### 设置/获取套接字选项 `setsockopt` / `getsockopt`
用于调整缓冲区大小、水位线等属性。
```c
#include <sys/socket.h>

int setsockopt(int sockfd, int level, int optname, 
               const void *optval, socklen_t optlen);

int getsockopt(int sockfd, int level, int optname, 
               void *optval, socklen_t *optlen);
```
- **作用**：设置或获取套接字的属性。
- **参数分析**：
    - `sockfd`：套接字文件描述符。
    - `level`：选项级别。
        - `SOL_SOCKET`：通用套接字选项（缓冲区、水位线等）。
    - `optname`：选项名称。
        - `SO_SNDBUF`：发送缓冲区大小。
        - `SO_RCVBUF`：接收缓冲区大小。
        - `SO_RCVLOWAT`：接收低水位线。
    - `optval`：指向存放值的指针（通常是 `int` 类型）。
    - `optlen`：值的长度（`getsockopt` 中是指针）。
- **返回值**：成功返回 `0`，失败返回 `-1`。
### 多路复用监听 `select`
用于同时监听多个文件描述符的读、写和**异常**状态（OOB 数据属于异常）。
```c
#include <sys/select.h>

int select(int nfds, fd_set *readfds, fd_set *writefds, 
           fd_set *exceptfds, struct timeval *timeout);
```
- **作用**：阻塞等待文件描述符就绪。
- **参数分析**：
    - `nfds`：最大文件描述符值 + 1。
    - `readfds`：监听**读就绪**集合（普通数据）。
    - `exceptfds`：监听**异常就绪**集合（**OOB 带外数据**）。
- **返回值**：大于 0 表示就绪的文件描述符数量；0 表示超时；-1 表示出错。
### 文件控制 `fcntl`
用于设置异步 I/O 的信号属主（当使用信号方式接收 OOB 时需要）。
```c
#include <fcntl.h>

int fcntl(int fd, int cmd, ... /* arg */ );
```
- **作用**：控制文件描述符属性。
- **参数分析**：
    - `cmd`：`F_SETOWN`（设置套接字属主）。
    - `arg`：进程 ID（`getpid()`），指定谁来接收 `SIGURG` 信号。
### 示例代码
#### 设置发送缓冲区
```c
////////////////////////////////////////////////////////
//  文件: TCP-sendBuffer.c
//  描述: 检测、设置TCP的发送缓冲区
///////////////////////////////////////////////////////
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <sys/socket.h>

int main(int argc, char **argv)
{
    int sockfd = socket(AF_INET, SOCK_STREAM, 0);
    if (sockfd < 0) { perror("socket"); exit(1); }

    int bufSize = 0;
    int len = sizeof(bufSize);

    // 1. 获取默认发送缓冲区大小
    getsockopt(sockfd, SOL_SOCKET, SO_SNDBUF, &bufSize, &len);
    printf("默认发送缓冲区大小: %d\n", bufSize);

    // 2. 设定新的大小
    printf("请输入你要设定的大小: ");
    scanf("%d", &bufSize);
    len = sizeof(bufSize);
    
    // 注意：内核为了管理开销，实际设置的大小通常是请求值的两倍
    if(setsockopt(sockfd, SOL_SOCKET, SO_SNDBUF, &bufSize, len) != 0)
    {
        perror("setsockopt() 失败");
        exit(0);
    }

    // 3. 验证结果
    bufSize = 0;
    len = sizeof(bufSize);
    getsockopt(sockfd, SOL_SOCKET, SO_SNDBUF, &bufSize, &len);
    printf("目前发送缓冲区大小: %d\n", bufSize);

    close(sockfd);
    return 0;
}
```

### 接收带外数据 (使用 select)
```c
////////////////////////////////////////////////////////
//  文件: TCP-oob-recv.c
//  描述: 使用 select 监测并接收 OOB 带外数据
///////////////////////////////////////////////////////
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <string.h>
#include <sys/socket.h>
#include <arpa/inet.h>
#include <sys/select.h>

int main(int argc, char **argv)
{
    // 1. 创建监听套接字
    int listenfd = socket(AF_INET, SOCK_STREAM, 0);
    
    struct sockaddr_in addr = {0};
    addr.sin_family = AF_INET;
    addr.sin_addr.s_addr = htonl(INADDR_ANY);
    addr.sin_port = htons(50022);

    if (bind(listenfd, (struct sockaddr *)&addr, sizeof(addr)) != 0) {
        perror("bind failed"); exit(1);
    }
    listen(listenfd, 3);
    printf("正在监听 50022 端口等待连接...\n");

    // 2. 等待连接
    int connfd = accept(listenfd, NULL, NULL);
    printf("客户端已连接!\n");

    fd_set rset, eset;
    char buf[100];

    while(1)
    {
        FD_ZERO(&rset);
        FD_ZERO(&eset);
        
        FD_SET(connfd, &rset); // 监听可读 (普通数据)
        FD_SET(connfd, &eset); // 监听异常 (带外数据)

        // 3. 多路复用阻塞等待
        select(connfd + 1, &rset, NULL, &eset, NULL);

        // 4. 检查是否有 OOB 数据
        if(FD_ISSET(connfd, &eset))
        {
            char oob;
            // 必须加 MSG_OOB 标记
            recv(connfd, &oob, 1, MSG_OOB);
            printf("【紧急】收到带外数据: %c\n", oob);
        }

        // 5. 检查是否有普通数据
        if(FD_ISSET(connfd, &rset))
        {
            memset(buf, 0, 100);
            int n = recv(connfd, buf, 100, 0);
            if(n <= 0) {
                printf("连接断开\n");
                break;
            }
            printf("收到普通数据: %s\n", buf);
        }
    }

    close(connfd);
    close(listenfd);
    return 0;
}
```
