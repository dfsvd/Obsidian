# 课程概览
在深入代码之前，我们需要先建立宏观的认知网络通信从本质上讲，就是**广义的 IPC (Inter-Process Communication，进程间通信)**
- **单机 IPC**：管道、消息队列、共享内存等，解决的是同一台机器内核中不同进程的数据交互
- **网络通信**：解决的是跨越物理主机、跨越网络设备的进程间数据交互
相比单机 IPC，网络通信引入了“不可靠的物理介质”和“复杂的路由寻址”，因此学习网络编程的首要任务并非死记 API，而是**理解网络分层的基本思想**，进而引出**网络协议**的概念网络编程在很大程度上就是基于某种特定协议，编写符合该协议规范的通信代码
## 网络分层
计算机网络是一个极其复杂的系统，涉及物理信号传输、链路控制、路由选择、数据校验、流量控制等众多环节为了降低复杂性，计算机科学家采用了**分层 (Layering)** 的设计思想
- **分层的目的**：将复杂的网络传输过程**按照所完成的功能进行解耦**
- **分层的优势**：
    - **独立性**：每一层只需关注自己的核心功能（例如：物理层只管发信号，不关心信号代表什么图片）
    - **标准化**：每一层的实现方式容易形成统一的行业标准（如 Ethernet, IP, TCP）
    - **可维护性**：上层只需调用下层提供的接口，无需了解下层具体实现

## 网络协议
协议（Protocol）是网络通信的基石简单来说，协议就是**通信双方预先商量好的一组“暗号”或规则**
- **核心定义**：协议规定了彼此之间需要协定的数据（语法）、写入数据包的固定位置（格式）以及大家使用相同的方式来解读这一组特定的信息（语义）
- **示例**：如下图所示的“午餐点单”矩阵如果双方没有约定好“每一位代表一种食物”，接收方看到 `1001110` 这串数字将不知所云协议就是这个“约定”
![](images/1.%20基础概念/file-20251117214412353.jpg)
- **协议族**：对应于不同的网络分层，每一层都有一个或多个协议
    - **应用层**：HTTP, FTP, NFS, TELNET, SSH 等
    - **传输层**：TCP, UDP
    - **网络层**：IP, ICMP
在互联网领域，应用最为广泛、事实上的工业标准是 **TCP/IP 协议栈**需要注意的是，**TCP/IP 协议**不仅仅指 TCP 和 IP 这两个协议，它是指利用 IP 进行通信时所必须用到的协议群的统称，包括传输层最重要的 **TCP** 和 **UDP**，以及众多 IP 协议的辅助协议（如 ARP, RARP, ICMP 等）
## 网络模型

网络模型主要分为理论上的 **OSI 七层模型** 和 实际应用中的 **TCP/IP 四层模型**

### OSI 七层模型 (理论模型)
**OSI (Open Systems Interconnection)** 模型是一个由国际标准化组织 (ISO) 提出的概念性框架，试图将计算机网络通信划分为七个抽象层它虽然在实际部署中被 TCP/IP 取代，但它依然是描述网络通信的标准术语
- **7. 应用层 (Application)**：为应用程序提供网络服务
- **6. 表示层 (Presentation)**：数据格式转换、加密、解密、压缩
- **5. 会话层 (Session)**：建立、管理和终止会话
- **4. 传输层 (Transport)**：提供端到端的传输
- **3. 网络层 (Network)**：路径选择和路由
- **2. 数据链路层 (Data Link)**：物理寻址 (MAC) 和介质访问控制
- **1. 物理层 (Physical)**：二进制比特流传输
### TCP/IP 四层模型
现实互联网中实际运行的是 **TCP/IP 模型**它是对 OSI 模型的简化和合并，更注重实用性和效率

| **OSI 七层模型**                                                         | **TCP/IP 四层模型**                     | **对应功能与协议**                       | **协议**                           |
| -------------------------------------------------------------------- | ----------------------------------- | --------------------------------- | -------------------------------- |
| **应用层** (Application)<br>**表示层** (Presentation)<br>**会话层** (Session) | **应用层** (Application)               | 包含 OSI 顶部三层的功能负责处理特定的应用程序细节  <br> | HTTP, FTP, SSH, DNS 等            |
| **传输层** (Transport)                                                  | **传输层** (Transport)                 | 位于操作系统内核负责提供端到端的通信服务（可靠或不可靠）<br>  | TCP, UDP                         |
| **网络层** (Network)                                                    | **网络层** (Internet)                  | 位于操作系统内核负责数据包的路由选择和逻辑寻址           | IP, ICMP, IGMP                   |
| **数据链路层** (Data Link) <br>**物理层** (Physical)                         | **网络接口与物理层**<br>(Network Interface) | 位于操作系统内核及驱动负责物理媒介的数据传输            | Ethernet (802.3), Wi-Fi (802.11) |

## 数据封装与解封装

数据在网络中传输时，并非直接发送原始数据，而是需要经历**封装 (Encapsulation)** 和 **解封装 (Decapsulation)** 的过程，这类似于寄快递时的打包和拆包
1. **封装（发送方）**：
    - 数据从上层向下层流动
    - 每经过一层，该层协议就会在数据头部加上自己的**协议头 (Header)**（就像给包裹贴上新的标签）
    - 例如：应用层数据 -> 加上 TCP 头 -> 加上 IP 头 -> 加上 MAC 头 -> 转换为物理信号发送
2. **解封装（接收方）**：
    - 接收方收到信号后，执行相反的过程
    - 数据从下层向上层流动，每经过一层，就剥离掉对应的协议头，读取该层的信息，并将剩余数据传递给上一层

# 基本术语
## 套接字 (Socket)
在 Linux 网络编程中，**套接字 (Socket)** 是最核心的接口概念
- **定义**：Socket 原意是“插座”或“插孔”在网络编程中，它是应用层与操作系统网络协议栈之间的**接口 (Interface)**
![](images/1.%20基础概念/file-20251117214412345.jpg)
    
- **隐喻**：我们可以把 Socket 想象成墙上的**插座**
    - 应用层的数据（电器）需要发送到网络中
    - 操作系统提供了不同类型的插座（Socket）
    - 应用程序需要根据自己的需求（是需要可靠传输 TCP，还是快速传输 UDP），选择对应协议的“插座”插入，从而接入网络通信系统
- **本质**：在 Linux 内核中，Socket 被实现为一种**文件描述符**对 Socket 的操作（读写网络数据）与操作普通文件非常相似
## IP 地址
如果说 Socket 是通信的关口，那么 **IP 地址** 就是网络中主机的“门牌号”
- **本质**：IP 地址实质上等同于一台计算机在网络中的 **ID**，用于在世界范围内唯一标识某台机器
- **IPv4 格式**：以目前通用的 IPv4 为例，IP 地址总共 **32位**通常采用**点分十进制**字符串形式表示，例如 `192.168.18.2`
## IP 地址的组成与分类
当初设计 IP 地址时，认为 32 位（约 43 亿个地址）足以覆盖全世界的计算机但随着设备激增，IPv4 地址面临枯竭（虽然后续发明了子网掩码和 NAT 技术来缓解）
从逻辑上，一个 IP 地址可以分为两部分：
1. **网络号 (Network ID)**：前半段类似于“街道名”或“小区名”，用于明确主机所在的局域网
2. **主机号 (Host ID)**：后半段类似于“门牌号”，用于在该网络内部唯一标识一台主机
根据网络号和主机号所占位数的不同，IP 地址被分为以下几类（Classful Addressing）：
- **A 类地址**
    - **规则**：第 **1** 个字节为网络号，后 **3** 个字节为主机号
    - **特征**：第 1 字节的最高位固定为 `0`
    - **范围**：`1.0.0.1` - `126.255.255.255`
    - **适用**：超大型网络（主机数极大）
- **B 类地址**
    - **规则**：前 **2** 个字节为网络号，后 **2** 个字节为主机号
    - **特征**：第 1 字节的前两位固定为 `10`
    - **范围**：`128.0.0.1` - `191.255.255.255`
    - **适用**：中型网络
- **C 类地址**
    - **规则**：前 **3** 个字节为网络号，最后 **1** 个字节为主机号
    - **特征**：第 1 字节的前三位固定为 `110`
    - **范围**：`192.0.0.1` - `223.255.255.255`
    - **适用**：小型网络（如家庭、小型办公室）
- **D 类地址**
    - **规则**：不分网络地址和主机地址
    - **特征**：第 1 字节的前四位固定为 `1110`
    - **范围**：`224.0.0.1` - `239.255.255.255`
    - **特殊用途**：**不是**用于标识单一主机，而是作为 **UDP 协议的多播 (Multicast) 组标识**
> **注意**
>  1. 我们通常看到的主机 IP（如 `192.168.x.x`）通常是**局域网 (LAN)** 地址，由路由器通过 DHCP 分配
>  2. D 类地址专用于多播，不能分配给具体的主机网卡作为单播 IP
## 子网掩码与网段
我们知道 IP 地址分为“网络号”和“主机号”，但在实际应用中，仅仅依靠 A/B/C 类地址的自然划分是不够灵活的为了更有效地利用 IP 资源并方便管理，引入了**子网掩码 (Subnet Mask)** 的概念
在配置网络（例如 Windows 的 IPv4 属性）时，IP 地址通常与子网掩码成对出现
### 网段的计算
子网掩码的核心作用是将 IP 地址划分为**网络地址**（网段）和**主机地址**计算公式如下：

```c
网段 (Network Address) = IP 地址 & 子网掩码
```

这里的 `&` 是**按位与**运算
- **示例分析**：
    - **IP 地址**：`192.168.9.88`
    - **子网掩码**：`255.255.255.0`
    - **计算过程**：
        - `255` 的二进制是全 1，`0` 的二进制是全 0
        - IP 的前三个字节与 `255` 相与，保留原值；最后一个字节与 `0` 相与，变为 0
    - **结果（网段）**：`192.168.9.0`
这意味着，所有 IP 地址为 `192.168.9.x` 且掩码为 `255.255.255.0` 的设备，都属于**同一个局域网（网段）**
### 通信规则
- **同网段通信**：如果源主机和目标主机处于同一网段，数据包可以通过交换机直接投递，无需经过路由器
- **跨网段通信**：如果计算出的网段不同，数据包必须发送给**默认网关 (Default Gateway)**（通常是路由器，如 `192.168.9.1`），由网关负责转发到外部网络
### CIDR 表示法
在很多服务器配置或 Linux 命令行（如 `ip addr`）中，我们经常看到类似 `/24` 的写法，这被称为 **CIDR (无类别域间路由)** 表示法
```sh
192.168.9.88/24
```
- **含义**：`/24` 代表子网掩码的**前 24 位是 1**
- **换算**：32 位地址中，前 24 位为 1，后 8 位为 0即 `11111111.11111111.11111111.00000000`，转换为十进制正是 `255.255.255.0`
## 端口号
如果说 IP 地址解决了“定位到哪台房子（主机）”的问题，那么**端口号 (Port Number)** 就解决了“定位到哪个房间（进程）”的问题
### 存在的意义
- **IP 地址**：唯一标识网络中的一台**主机**
- **端口号**：唯一标识主机内部的一个**网络进程**
当网卡接收到一个数据包时，操作系统内核通过查看数据包头部的端口号，决定将这个数据包转交给 Chrome 浏览器、微信还是 Web 服务器因此，端口号也可以理解为**网络中的进程号**
### 端口号的特性
- **数据类型**：端口号在 C 语言网络编程中是一个 `unsigned short`（无符号短整型），长度为 **16位**
- **取值范围**：`0 ~ 65535`
### 端口号的分类
根据用途和管理权限，端口号被划分为三个区间：
1. **系统端口 / 知名端口 (Well-Known Ports)**：`1 ~ 1023`
    - **特点**：这些端口被预留给系统级的核心服务在 Linux 下，绑定这些端口需要 **Root 权限**
    - _常见例子_：SSH (22), HTTP (80), HTTPS (443), FTP (21)
2. **注册端口 (Registered Ports)**：`1024 ~ 49151`
    - **特点**：分配给用户进程或特定的应用程序我们编写服务器程序时，通常使用这个范围的端口
    - _常见例子_：MySQL (3306), Tomcat (8080), Redis (6379)
3. **动态 / 私有端口 (Dynamic Ports)**：`49152 ~ 65535`
    - **特点**：通常由操作系统自动分配给**客户端**程序使用（短暂端口）
### 注意事项
- **协议独立性**：**TCP 端口与 UDP 端口是相互独立的**也就是说，TCP 的 8080 端口和 UDP 的 8080 端口可以同时存在，互不冲突，因为它们分属不同的协议栈处理流程
- **唯一性**：在同一协议下（如都是 TCP），同一时刻一个端口只能被一个进程绑定
## 字节序
在单机编程中，我们很少关注整数在内存中是怎么存的但在网络编程中，**字节序 (Byte Order)** 是一个必须跨越的障碍
### 什么是字节序
当一个数据需要使用 2 个或以上字节存储时（例如 `int` 占 4 字节，`short` 占 2 字节），这就涉及到“哪个字节存在低地址，哪个字节存在高地址”的问题
假设有一个 4 字节整数：`0x12345678`（十六进制）其中 `12` 是最高有效位 (MSB)，`78` 是最低有效位 (LSB)
![](images/1.%20基础概念/file-20251117214412336.jpg)

- **小端序 (Little-Endian)**：
    - **规则**：**低**位数据存放在**低**地址
    - **特点**：常见于 x86/x64 架构的 CPU（我们常用的 PC 和服务器）
    - _内存布局_：`78 56 34 12` （低地址 -> 高地址）
- **大端序 (Big-Endian)**：
    - **规则**：**高**位数据存放在**低**地址
    - **特点**：符合人类的阅读习惯常见于网络设备、一些 RISC 架构处理器
    - _内存布局_：`12 34 56 78` （低地址 -> 高地址）
### 网络通信中的困境
如果两台机器的字节序不一致，就会出现“鸡同鸭讲”的现象 例如：主机 A (小端序) 发送 `0x1234` (发送顺序 `34 12`)，主机 B (大端序) 接收到 `34 12` 后，会将其解析为 `0x3412`**数据的值完全变了！**
### 解决方案：网络字节序
为了解决这个问题，TCP/IP 协议规定了**网络字节序 (Network Byte Order)**： **网络传输中的数据，必须统一采用大端序 (Big-Endian)**
![](images/1.%20基础概念/file-20251117214412335.jpg)
- **发送方规则**：不管本机是什么字节序，发送数据前，必须转换为网络字节序（大端）
- **接收方规则**：从网络接收数据后，必须将网络字节序（大端）转换为本机的主机字节序
- **效果**：网络字节序屏蔽了底层硬件的差异，使得不同架构的计算机（如 x86 PC 和 ARM 手机）能够正常通信
