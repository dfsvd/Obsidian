## UDP 简介
**UDP (User Datagram Protocol，用户数据报协议)** 是传输层中与 TCP 并列的核心协议之一。如果说 TCP 是“打电话”（建立连接、确认收到），那么 UDP 就是“写信”或“寄包裹”。
UDP 是**面向无连接**的协议，它不保证数据的可靠传输，但以此换取了极高的传输效率和实时性。
### 核心特性
- **无连接 (Connectionless)**
    - 通信双方在发送数据前**不需要**像 TCP 那样进行“三次握手”建立连接。
    - 发送端想发就发，资源占用极少，启动速度快。
- **不可靠 (Unreliable)**
    - **无确认**：接收方收到数据后，不会向发送方发送 ACK（确认应答）。发送方发出去就不管了，不知道对方是否收到。
    - **不重传**：如果数据在网络中丢失，UDP 协议层不会自动重传。
    - **无序**：先发送的数据包不一定先到达。
- **面向数据报 (Datagram / Frame Synchronization)**
    - 这是 UDP 与 TCP 的根本区别之一。UDP 采用**帧同步**方式。
    - UDP 保留了报文的边界。发送方发送 100 字节，接收方就必须一次性接收 100 字节。它不会像 TCP 那样将数据看作“水流”（字节流）产生粘包问题。
    - **例如**：发送方调用了 3 次 `sendto`，接收方就必须调用 3 次 `recvfrom`。
### 适用场景
由于 UDP 也就是“寄信”模式——把信丢进邮箱后，无法得知对方是否收到，也无法保证信件不丢失，但省去了繁琐的挂号和回执过程。因此 UDP 适用于对**速度**和**实时性**要求高，但对**少量丢包**不敏感的场景：
1. **实时音视频 / 流媒体**：视频会议、直播、VoIP（网络电话）。稍微丢几帧画面只会导致瞬间花屏，比画面卡顿延迟要好得多。
2. **小尺寸数据查询**：例如 **DNS (域名解析)**。发送一个域名请求，快速回一个 IP，丢包了就重发一次，没必要建立昂贵的 TCP 连接。
3. **广播与组播**：只有 UDP 支持向多个目标同时发送数据（TCP 只能一对一）。
4. **在线游戏**：玩家的位置坐标更新，追求极致的低延迟。
通信流程
UDP 通信不需要建立连接，因此其流程比 TCP 简单，主要分为发送端和接收端两部分。
#### UDP 发送端流程
发送端的主要任务是向指定的目标地址发射数据。
1. **申请套接字 (Socket)**：向内核获取一个通信设备（文件描述符）。
2. **明确通信目标**：设置接收者的 IP 地址和端口信息（明确发给谁）。
3. **发送消息**：调用发送接口将数据发出去。
4. **销毁关闭**：通信结束，释放资源。
#### UDP 接收端流程
接收端需要公开自己的地址，静候数据到来。
1. **申请套接字 (Socket)**：获取通信设备。
2. **明确自己的地址信息**：配置自己的 IP 和端口（对外公布联系方式）。
    - **2.1 设置地址**：填充地址结构体。
    - **2.2 绑定 (Bind)**：将该地址与套接字绑定，确保发往该端口的数据能被当前进程捕获。
3. **坐等消息到达**：阻塞等待数据。
4. **销毁关闭**：释放资源。
## 关键 API 接口
### 地址结构体
在网络编程中，我们不能直接传递字符串形式的 IP（如 "192.168.1.1"），内核需要特定的结构体和整型数据。
#### IPv4 地址结构体 `struct sockaddr_in`
这是专门用于 IPv4 编程的结构体，在调用 API 时通常需要强制转换为通用的 `struct sockaddr`。
```c
struct sockaddr_in {
    sa_family_t    sin_family; 
    /* 通信协议 address family: AF_INET */
    in_port_t      sin_port;   
    /* 端口号 port in network byte order */
    struct in_addr sin_addr;   
    /* IP地址 internet address */
};

/* 其中 IP 地址的结构定义如下 */
struct in_addr {
    uint32_t       s_addr;     
    /* address in network byte order */
};
```
- **`sin_family`**：必须设置为 `AF_INET`。
- **`sin_port`**：存储端口号，必须是**网络字节序**（大端）。
- **`sin_addr`**：存储 IP 地址，也必须是**网络字节序**。
### 字节序转换函数
网络传输统一使用**大端序 (Big-Endian)**，而主机（如 x86 架构）通常是**小端序**。为了保证数据在不同机器间正确解析，必须在发送前和接收后进行转换。
- **函数原型**
    ```c
    #include <arpa/inet.h>
    
    // 主机字节序 -> 网络字节序 (Host to Network)
    uint32_t htonl(uint32_t hostlong); 
    // 用于 IP 地址 (Long, 32位)
    uint16_t htons(uint16_t hostshort);
    // 用于 端口号 (Short, 16位)
    
    // 网络字节序 -> 主机字节序 (Network to Host)
    uint32_t ntohl(uint32_t netlong);  
    // 用于 IP 地址
    uint16_t ntohs(uint16_t netshort); 
    // 用于 端口号
    ```
- **作用** 在**主机字节序**（通常是小端）和**网络字节序**（大端）之间进行数值转换。
- **参数详解**
    - `hostlong` / `hostshort`：主机上的整数。
    - `netlong` / `netshort`：从网络接收到的、或准备发送到网络的整数。
- **返回值** 转换后的整数值。
- **代码示例**
    ```c
    uint16_t host_port = 8080;
    // 发送前：主机序 -> 网络序
    uint16_t net_port = htons(host_port); 
    
    printf("主机序: %#x, 网络序: %#x\n", host_port, net_port);
    ```
### IP 地址转换函数
人类习惯使用点分十进制字符串（如 `"192.168.46.3"`），而网络协议栈需要的是 32 位的大端整型数据。
#### 字符串 转 网络整型
- **函数原型**
    ```c
    #include <sys/socket.h>
    #include <netinet/in.h>
    #include <arpa/inet.h>
    
    // 方法1: 推荐使用，将结果存入结构体
    int inet_aton(const char *cp, struct in_addr *inp);
    
    // 方法2: 较旧，直接返回整型 (失败返回 -1，易与 255.255.255.255 混淆)
    in_addr_t inet_addr(const char *cp);
    
    // 方法3: 仅提取网络号 (较少使用)
    in_addr_t inet_network(const char *cp);
    ```
    
- **作用** 将点分十进制的字符串 IP 转换为网络字节序的 32 位二进制整数。
- **参数详解**
    - `cp`：指向点分十进制字符串 IP 的指针（例如 `"192.168.46.3"`）。
    - `inp`：指向 `struct in_addr` 结构体的指针，转换结果将直接存储在该结构体中。
- **返回值**
    - `inet_aton`：成功返回非 0 值，失败返回 0。
    - `inet_addr`：成功返回转换后的 32 位整数，失败返回 `INADDR_NONE`。
- **代码示例**
    ```c
    struct sockaddr_in addr;
    const char *ip_str = "192.168.1.100";
    
    // 方式一：使用 inet_aton (推荐)
    if (inet_aton(ip_str, &addr.sin_addr) == 0) {
        printf("无效的 IP 地址\n");
    }
    
    // 方式二：使用 inet_addr
    addr.sin_addr.s_addr = inet_addr(ip_str);
    ```
#### 网络整型 转 字符串
- **函数原型**
    ```c
    #include <arpa/inet.h>
    
    char *inet_ntoa(struct in_addr in);
    ```
- **作用** 将网络字节序的 IP 地址结构体转换回点分十进制字符串，常用于打印日志或显示给用户。
- **参数详解**
    - `in`：`struct in_addr` 类型的结构体（注意：这里传递的是**结构体变量**本身，而不是指针）。
- **返回值**
    - 成功：返回指向转换后字符串的指针。
    - **注意**：该函数使用**静态缓冲区**存储结果，多次调用会覆盖旧值，且非线程安全。
- **代码示例**
    ```c
    struct sockaddr_in addr;
    // 假设 addr.sin_addr 已经被赋值
    
    // 将结构体中的整型 IP 转为字符串打印
    printf("IP地址是: %s\n", inet_ntoa(addr.sin_addr));
    ```
### 申请套接字 `socket()`
```
#include <sys/socket.h>

int socket(int domain, int type, int protocol);
```
- **作用**：向内核申请一个通信端点。
- **参数分析**：
    - `domain`：选用通信协议族。
        - `AF_INET`：IPv4 互联网协议。
        - `AF_UNIX` / `AF_LOCAL`：本地进程间通信。
    - `type`：选用通信协议类型。
        - `SOCK_DGRAM`：**\[UDP\]** 支持数据报（无连接、不可靠）。
        - `SOCK_STREAM`：**\[TCP\]** 提供序列化、可靠、双向连接。
    - `protocol`：控制协议，一般设置为 `0`，让系统自动匹配（如 AF_INET + SOCK_DGRAM 自动匹配 UDP）。
- **返回值**：
    - 成功：返回**文件描述符**。
    - 失败：返回 `-1`。
### 绑定地址 `bind()`
```
#include <sys/socket.h>

int bind(int sockfd, const struct sockaddr *addr, socklen_t addrlen);
```
- **作用**：将套接字与特定的 IP 和端口“捆绑”，主要用于接收端明确自己“收哪里发来的信”。
- **参数分析**：
    - `sockfd`：需要绑定的目标套接字。
    - `addr`：指向包含自身 IP 和端口的地址结构体（需强转为 `struct sockaddr*`）。
    - `addrlen`：地址结构体的实际长度 (`sizeof(struct sockaddr_in)`)。
- **返回值**：
    - 成功：返回 `0`。
    - 失败：返回 `-1`。
### 发送 UDP 消息 `sendto()`
```
#include <sys/socket.h>

ssize_t sendto(int sockfd, const void *buf, size_t len, int flags,
               const struct sockaddr *dest_addr, socklen_t addrlen);
```
- **作用**：向指定目标发送数据。
- **参数分析**：
    - `sockfd`：文件描述符。
    - `buf`：需要发送的消息内容缓冲区。
    - `len`：内容的实际长度。
    - `flags`：发送的特殊标记，默认直接设置为 `0`。
    - `dest_addr`：**目标地址**结构体，必须包含对方的 IP 和端口。
    - `addrlen`：目标地址的长度。
- **返回值**：
    - 成功：返回实际发送的字节数。
    - 失败：返回 `-1`。
### 接收 UDP 消息 `recvfrom()`
```
#include <sys/socket.h>

ssize_t recvfrom(int sockfd, void *buf, size_t len, int flags,
                 struct sockaddr *src_addr, socklen_t *addrlen);
```
- **作用**：接收数据，并（可选地）获取发送方的地址信息。
- **参数分析**：
    - `sockfd`：通信套接字。
    - `buf`：用户缓冲区，用于存储收到的消息。
    - `len`：用户缓冲区的大小。
    - `flags`：特殊标记，默认填 `0`。
    - `src_addr`：**输出参数**。用于存储**数据来源地**（发送方）的地址信息。如果不关心谁发的，可填 `NULL`。
    - `addrlen`：**输入输出参数**。传入地址结构体的具体尺寸；函数返回时会被修改为实际写入的地址长度（注意：这是一个“坑”，必须初始化）。
- **返回值**：
    - 成功：返回实际收到的字节数。
    - 失败：返回 `-1`。
## 示例代码
### 接收端 (Receiver)
接收端的核心任务是**绑定 (bind)** 自身的地址，如同公开自己的“邮箱地址”，以便接收来自任何人的投递。

```c
#include <stdio.h>
#include <unistd.h>
#include <string.h>
#include <sys/socket.h>
#include <netinet/in.h>
#include <arpa/inet.h>
#include <netinet/ip.h> 

int main(int argc, char const *argv[])
{
    // 1. 创建UDP套接字
    // AF_INET: 使用IPv4协议
    // SOCK_DGRAM: 使用数据报传输协议 (即UDP)
    int udp_socket = socket(AF_INET, SOCK_DGRAM, 0);
    if (udp_socket < 0)
    {
        perror("udp socket error");
        return -1;
    }
    // 打印成功提示 (实际开发中通常省略)
    perror("udp socket"); 

    // 2. 设置本端(接收端)的IP地址信息
    // 使用 C99 标准的指定初始化器语法
    struct sockaddr_in MyAddr = {
        .sin_family = AF_INET,       // 协议族
        .sin_port = htons(65000),    // 端口号：主机序转网络序 (Host TO Network Short)
        // IP地址：字符串转网络整型
        // 注意：此处绑定了特定IP "192.168.46.1"，这要求本机必须配置有该IP
        // 实际通用代码中常用 INADDR_ANY (0.0.0.0) 来绑定本机所有网卡
        .sin_addr.s_addr = inet_addr("192.168.46.1") 
    };

    // 3. 绑定地址信息 (Bind)
    // 将套接字与指定的IP和端口“捆绑”，确保发往该地址的数据能被此进程捕获
    if(bind(udp_socket, (struct sockaddr *)&MyAddr, sizeof(MyAddr)))
    {
        perror("Bind error"); // 绑定失败通常是因为端口被占用或IP不存在
        return -1;
    }
    perror("Bind success");

    // 4. 等待消息
    char RecvMsgBuf[128] = {0};       // 接收缓冲区
    struct sockaddr_in FromAddr = {0};// 用于存储发送方的地址信息
    socklen_t AddrLen = sizeof(FromAddr); // 必须初始化为结构体的大小

    while (1)
    {
        // 清空缓冲区，防止残留数据
        bzero(RecvMsgBuf, sizeof(RecvMsgBuf));

        // 阻塞接收数据
        // recvfrom 会将发送者的地址信息填入 FromAddr，长度填入 AddrLen
        int retVal = recvfrom(udp_socket, RecvMsgBuf, sizeof(RecvMsgBuf), 0,
                              (struct sockaddr *)&FromAddr, &AddrLen);
        
        if (retVal > 0)
        {
            // 解析并打印发送者的信息和数据内容
            // inet_ntoa: 将网络整型IP转为点分十进制字符串
            // ntohs: 将网络序端口转为主机序
            printf("[%s:%d] 成功收到 %d 字节的数据：%s\n", 
                   inet_ntoa(FromAddr.sin_addr), 
                   ntohs(FromAddr.sin_port),    
                   retVal, 
                   RecvMsgBuf);
        }
    }
    
    // 5. 关闭套接字
    close(udp_socket);

    return 0;
}
```
#### 代码分析
1. **`bind` 的必要性**：作为接收方，必须显式调用 `bind` 来锁定一个端口（如 65000）。如果省略此步，系统会随机分配一个端口，发送方将无法知道该向哪里发送数据。
2. **地址结构初始化**：代码使用了指定 IP `192.168.46.1`。**注意**：如果运行代码的机器没有配置这个 IP，`bind` 会失败（报错 "Cannot assign requested address"）。在通用测试中，建议将 IP 改为 `0.0.0.0` (即 `INADDR_ANY`) 或 `127.0.0.1`。
3. **`recvfrom` 的参数**：`&FromAddr` 和 `&AddrLen` 至关重要，它们构成了 UDP 的“来电显示”功能，允许服务器知道是谁发来的数据，以便后续可能的回复。
### 发送端 (Sender)
发送端通常不需要绑定固定端口（由操作系统自动分配随机端口），只需要明确“发给谁”。
```c
#include <stdio.h>
#include <unistd.h>
#include <string.h>
#include <sys/socket.h>
#include <netinet/in.h>
#include <arpa/inet.h>
#include <netinet/ip.h> 

int main(int argc, char const *argv[])
{
    // 1. 创建UDP套接字
    int udp_socket = socket(AF_INET, SOCK_DGRAM, 0);
    if (udp_socket < 0)
    {
        perror("udp socket error");
        return -1;
    }
    perror("udp socket");

    // 2. 设置接收端(目标)的IP地址信息
    // 这里配置的是数据包要“去哪里”
    struct sockaddr_in ToAddr = {
        .sin_family = AF_INET,
        .sin_port = htons(65000),    // 必须与接收端绑定的端口一致
        .sin_addr.s_addr = inet_addr("192.168.46.1") // 接收端的IP地址
    };

    // 3. 循环发送消息
    char SendMsgBuf[128] = {0};

    while (1)
    {
        // 清空缓冲区
        bzero(SendMsgBuf, sizeof(SendMsgBuf));
        
        // 从标准输入(键盘)读取数据
        // fgets 会读取换行符，实际发送长度包含换行符
        printf("请输入要发送的内容: ");
        fgets(SendMsgBuf, sizeof(SendMsgBuf), stdin);

        // 发送数据
        // sendto 不需要建立连接，直接向 ToAddr 发射数据
        int retVal = sendto(udp_socket, SendMsgBuf, strlen(SendMsgBuf), 0,
                            (struct sockaddr *)&ToAddr, sizeof(ToAddr));
        
        if (retVal > 0)
        {
            printf("成功发送 %d 字节的数据\n", retVal);
        }
        else 
        {
            perror("sendto failed");
        }
    }
    
    // 4. 关闭套接字
    close(udp_socket);

    return 0;
}
```
#### 代码分析
1. **无需 `connect` 或 `bind`**：发送端直接创建 Socket 即可使用。系统会在第一次调用 `sendto` 时，自动为该 Socket 分配一个临时的端口号和本机 IP。
2. **目标地址匹配**：`ToAddr` 结构体中的 IP 和端口必须严格匹配接收端 `bind` 的地址，否则数据包将有去无回（丢失）。
3. **数据边界**：`strlen(SendMsgBuf)` 决定了该 UDP 数据报的大小。接收端收到的包大小将严格等于发送端指定的长度（UDP 保护消息边界）。
### 运行与测试
1. **编译**：
    ```Bash
    gcc receiver.c -o recv 
    gcc sender.c -o send 
    ```
2. **运行顺序**：
    - 先运行接收端：`./recv`（此时程序阻塞，等待数据）。
    - 再运行发送端：`./send`。
3. **注意事项**：
    - 如果两端在同一台机器测试，确保机器拥有代码中指定的 IP（`192.168.46.1`），或者将代码中的 IP 修改为 `127.0.0.1`。
    - 如果在不同机器测试，请确保防火墙（iptables/ufw）允许 UDP 65000 端口的通信。
