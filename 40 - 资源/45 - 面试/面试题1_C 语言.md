### 变量的声明和定义有什么区别？

- **掌握级别**：重点
    
- **核心解析**：
    
    - **定义**：为变量分配地址和存储空间的称为定义。一个变量只能在**一个**地方定义。
        
    - **声明**：不分配地址，仅告知编译器该变量的存在。一个变量可以在**多个**地方声明。
        
    - **识别标志**：加入 `extern` 修饰的通常是变量的声明，说明该变量在文件以外或在文件后面部分定义。
        

### C 语言中，变量的作用域有哪些？

- **掌握级别**：重点
    
- **局部作用域 (Local Scope)**：
    
    - 在函数内部定义的变量具有局部作用域，仅在定义它的函数内部可见。
        
    - 每次函数调用时，会为这些局部变量重新分配内存空间，并在函数返回时释放。
        
    - 默认使用 `auto` 关键字声明（通常省略）。
        
- **全局作用域 (Global Scope)**：
    
    - 在所有函数之外定义的变量具有全局作用域，在整个程序中可见。
        
    - 生命周期贯穿整个程序执行过程，程序开始时分配空间，结束时释放。
        
    - 可使用 `extern` 在其他源文件中声明并访问。
        
- **static 关键字的作用**：
    
    - **修饰局部变量**：使其变为静态存储期（Static Storage Duration），函数执行完后不销毁，保留上一次的值。
        
    - **修饰全局变量**：限制其可见性，使其仅在当前的源文件中可见（File Scope），但不影响生命周期。
        
- **特别注意**：C 语言中**没有块级作用域**（Block Scope），如 `if`、`for` 块中定义的变量仍遵循函数级局部作用域规则。
    

### 局部变量能否和全局变量重名？

- **掌握级别**：必问
    
- **核心规则**：可以重名。
    
- **屏蔽机制**：在函数内部引用该变量时，局部变量会**屏蔽**全局变量，优先使用局部变量。
    
- **同级重名**：在同一个函数内，可以在不同的控制结构块（如两个独立的 `while` 循环体）中定义同名的局部变量，它们仅在其所属的块内生效。
    
### while 与 do...while 的区别？
- **掌握级别**：了解
- **执行逻辑**：
    - **while**：先判断条件是否满足，若满足则执行循环体。如果条件一开始就不满足，循环体一次都不会执行。
        
    - **do...while**：先执行一次循环体，再判断条件是否满足。即使条件不满足，循环体也至少执行一次。
        

### while 与 for 的区别以及应用场景？

- **掌握级别**：了解
    
- **语法用法**：
    
    - `while` 仅包含条件判断。
        
    - `for` 集成了初始化、条件检查和变量更新。
        
- **应用场景**：
    
    - **循环次数已知**：推荐使用 `for` 循环，因为它在处理数组遍历或固定次数计数时更直观。
        
    - **循环次数未知**：推荐使用 `while` 循环，当循环是否继续取决于某个特定的动态条件时更为合适。
        

### 简述 i++ 和 ++i 的区别

- **掌握级别**：了解
    
- **基本运算**：
    
    - `i++`：先参与运算，然后再自增 1。
        
    - `++i`：先自增 1，然后再参与运算。
        
- **底层原理**：
    
    - `i++` 返回的是一个**常量值**。
        
    - `++i` 返回的是一个**引用的指针**（在 C++ 语境下）。
        
### 数组的特点有哪些？

- **掌握级别**：必问
    
- **核心特征**：
    
    1. **长度固定**：在声明时需指定长度，且运行期间不可改变。
        
    2. **同类型数据**：只能存储相同类型的数据（如全是整型、浮点型等）。
        
    3. **连续内存**：数组元素在内存中是连续存储的，因此可以通过下标快速访问。
        
    4. **下标访问**：下标从 0 开始。
        
    5. **缺乏越界检查**：C 语言不对数组下标进行检查，程序员需自行确保不越界访问。
        

### 什么是内存访问越界？

- **掌握级别**：必问
    
- **核心定义**：程序员向系统申请了一块内存，但在使用时超出了申请的范围。
    
- **两种情况**：
    
    1. **读越界**：读取了不属于该程序的随机数据，可能导致程序逻辑错误。
        
    2. **写越界（缓冲区溢出）**：向不属于自己的内存空间写入数据，会导致不可预料的程序错误甚至崩溃。
        

### 什么是内存泄漏？以及如何解决？

- **掌握级别**：必问
    
- **现象定义**：程序在申请内存后，没有释放已申请的内存空间，导致系统可用内存逐渐减少。
    
- **常见情况及对策**：
    
    1. **忘记释放**：调用 `malloc` 后未调用 `free`。**解决**：养成良好的配对习惯，或使用 C++ 智能指针。
        
    2. **重复申请**：在未释放前再次申请，导致原内存指针丢失。**解决**：申请前确保前序内存已处理。
        
    3. **静态变量占用**：静态变量在运行期间不释放。**解决**：尽量避免静态变量持有大块内存，或在退出前手动清理。

### 什么是野指针，有什么危害？

- **掌握级别**：重点
    
- **定义**：野指针（Wild Pointer）是指指向一个未被正确初始化的内存地址，或者是一个已经被释放（如使用 `free` 函数）但仍然被引用的指针。其指向的地址是未知的、不可预测的。
    

- 野指针的成因
	
	- **未初始化**：指针变量在定义后没有被赋予有效的内存地址。
	- **释放后继续使用**：使用 `malloc`/`calloc` 分配内存并用 `free` 释放后，未将指针置为 `NULL`，随后又被错误引用。
	- **指针越界**：指针访问超出了其合法的内存范围。
	- **错误操作**：如错误的指针运算或强制类型转换。
- 野指针的危害
	- **程序崩溃**：尝试访问或修改非法地址的内容会导致程序崩溃（如段错误）。
	- **数据损坏**：野指针可能会意外改写其他变量的值，导致程序逻辑混乱。
	- **安全漏洞**：在复杂系统中，可能导致缓冲区溢出等漏洞，被恶意利用。
	- **难以调试**：由于行为不可预测，崩溃原因往往很难定位。
- 如何避免野指针
	- **初始化指针**：在定义指针时，将其初始化为 `NULL` 或其他有效地址。
	- **检查指针**：在使用前检查指针是否为 `NULL`。
	- **释放后置空**：释放内存后立即将指针重置为 `NULL`。
	- **使用安全实践**：如使用智能指针（在 C++ 中）或结构化封装。

### 数组指针与指针数组的区别
- **掌握级别**：重点
- **核心逻辑**：区分这两个概念的关键在于“限定词”和“主体”。前面的词是限定词，后面的词是主体。
- 指针数组 (Array of Pointers)
	- **本质**：是一个**数组**，数组中存放的每个元素都是**指针**。
	- **语法示例**：`int *arr[10];`
	    - 由于 `[]` 的结合优先级高于 `*`，`arr` 先与 `[]` 结合，说明它是一个数组。
	    - `int *` 说明数组内存放的是指向整型数据的指针。
- 数组指针 (Pointer to an Array)

- **本质**：是一个**指针**，该指针指向的是一个**数组**的起始地址。
- **语法示例**：`int (*parr)[10];`
    - 由于 `()` 的结合优先级最高，`*` 先与 `parr` 结合，说明它是一个指针。
    - 指向的数据类型是一个包含 10 个元素的整型数组。
### 函数指针与指针函数的区别

- **掌握级别**：必问
- **指针函数 (Function returning a pointer)**：
    - **本质**：是一个**函数**，其返回值类型是一个指针。
    - **声明方式**：`类型标识符 *函数名(参数列表);`。
    - **用途**：可以动态分配内存并返回该内存内容的指针，常用于实现动态创建对象或数据的逻辑。
        
- **函数指针 (Function Pointer)**：
    - **本质**：是一个**指针变量**，它指向的是函数的起始地址。
    - **声明方式**：`类型标识符 (*指针名)(参数列表);`。
    - **用途**：可以作为参数传递给其他函数，用于实现回调函数（Callback）功能，或作为数据结构成员实现函数的动态绑定。
### sizeof 与 strlen 的区别

- **掌握级别**：必问
    
- **strlen**：
    - 是 C 标准库中的一个函数，专门用于计算字符串的长度。
    - 它通过查找字符串中的 `\0` 结束符来确定长度，返回的是字符个数（不包括 `\0`）。
- **sizeof**：
    - 是 C/C++ 语言中的一个**运算符**，用于获取数据类型或变量所占用的总字节数。
    - 在编译时确定，对于指针变量返回的是指针本身的大小，而不是指针指向的内容空间大小。
    - **关键区别**：`strlen` 遇到 `\0` 就会结束计数，而 `sizeof` 会将字符串末尾的 `\0` 字节也计算进去。
        
### strcpy 与 memcpy 的区别

- **掌握级别**：重点
    
- **复制内容不同**：`strcpy` 只能复制字符串；`memcpy` 则可以复制任意类型的数据，例如字符数组、整型、结构体、类等。
- **复制方法不同**：`strcpy` 不需要指定长度，它遇到被复制字符串的结束符 `\0` 才停止（容易导致溢出）；`memcpy` 则是根据其第 3 个参数明确指定的字节数进行内存拷贝。
- **用途不同**：通常在复制字符串时用 `strcpy`，在复制其他类型数据时调用 `memcpy`。
    

### const 关键字的作用

- **掌握级别**：必问
    
- **核心作用**：用于指定一个变量为**只读**。一旦初始化后，其值就不能再被修改，增加了程序的健壮性。

- **主要用途**：
    - **常量定义**：定义运行期间固定不变的值，例如 `const int MAX_VALUE = 100;`。
    - **修饰指针**：
        - **指向常量的指针**：`const int *p;` 指针指向的数据是常量，不能通过该指针修改数据。
        - **常量指针**：`int *const q;` 指针本身是常量，即指针指向的地址不能改变，但指向的数据可以修改。
        - **指向常量的常量指针**：`const int *const r;` 地址和数据均不可修改。
    - **函数参数**：确保函数内部不会意外修改传入的参数值，这是一种自我文档化的编程方式。
    - **函数返回值**：修饰返回值以防止返回的内部指针被外部错误修改。
### static 关键字的作用

- **掌握级别**：重点
    
- **修饰局部变量**：使其变为静态存储期。变量的生命周期延长至程序结束，且在函数多次调用之间能够保留上一次的值。
- **修饰全局变量**：限制该变量的作用域，使其仅在当前定义的源文件中可见，防止被其他文件通过 `extern` 访问，避免命名冲突。
- **修饰函数**：与修饰全局变量类似，该函数只能在当前源文件中被调用，不对外暴露。

### define 与 const 的区别

- **掌握级别**：了解
    
- **编译阶段**：`#define` 在预处理阶段进行简单的文本替换；而 `const` 在编译阶段进行确定。
- **安全性**：`#define` 没有类型安全检查，仅是宏替换；`const` 具有明确的类型，编译器会对其进行类型检查。
- **内存占用**：`#define` 定义的宏在代码中每使用一次就会替换一次，可能产生多份备份；`const` 定义的常量通常只占用一份内存空间。
    
### 结构体（struct）与共用体（union）的区别

- **掌握级别**：重点
    
- **内存分配**：
    - **struct**：结构体中每个成员都拥有独立的内存空间，结构体的总大小通常是所有成员大小之和（需考虑内存对齐）。
    - **union**：所有成员共享同一块内存空间，同一时刻只能存储其中一个成员的值。
- **空间占用**：结构体的大小随成员增多而增大；共用体的大小至少要能容纳其最大的成员。

### 什么是内存对齐？为什么要进行内存对齐？

- **掌握级别**：必问
    
- **定义**：内存对齐是指数据在内存中的存放地址必须是其大小的整数倍（例如 `int` 型通常从 4 的倍数地址开始存储）。
    
- **原因**：
    1. **平台移植性**：并非所有硬件平台都能访问任意地址上的任意数据，某些硬件要求特定类型数据必须对齐。
    2. **性能优化**：处理器读取内存通常是按块（如 4 字节或 8 字节）读取的。对齐后，处理器只需一次内存访问即可读取完整数据，否则可能需要多次访问并进行拼凑，降低效率。

### 21. 谈谈对 inline 关键字的理解

- **掌握级别**：重点
    
- **核心作用**：用于建议编译器将函数调用替换为函数体本身的扩展，以减少函数调用时的开销（如参数入栈、跳转等）。
- **特点**：
    - **空间换时间**：由于在每个调用点都展开代码，会增加最终可执行文件的大小。
    - **适用场景**：通常用于函数体非常小且频繁被调用的函数。
    - **编译器决定**：`inline` 只是给编译器的建议，编译器有权根据函数复杂程度决定是否真正执行内联。
