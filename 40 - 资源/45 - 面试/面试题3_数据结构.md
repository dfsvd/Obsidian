### 谈一下什么是数据结构
数据结构是计算机科学技术领域广泛使用的专业术语。在很多书籍以及博客中，对数据结构的解释为数据在计算机的存储形式，容易让人误以为数据结构只是一种数据的物理存储方式。其实不然，数据结构可以理解为：**数据 + 结构**。
数据是描述客观事物的符号，为程序操控，存储在计算机上。结构包括数据的**逻辑结构**和**存储结构**：
- 数据元素间抽象化的相互关系，与数据的存储无关，独立于计算机，但逻辑结构决定元素的输入、存储、发送、处理和信息传递的基本操作功能。
- 逻辑结构有四种基本类型：**集合结构、线性结构、树形结构和图形结构**。
- 表和树是最常用的两种高效数据结构，许多高效的算法能够用这两种数据结构来设计实现。

### 数组与链表的区别

| 对比维度      | 数组                 | 链表                 |
| --------- | ------------------ | ------------------ |
| 元素个数      | **固定**             | 结点个数可按需增减          |
| 内存分配      | 定义时分配，**内存连续**     | 程序执行时动态向系统申请，内存不连续 |
| 元素顺序关系    | 由元素在数组中的**下标位置**确定 | 由结点所包含的**指针**体现    |
| 访问效率      | 随机访问速度快            | 访问元素速度比数组慢         |
| 插入 / 删除效率 | 需移动大量元素，效率低        | 仅修改指针指向，效率高        |
补充示例：
- 插入元素：用数组表示列表时，插入处后所有元素需向后移动以腾出位置；用链表表示时，仅需修改相关结点的指针指向，无需移动元素。
- 删除元素：用数组表示列表时，删除处后所有元素需向前移动以填补空缺；用链表表示时，仅修改结点指针，与结点实际存储位置无关。

### 了解过哪些排序算法

- **冒泡排序**：比较相邻的元素，如果顺序错误就交换位置，重复此过程直到排序完成。
- **插入排序**：将待排序的元素逐个插入到已经排序好的序列中的适当位置。
- **选择排序**：从未排序的序列中选择最小（或最大）的元素，将其放到已排序序列的末尾。
- **快速排序**：选择一个基准元素，将序列分为两部分（一部分比基准元素小，一部分比基准元素大），递归地对两部分进行排序。
- **归并排序**：将序列不断地分割成两个子序列，分别对子序列进行排序，然后合并两个有序的子序列。
- **堆排序**：将序列构建成最大堆或最小堆，然后依次取出堆顶元素，每次取出的元素都是当前堆中的最大（或最小）元素。
- **希尔排序**：将序列按照一定的间隔进行分组，对每组进行插入排序；随着间隔的逐渐缩小，最后进行一次完整的插入排序。
- **计数排序**：统计序列中每个元素出现的次数，然后根据统计结果将元素放回原序列中的正确位置。
- **桶排序**：将序列按照一定的范围划分为多个子序列（桶），对每个子序列进行排序，然后将各个子序列合并。
- **基数排序**：将序列按照个位、十位、百位等位数的大小进行排序，依次排序直到最高位。
### 快速排序

快速排序采用**分治思想**，即在一个无序的序列中选取一个任意的**基准元素 pivot**，利用 pivot 将待排序的序列分成两部分：前面部分元素均小于或等于基准元素，后面部分均大于或等于基准元素。然后采用递归的方法分别对前后两部分重复上述操作，直到将无序序列排列成有序序列。

### 衡量算法性能的指标有哪些
- **时间复杂度**
    衡量算法运行时间的增长率，描述算法所需要执行的基本操作数量随输入规模的增长情况。**时间复杂度越低**，算法执行效率越高。
- **空间复杂度**
    衡量算法所需的内存空间随输入规模的增长情况，描述算法所需要的额外内存空间（通常不包括输入数据本身所占用的空间）。**空间复杂度越低**，算法的内存占用越小。
- **稳定性**
    在一组无序数据中，若两个待排序字段一致的数据，在排序前后相对位置不变，则称排序算法是稳定的，否则是不稳定的。
- **正确性**
    即算法是否能够正确地解决问题。正确性是评价一个算法的基本要求，一个正确的算法应该能够在给定输入下产生正确的输出。
- **可读性**
    算法的可读性指算法的代码是否易于理解和维护。清晰、模块化、注释良好的代码更容易被理解和修改，提高了算法的可读性。
- **可伸缩性**
    算法在处理大规模数据时的性能表现。一个具有良好可伸缩性的算法能够在输入规模增大时，保持较好的性能表现，而不是出现明显的性能下降。

### 链表如何排序
在链表排序过程中，可使用多种算法来拆分和拼接链表，主要包括以下三种：
- **快速排序**
    选择链表中的一个节点作为基准点（通常选第一个节点），遍历链表将小于基准值的节点放入新链表，大于等于基准值的节点放入另一新链表；对两个新链表分别递归执行快速排序，最后将小于基准值的链表连接到基准点后，再连接大于等于基准值的链表。
- **归并排序**
    将链表分成两半（使用快慢指针法找到中间节点），递归地对两个子链表进行归并排序；将两个排序好的子链表进行合并，即比较两个子链表的头节点，将较小的节点连接到新链表中，并将对应子链表的指针向后移动。
- **插入排序**
    创建新链表，初始时只包含原链表的第一个节点；遍历原链表的剩余节点，将每个节点插入到新链表的正确位置，插入时需找到新链表中合适的位置并调整节点的前后指针。

### 栈和队列的区别

| 对比维度    | 栈（Stack）                      | 队列（Queue）                        |
| ------- | ----------------------------- | -------------------------------- |
| 插入和删除位置 | 只能在**栈顶**进行插入和删除              | 分别在**队尾**插入、**队头**删除             |
| 数据使用顺序  | **后进先出（LIFO）**                | **先进先出（FIFO）**                   |
| 访问元素能力  | 只能访问**栈顶元素**                  | 可同时访问**队头和队尾元素**                 |
| 应用场景    | 表达式的转换和求值、函数调用和递归实现、深度优先搜索遍历等 | 计算机系统中各种资源的管理、消息缓冲器的管理、广度优先搜索遍历等 |

### 如何理解环形队列

环形队列是一种线性数据结构，遵循**先进先出**原则，且队尾连接在队首之后形成一个循环，也被称为**环形缓冲队列**。

- 普通队列问题：每出队一次，头指针必须向后移一位，已使用过的空间无法再被使用（头指针无法回移），即使队列元素小于队列大小，也会造成空间浪费。
- 环形队列优势：可以**重复利用已使用过的空间**，解决了普通队列的空间浪费问题。
- 实现特点：可使用数组实现，尾指针到数组大小时，回跳到头位置即可。

### 二叉树如何进行遍历
二叉树遍历分为三种核心遍历方式，均从根节点出发，每个节点需按指定顺序访问：
- **前序遍历**
    访问顺序：**根节点 → 左子树 → 右子树**。
- **中序遍历**
    访问顺序：**左子树 → 根节点 → 右子树**。
- **后序遍历**
    访问顺序：**左子树 → 右子树 → 根节点**。

### 什么是查表法

查表法是一种通过查找预先计算好的表格来获取结果的算法技术，其基本思想是将问题的可能输入值和对应的输出值存储在一个表格中，然后通过查找表格中的数据来获取结果，而不是通过重新计算。
- **核心优势**
    可**大幅提高算法执行效率**，尤其是对于一些重复计算较多的问题，通过预先计算并存储结果，可避免重复计算，从而减少算法的时间复杂度。
    此外，查表法还可以简化算法的实现和理解，提高代码的可读性和可维护性。
- **使用注意事项**
    使用时需要权衡**空间和计算成本**，并根据具体问题的特点来选择是否使用查表法。

### 谈一下你对内核链表的理解

在 Linux 系统中，**内核链表（Kernel Linked Lists）** 是内核空间中用于高效数据组织与管理的核心数据结构，因内核对性能与资源使用的严格要求，其实现相比用户态链表更精简高效。
- **核心用途**：用于管理动态分配的内存块、进程描述符、文件描述符等对象，可方便地完成添加、删除和遍历操作。
- **数据结构**：通常采用**双向链表**实现，每个节点包含指向前一个和后一个节点的指针，支持任意位置的高效插入 / 删除，无需移动其他节点。
- **精简性**：内核对空间性能要求极高，链表实现非常精简，不包含不必要开销，如错误检查或调试信息。
- **并发性**：在多处理或多线程环境中，内核链表需支持并发访问，通常通过自旋锁或读写锁保证数据一致性。
- **API 接口**：Linux 内核提供了`list_add()`、`list_del()`、`list_empty()`等操作函数，简化了链表使用并确保操作正确性。
- **应用场景**：广泛用于内核组件与子系统，如进程描述符管理（进程调度）、TCP/IP 连接管理（网络通信）、设备驱动程序中的 I/O 请求等。

### 内核链表与单 / 双循环链表的区别

| 对比维度     | 内核链表                                                                  | 单 / 双循环链表                                           |
| -------- | --------------------------------------------------------------------- | --------------------------------------------------- |
| **设计目的** | 为内核环境高效组织管理数据，追求**轻量级、高效、灵活**                                         | 通用数据结构，用于应用程序存储与操作数据，追求**通用性**                      |
| **实现方式** | 采用**双循环链表**实现，节点仅包含指针，不包含数据域；通过`list_head`结构体定义节点，位于`linux/list.h`头文件 | 单循环链表仅含后继指针，双循环链表含前驱与后继指针，首尾节点相互指向形成环；节点通常包含数据域与指针域 |
| **应用场景** | 用于内核设备列表、进程列表、文件描述符表等场景，对性能与灵活性要求极高                                   | 应用程序中更常见，用于实现缓存、队列、栈等结构，适用于频繁插入 / 删除与顺序访问场景         |
| **核心特点** | 可灵活嵌入各种数据类型，实现高度复用                                                    | 提供对数据的顺序访问和快速插入 / 删除能力                              |

---

**总结**：Linux 内核链表在设计目的、实现方式与应用场景上与通用单 / 双循环链表存在显著差异，它是为 Linux 内核环境量身打造的轻量级、高效且灵活的数据结构，而单 / 双循环链表则是更通用的上层数据结构。

### 请你讲一下动态链表和静态链表的区别

|对比维度|静态链表（顺序表）|动态链表|
|---|---|---|
|**实现方式**|用**数组**实现，属于顺序存储结构，物理地址上是连续的|基于**指针**实现，动态申请内存（`malloc/free`），物理地址不连续|
|**空间分配**|需预先分配地址空间大小，**初始长度固定**|长度无限制，**动态申请 / 释放**内存|
|**插入 / 删除操作**|需移动元素，仅修改指针，效率低|无需移动元素，仅修改指针指向，效率高|
|**访问特性**|支持**随机访问**，通过下标直接定位|仅支持**顺序访问**，需从头节点遍历|
|**内存利用率**|易出现内存浪费（空间固定）|内存利用率高，按需分配|

### 怎样检测链表中存在环

以下是五种常用的链表环检测方法，核心原理围绕**标记 / 计数**或**快慢指针追及**：
1. **标记法（哈希 / 访问标记）**
    修改链表的数据域，向里面增加一个标记位。遍历链表，每次遍历到未遍历过的节点，将节点的标记位修改为 “已访问”。若出现了标记位是修改过的值的节点，则证明链表存在环。
2. **集合法（数组 / 哈希表）**
    若链表是只读的，不能修改数据域，则建立一个数组 / 哈希表。访问每一个元素，并将元素存入链表中，然后检查下一个节点，拿它的数据和数组中的数据进行遍历比较，若出现在数组中，则存在环。
3. **快慢指针法（龟兔赛跑算法）**
    内存容量有限，不能使用数组。假定环出现在前 N 个节点处，则建立一个指针，指向头结点的下一个结点，随后遍历链表和建立的指针比较。若无相同，则建立的指针指向下个结点，继续遍历链表与其比较。直到出现有限的节点，则证明有环；若新建指针已经达到第 N 个结点，则无环。
    
    _（注：标准逻辑为：定义慢指针（每次走 1 步）和快指针（每次走 2 步），若两指针相遇则存在环；若快指针走到 NULL 则无环。）_
4. **断链法（指针修改）**
    内存容量有限，不能使用数组，并且环可能出现在链表任何一处。则我们先将链表头只有三个指针的情况，随后建立两个指针 P1、P2，P1 指向头结点的下一个节点（第二个节点），P2 指向头结点下一个节点的下一个节点（第三个节点）。然后我们每一次令 P1 向后指一个节点，P2 每次向后指向两个节点，进行循环。若最终 P1、P2 都指向 NULL，则没有环；若最终 P1 和 P2 指向同一个节点，则证明存在环。
    _（注：该方法核心为快慢指针追及，若相遇则存在环。）_
5. **删除节点法（破坏链表结构）**
    遍历链表，遍历过程中将每个节点的`next`指针指向头结点。若遍历过程中发现某个节点的`next`已经指向头结点，则说明存在环；若遍历到`NULL`则无环。

### SQL 的约束
SQL 约束是用于限制表中数据的规则，保证数据的**实体完整性、域完整性、引用完整性**和**用户定义完整性**，主要包括以下几类：
- **主键约束（PRIMARY KEY）**：唯一标识表中的每一行，不允许`NULL`值，一个表只能有一个主键。
- **唯一约束（UNIQUE）**：保证列中的所有值唯一（可以有一个`NULL`值），一个表可以有多个唯一约束。
- **非空约束（NOT NULL）**：强制列不接受`NULL`值，确保字段必须输入数据。
- **默认约束（DEFAULT）**：为列指定默认值，当插入数据时未指定该列值时，自动填充默认值。
- **检查约束（CHECK）**：限制列中的值必须满足指定的逻辑条件（如`age > 0`），保证数据的域完整性。
- **外键约束（FOREIGN KEY）**：用于建立和强制两个表之间的链接，保证引用完整性（如学生表的班级 ID 引用班级表的班级 ID）。

---
### SQL 中的索引
索引是一种特殊的查询结构，用于提高对表中数据的查询速度，同时可以保证数据的唯一性。主要类型包括：

- **主键索引**：由主键约束自动创建，聚集索引，唯一且不允许为空。
- **唯一索引**：确保索引列中的值唯一，允许为空（但只能有一个`NULL`）。
- **普通索引**：仅用于提高查询速度，允许列中有重复值和`NULL`值。
- **复合索引**：在表的多个字段上创建的索引，遵循**最左匹配原则**。
- **聚集索引（聚簇索引）**：决定表中数据的物理存储顺序，表数据本身就是索引（如 InnoDB 的主键索引）。
- **非聚集索引**：数据的逻辑顺序与物理顺序无关，包含索引键和行指针。

### SQL 中 DDL 和 DML
#### DDL（数据定义语言 - Data Definition Language）
用于定义和管理数据库、表、视图、索引等数据库对象的结构。
- **核心操作**：
    - **CREATE**：创建数据库、表、视图等对象（如`CREATE TABLE`）。
    - **ALTER**：修改已存在的数据库对象结构（如修改表字段类型、添加 / 删除列）。
    - **DROP**：删除数据库对象（如删除表、数据库）。
    - **TRUNCATE**：清空表中所有数据，并重置自增计数器（属于 DDL，不可回滚）。
    - **RENAME**：重命名表名。
#### DML（数据操作语言 - Data Manipulation Language）
用于操作表中数据，进行增、删、改、查操作。
- **核心操作**：
    - **SELECT**：从表中查询数据（DML 核心）。
    - **INSERT**：向表中插入新数据。
    - **UPDATE**：修改表中已存在的数据。
    - **DELETE**：删除表中的数据。

### 用伪代码写一个实现链表的模块
以下是基于 C 语言的双向链表核心实现伪代码（包含节点定义、创建、插入、遍历、删除）：
```c
// 1. 定义链表节点结构体
struct Node {
    int data;               // 数据域
    struct Node* next;      // 指针域，指向下一个节点
};

// 2. 创建新节点
struct Node* createNode(int data) {
    struct Node* newNode = (struct Node*)malloc(sizeof(struct Node));
    newNode->data = data;
    newNode->next = NULL;
    return newNode;
}

// 3. 插入节点（头插法）
void insertAtHead(struct Node** head, int data) {
    struct Node* newNode = createNode(data);
    newNode->next = *head; // 新节点指向原头节点
    *head = newNode;       // 头指针指向新节点
}

// 4. 插入节点（尾插法）
void insertAtTail(struct Node** head, int data) {
    struct Node* newNode = createNode(data);
    if (*head == NULL) {   // 若链表为空，新节点作为头节点
        *head = newNode;
        return;
    }
    struct Node* temp = *head;
    while (temp->next != NULL) { // 遍历到尾节点
        temp = temp->next;
    }
    temp->next = newNode;  // 尾节点指向新节点
}

// 5. 遍历链表并打印
void traverseList(struct Node* head) {
    struct Node* current = head;
    while (current != NULL) {
        printf("%d -> ", current->data);
        current = current->next;
    }
    printf("NULL\n");
}

// 6. 删除指定值的节点
void deleteNode(struct Node** head, int key) {
    struct Node* temp = *head;
    struct Node* prev = NULL;

    if (temp != NULL && temp->data == key) { // 待删节点是头节点
        *head = temp->next;
        free(temp);
        return;
    }

    while (temp != NULL && temp->data != key) { // 查找待删节点
        prev = temp;
        temp = temp->next;
    }

    if (temp == NULL) return; // 未找到节点

    prev->next = temp->next;  // 断开节点连接
    free(temp);               // 释放内存
}
```
