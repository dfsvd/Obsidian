### 动态库与静态库的区别

| 对比项   | 静态库                | 动态库                |
| :---- | :----------------- | :----------------- |
| 文件扩展名 | **.a**或 **.lib**   | **.so**或 **.dll**  |
| 编译时行为 | 编译时直接整合到目标程序中      | 编译时不会放到链接的目标程序中    |
| 运行时依赖 | 可独立运行，程序大小较大       | 运行时必须依赖动态库         |
| 本质区别  | **是否被编译进目标（程序）内部** | **是否被编译进目标（程序）内部** |

### 谈谈你对 make 的理解
Make 是 GNU 提供的一种半自动化的工程管理器。所谓的半自动化是指在使用工程管理器之前需要人工编写程序的编译规则，所有的编译规则都保存在**Makefile**文件中，全自动化则得工程管理器会在编译程序前自动生成 Makefile 文件。

---
### 为什么要有工程管理器 Make

因为在实际的开发过程中，仅通过**gcc**命令对程序进行编译时非常低效的，原因主要有两点：

- 程序往往是由多个源文件组成的，源文件的个数越多，那么 gcc 的命令行就会越长。此外，各种编译规则也会加大 gcc 命令行的复杂度，所以在开发调试的过程中，通过输入 gcc 命令行来编译程序是很麻烦的。
- 在程序的整个开发过程中，调试的工作量占到了整体工作量的 70% 以上。在调试程序的过程中，每次调试一般只会修改部分源文件。而在使用 gcc 命令行编译程序时，gcc 会把那些没有被修改的源文件一起编译，这样就会影响变异的总体效率。

因此为了提高编译程序的效率，工程管理器 Make 就应运而生。

### make 与 makefile 的区别

在 Linux 中，make 是一个工程构建工具，而 makefile 是用于描述和指导 make 工具进行构建过程的文件。

- **make 的概念**：make 是一个命令行工具，旨在自动化构建软件的过程。它根据指定的构建规则和依赖关系，判断哪些文件需要重新编译，并执行相应的构建命令进行编译和链接。make 会读取 makefile 文件来获取构建规则和命令。
- **makefile 的概念**：makefile 是一个文本文件，包含了构建软件的规则、依赖关系和构建命令。它告诉 make 工具如何进行构建，定义了目标、依赖关系和构建命令之间的关联。通过编写合适的 makefile 文件，可以实现对项目的自动化构建。

### 什么是 cmake
CMake 是一个跨平台的编译 (Build) 工具，可以用简单的语句来描述所有平台的编译过程。
CMake 能够输出各种 makefile 或者 project 文件，能测试编译器所支持的 C++ 特性，类似 UNIX 下的 automake。
在复杂多工程框架场景下，原作者只需生成一份**CMakeLists.txt**文档，框架使用者可利用该文件和 CMake 完成工程搭建，无需手动梳理复杂依赖关系。

### Git 版本控制工具
Git 是目前最流行的分布式版本控制工具（DVCS），核心逻辑是将每一次改动拍成快照存到本地数据库，可在完全离线的情况下完成提交、回退、分支、合并，最后再与远端仓库交换数据。
**Git 核心概念（3 组 9 词）**
- **区域**：Working Tree（工作区） → Index / Stage（暂存区） → HEAD（本地仓库）
- **对象**：blob（文件内容） + tree（目录快照） + commit（提交对象） + tag（标签）
- **分支**：本质是指向某 commit 的可移动指针；创建 / 切换 / 合并只是修改指针和追加快照，因此执行速度极快。
**典型工作流程（Feature Branch）**
```bash
git switch -c feature/login  # 新建功能分支
# 编码 → git add → git commit  # 局部提交
git switch main && git pull    # 同步主干
git merge feature/login       # 合并（或rebase）
git push origin main          # 发布
```

### 在编译过程中链接的步骤优化
链接阶段的核心优化方向主要包括以下几点：
- **减少冗余代码**：通过**函数级 / 符号级链接（-ffunction-sections/-fdata-sections + --gc-sections）**，让链接器只打包被实际引用的函数和数据，剔除未使用的代码段，减小可执行文件体积。
- **使用动态链接替代静态链接**：将公共库编译为动态库（.so/.dll），多个程序可共享同一份库文件内存，降低整体内存占用，同时便于库文件单独更新。
- **延迟加载 / 懒加载**：对不常用的功能模块采用延迟加载技术，程序启动时仅加载核心依赖，运行中按需加载其他模块，缩短启动时间。
- **链接时优化（LTO）**：开启编译器的**Link Time Optimization**，在链接阶段进行跨编译单元的全局优化（如内联、常量传播、死代码消除），进一步提升程序运行效率。
- **合理使用链接脚本**：通过自定义链接脚本（.ld）精细控制内存布局，将高频访问代码 / 数据放到更高效的内存区域，提升程序执行速度。

### 在 Linux C 中，ls 这个命令是怎么被执行的？
1. **shell 解析命令**：用户在 shell 输入`ls`后，shell 会先解析命令，判断是否为内置命令，`ls`是外部命令，因此会去`$PATH`环境变量指定的目录中查找`ls`可执行文件（通常位于`/bin/ls`或`/usr/bin/ls`）。
2. **创建新进程**：shell 调用`fork()`创建子进程，子进程调用`execve()`系统调用，加载`ls`的二进制代码到内存，替换当前进程的地址空间。
3. **执行程序逻辑**：`ls`程序初始化后，调用`opendir()`、`readdir()`等系统调用遍历目标目录，获取文件元数据（通过`stat()`/`lstat()`），然后按照指定格式输出文件列表。
4. **进程结束回收**：`ls`执行完毕后调用`exit()`退出，父进程 shell 调用`wait()`/`waitpid()`回收子进程资源，回到等待输入状态。

### 解释 Linux 内核调度和内存管理的概念，并描述如何优化系统的调度和内存管理性能？

**内核调度**：内核调度器负责分配 CPU 时间片给各个进程，决定哪个进程在何时运行，目标是最大化 CPU 利用率、保证响应时间和公平性。Linux 常用 CFS（完全公平调度器），按进程权重分配运行时间。

**内存管理**：内核负责管理物理内存和虚拟内存，通过分页 / 分段机制实现地址映射、内存分配、页面交换（swap）和缓存管理。

**调度性能优化**：

- 调整调度器参数：如`sysctl`修改`sched_min_granularity_ns`等，平衡延迟与吞吐量。
- 绑定进程到特定 CPU 核心（`taskset`），减少缓存失效和上下文切换。
- 区分实时进程与普通进程：为关键任务配置`SCHED_FIFO`/`SCHED_RR`调度类，保证实时响应。
- 减少不必要的中断和软中断，降低调度干扰。

**内存管理性能优化**：

- 调整`swappiness`参数：控制内存交换倾向，高负载场景下避免频繁 swap 导致性能下降。
- 优化页缓存：调整`dirty_ratio`等参数，平衡磁盘写入性能和数据安全性。
- 使用大页（HugePages）：减少 TLB 缓存失效，提升内存密集型应用（如数据库）性能。
- 避免内存泄漏：通过工具（如`valgrind`）定位并修复，防止 OOM（内存溢出）。
- 配置内存 cgroup：限制进程组内存使用，防止单一任务耗尽系统资源。

### Linux 中断的实现机制，tasklet 与 workqueue 的区别及底层实现区别？为什么要区分上半部和下半部？

**中断实现机制**：
- 上半部（Top Half）：中断处理函数本身，响应硬件中断，执行快速、原子操作（如清中断标志、保存硬件状态），不可阻塞。
- 下半部（Bottom Half）：处理耗时操作，延迟执行，避免阻塞中断上下文。
**tasklet 与 workqueue 的区别**：

| 特性        | tasklet                                   | workqueue                   |
| :-------- | :---------------------------------------- | :-------------------------- |
| **执行上下文** | 软中断上下文（原子上下文，不可阻塞）                        | 进程上下文（可阻塞，可睡眠）              |
| **调度时机**  | 立即调度，在软中断上下文执行                            | 放入工作队列，由内核线程调度执行            |
| **适用场景**  | 轻量级、快速的延迟处理                               | 耗时较长、可能阻塞的操作                |
| **底层实现**  | 基于软中断（`TASKLET_SOFTIRQ`），由 per-CPU 数据结构管理 | 基于内核工作线程（`kworker`），队列化管理任务 |

**区分上半部和下半部的原因**：
- 中断上下文时间极短且不可阻塞，必须快速响应硬件，避免丢失后续中断。
- 将耗时操作移至下半部，可减少中断屏蔽时间，提升系统响应性和吞吐量。
- 下半部提供了不同延迟级别（软中断、tasklet、workqueue），可根据任务特性灵活选择。

### 一个计划跑 Linux 系统的 ARM 系统把 bootloader 烧录进去后，上电后串口上没有任何输出，硬件和软件各应该去检查什么？
**硬件检查**：
- 电源：确认核心板、外设电源稳定，电压、电流符合规格，无短路、过流。
- 时钟：检查晶振、PLL 配置是否正确，CPU、UART、DRAM 时钟是否正常起振。
- 串口：确认串口线连接正确（TX/RX/GND），电平标准（TTL/RS232）匹配，波特率、数据位、校验位、停止位与串口工具一致。
- 存储：确认 Flash/SD 卡烧录正常，无坏块，bootloader 镜像位置正确。
- 硬件复位：检查复位电路是否正常，无异常复位。
- 内存：确认 DRAM 焊接、配置正确，bootloader 是否完成内存初始化。
**软件检查**：
- bootloader 镜像：确认镜像格式（如 u-boot.bin）、加载地址、入口地址正确，无烧录错误。
- 串口初始化：检查 bootloader 中 UART 驱动配置，确认时钟、引脚复用、波特率初始化代码是否执行。
- 早期打印代码：确认 bootloader 启动阶段是否有调试打印（如`puts`），是否被编译器优化或条件编译关闭。
- 启动流程：确认 bootloader 是否卡在早期阶段（如 CPU 初始化、时钟配置、内存初始化），可通过 LED 状态、JTAG/SWD 调试定位。
- 交叉编译工具链：确认编译 bootloader 的工具链与 ARM 架构匹配，无编译选项错误导致代码异常。

### Linux 内核是什么
1. 内核是提供硬件抽象层、磁盘及文件系统控制、多任务等功能的系统软件，是操作系统的核心。
2. 它负责管理系统的进程、内存、设备驱动程序、文件和网络系统等，决定着系统的性能和稳定性。
3. 内核通过**硬件抽象**的方式封装了底层操作的复杂性，为应用软件和硬件提供了一套简洁、统一的接口，简化程序设计。
---
### Linux 内核的组成作用
- **进程管理**
    内核负责创建和销毁进程，处理进程与外部的输入输出、进程间通信（信号、管道、进程间通信原语），并通过调度器控制进程共享 CPU，实现多进程在单 / 多 CPU 上的抽象。
- **内存管理**
    内核为所有进程在有限物理内存上建立虚拟地址空间，通过内存管理子系统提供`malloc/free`等接口，实现内存分配、页交换、缓存管理等功能，直接影响系统性能。
- **文件管理**
    Linux 基于文件系统概念，将所有资源抽象为文件，支持多种文件系统类型（如 ext3、FAT），通过结构化方式管理磁盘上的数据。
- **驱动管理**
    内核通过设备驱动代码控制外部硬件（硬盘、键盘、磁带驱动器等），几乎所有非核心硬件的操作都依赖对应驱动。
- **网络管理**
    内核负责异步网络报文的收集、识别、分发，在程序和网络接口间传递数据，并控制进程的网络活动，同时实现路由和地址解析等核心网络功能。
### Linux 用户空间和内核空间 (用户态和内核态)
- **用户空间（用户态）**：用户程序的运行空间，为安全隔离，用户程序崩溃不影响内核；仅能执行简单操作，不能直接调用系统资源，必须通过**系统接口（system call）** 才能向内核发出指令。
- **内核空间（内核态）**：Linux 内核的运行空间，可执行任意指令，调用系统的一切资源。
---
### Linux 用户态和内核态切换三种方式
1. **系统调用**：用户进程主动要求切换到内核态的一种方式，用户进程通过系统调用申请使用操作系统提供的服务程序完成工作（如`fork()`）。系统调用机制和中断是操作系统实现的核心，是用户态到内核态的典型实现。
2. **异常**：当前进程运行在用户态，若发生异常事件（如缺页异常），会触发切换。
3. **外设中断**：外设完成用户请求时，向 CPU 发送中断，CPU 暂停当前用户态指令，转去执行中断处理程序；执行完后返回原程序，切换过程由用户态到内核态再到用户态完成。硬盘读写、系统时钟触发等场景的切换最终由中断机制实现。

### 静态链接和动态链接有什么区别？

|对比项|静态链接|动态链接|
|:--|:--|:--|
|**库文件**|静态库（.a/.lib）|动态库（.so/.dll）|
|**链接时机**|编译链接阶段，将库代码完整嵌入可执行文件|运行时加载，仅记录库依赖|
|**可执行文件体积**|**较大**（包含库代码）|**较小**（仅含自身代码）|
|**运行依赖**|无需依赖外部库文件|运行时必须加载对应动态库，依赖库存在|
|**更新维护**|库更新需重新编译程序|库单独更新即可，无需重新编译程序|
|**内存占用**|多程序加载同名库时，内存重复加载|多程序共享同一份动态库，内存占用更低|

### 简单描述嵌入式 Linux 启动步骤

1. **硬件上电与 Bootloader 启动**：CPU 上电后从固化地址执行 Bootloader（如 U-Boot），完成硬件初始化（时钟、内存、串口等）。
2. **内核加载**：Bootloader 从 Flash / 存储设备读取 Linux 内核镜像（zImage/Image）至内存指定地址。
3. **设备树加载**：加载设备树文件（.dtb），向内核传递硬件配置信息。
4. **内核启动与初始化**：内核解压启动，完成内存管理、进程调度、设备驱动初始化，挂载根文件系统。
5. **用户态启动**：执行`/sbin/init`或指定初始化程序，启动系统服务，最终进入登录 / 应用运行状态。

### Linux 系统下.ko 文件是什么文件？.so 文件是什么文件？

- **.ko 文件** ：Linux 内核模块文件，是内核的可加载模块，后缀为 **.ko**（Kernel Object）。可在系统运行时动态加载 / 卸载，用于扩展内核功能（如设备驱动、文件系统），无需重新编译内核。
- **.so 文件**：Linux 动态共享库文件，后缀为 **.so**（Shared Object）。是运行时被程序调用的库文件，多个程序可共享同一份库文件，节省内存、便于库更新。

---

### 简述 Linux 主设备号与次设备号的作用
- **主设备号**：标识设备对应的**设备驱动类型**（如串口、块设备），用于内核匹配对应的设备驱动程序。
- **次设备号**：标识同一类驱动下的**具体设备实例**（如串口 1、串口 2），驱动程序通过次设备号区分具体操作的硬件设备。

### 以 U-BOOT 为例，描述嵌入式 ARM-Linux 启动过程
1. **BL0/BL1 阶段（BootROM）**：CPU 上电后从内部 BootROM 执行，初始化最小硬件（时钟、栈），加载片外 Bootloader（U-Boot SPL）。
2. **U-Boot SPL 阶段**：完成板级低级别硬件初始化（DDR、串口），加载完整 U-Boot 镜像到内存并跳转执行。
3. **U-Boot 主阶段**：
    - 初始化硬件（时钟、内存、存储、网络）；
    - 加载内核镜像（zImage/Image）和设备树（.dtb）至内存指定地址；
    - 准备启动参数，设置内核启动入口。
4. **内核启动**：U-Boot 跳转至内核入口，内核解压、初始化，完成内存、进程、驱动、根文件系统挂载。
5. **用户空间启动**：执行 init 进程，启动系统服务，进入嵌入式 Linux 运行状态。

### 字符设备、块设备

|对比项|字符设备|块设备|
|:--|:--|:--|
|**读写方式**|一个字节一个字节读写，按先后顺序读取|以固定长度块（如 512K）传输，支持随机访问|
|**访问特性**|顺序读取，不可跳转|可从任意位置读取，内部会读取完整块后返回所需内容|

|**文件系统支持**|不可容纳文件系统|可容纳文件系统（如 ext4、FAT）|
|**设备节点**|在`/dev/`下对应设备文件，用户程序通过节点操作硬件|在`/dev/`下对应设备文件，用户程序通过节点操作硬件|

### ARM 中的指令集
- **ARM 指令集**：32 位指令集，执行效率高、功能丰富，适合高性能场景。
- **Thumb 指令集**：ARM 体系结构的变种，16 位指令集，代码密度更高，可节省存储空间，适合资源受限的嵌入式设备。

### 设计出虚拟地址和物理地址的好处
1. **地址空间隔离**：每个进程拥有独立且固定的虚拟地址空间，链接器可直接设定固定内存地址，无需关心实际物理地址，简化程序编译与加载。
2. **内存共享与节省**：相同代码（如库文件）在物理内存中仅存储一份，不同进程通过虚拟地址映射共享，大幅降低内存占用。
3. **利用内存碎片**：进程分配连续虚拟内存时，无需对应连续物理内存，可通过页表映射分散物理页，高效利用碎片化内存。
4. **内存保护**：通过页表权限控制，隔离进程地址空间，避免进程间相互干扰，提升系统稳定性。

### shell 脚本中如何定义数组？

- **基本定义**：
    ```bash
    # 方式1：直接赋值
    arr=("apple" "banana" "cherry")
    # 方式2：逐个赋值
    arr[0]="apple"
    arr[1]="banana"
    # 方式3：索引数组
    declare -a arr=("a" "b" "c")
    # 方式4：关联数组（需bash 4+）
    declare -A dict=([name]="tom" [age]=20)
    ```
    
- **常用操作**：
    ```    bash
    echo ${arr[0]}       # 访问第一个元素
    echo ${arr[@]}        # 访问所有元素
    echo ${#arr[@]}       # 获取数组长度
    arr+=("date")         # 追加元素
    ```

### API 与 SDK 的区别

|对比项|API|SDK|
|:--|:--|:--|
|**全称**|Application Programming Interface（应用程序编程接口）|Software Development Kit（软件开发工具包）|
|**本质**|一组函数 / 接口规范，定义了软件组件间的交互方式|一套完整的开发工具集合，包含 API、文档、示例、库、编译器等|
|**作用**|提供调用服务 / 功能的入口，让程序间实现数据交互|为开发者提供完整的开发环境，简化基于特定平台 / 服务的开发|
|**示例**|微信支付 API、地图 API|Android SDK、iOS SDK、AWS SDK|
|**包含关系**|SDK 中通常包含多个 API，API 是 SDK 的核心组成部分|SDK 是 API 的超集，除 API 外还提供开发所需的辅助工具|
